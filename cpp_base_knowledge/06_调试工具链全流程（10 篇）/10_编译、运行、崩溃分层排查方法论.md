# 编译、运行、崩溃分层排查方法论

## 一、前言

复杂问题最怕"上来就猜"。有效的方法是**分层**：先确定问题发生在哪一层，再在该层用对应工具缩小范围。

一条 C/C++ 程序的生命周期：

```text
预处理 → 编译 → 汇编 → 链接 → 加载 → 启动 → 运行 → 崩溃/退出
```

核心总纲：**症状定层，工具收窄，实验验证。** 不要跨层乱试。

## 二、分层与症状对照

| 层 | 典型症状 | 工具 |
|---|---|---|
| 预处理 | 头文件找不到、宏展开异常、条件编译错 | `gcc -E`、`.i` 文件 |
| 编译 | 语法/类型错误、警告 | 编译器报错、`-Wall -Wextra` |
| 汇编 | 汇编语法错误、非法指令 | `gcc -S`、`as` 报错 |
| 链接 | undefined reference、multiple definition、库顺序 | `nm`、`ldd`、`-Wl,--trace-symbol` |
| 加载 | 找不到 .so、版本不兼容、入口错误 | `ldd`、`readelf -d`、`LD_DEBUG` |
| 启动 | main 前崩溃、构造器异常 | gdb `break _start`、`catch throw` |
| 运行 | 逻辑错误、数据错误、性能问题 | 日志、断点、单元测试、profiler |
| 崩溃 | SIGSEGV/SIGABRT/SIGBUS | core、gdb、ASAN |
| 退出 | 数据未落盘、析构未执行、僵尸 | `strace`、`atexit`、`waitpid` |

## 三、按层排查流程

### 1. 先确定"能不能构建"

- 编译失败：看第一条错误，不要看连锁报错；
- 链接失败：看符号、库、顺序；
- 构建成功但运行失败：进入加载/运行层。

### 2. 确定"有没有启动到 main"

- 在 `main` 下断点；如果没停，问题在加载/构造器；
- `break _start`、`catch throw`、`LD_DEBUG`；
- 全局对象构造器里崩溃是常见原因。

### 3. 确定"运行到哪一步"

- 日志/断点/二分注释；
- 最小复现输入；
- 对比正常与异常环境（配置、版本、数据）。

### 4. 崩溃问题

- 信号 → 故障地址 → 指令 → 调用栈 → 源码；
- core/ASAN/Valgrind；
- 详见《程序崩溃、段错误通用定位链路》。

### 5. 非崩溃的逻辑错误

- 单元测试缩小函数；
- 断言不变量；
- 日志打印关键状态；
- git bisect 找引入点；
- 对比输入/输出。

## 四、缩小范围的通用手段

1. **最小复现**：删掉无关代码/输入，直到最小可复现。
2. **二分**：注释代码、二分版本（git bisect）、二分输入。
3. **对比**：正常环境 vs 异常环境（编译器、库版本、配置、数据）。
4. **替换**：换编译器/优化级别/分配器，看是否复现。
5. **插桩**：日志、断点、计数器、trace。
6. **静态分析**：编译器警告、clang-tidy、Coverity。
7. **动态分析**：ASAN、TSan、Valgrind、perf。

## 五、常见误区

### 1. 只看最后一条报错

编译器/链接器的第一条错误才是根因，后面的多是连锁反应。

### 2. 改代码碰运气

没有假设的修改会引入新问题，也学不到东西。先提出可验证的假设，再做实验。

### 3. 忽略环境差异

"我机器上能跑"通常说明编译器/库/配置/数据不同。记录并对比环境。

### 4. 把链接错误当编译错误

`undefined reference` 不是语法问题，改源码没用，要看符号和链接命令。

### 5. 把运行时错误当链接错误

`symbol lookup error` 是加载期/运行期问题，重链接不解决，要看 `ldd`/`LD_DEBUG`。

### 6. 过早优化

先定位正确性问题，再做性能分析（perf、火焰图），不要凭感觉优化。

## 六、排查记录模板

```text
现象：

已排除：
假设：

```

把过程写下来，能避免重复踩坑，也方便他人接手。

## 七、面试标准简答

### 1. 遇到程序问题，你的排查思路？

先分层：构建、加载、启动、运行、崩溃；根据症状确定层，用对应工具（编译错误、nm/ldd、gdb/core、ASAN、日志）缩小范围；提出假设并做最小实验验证，最后回归。

### 2. 为什么编译错误只看第一条？

编译器是流式解析，一处语法错误会导致后续大量伪报错。修复第一条后重新编译，往往其余错误自动消失。

### 3. 如何区分编译期、链接期、运行期问题？

编译期是语法/类型错误，`.o` 还没生成；链接期是符号解析失败（undefined/multiple definition）；运行期是加载库、符号版本、内存访问、逻辑问题。报错信息和工具链不同。

### 4. 如何高效定位偶现问题？

记录环境与输入，增加日志/断言，用最小复现和二分（版本/输入/代码）缩小范围，必要时用 TSan/ASAN 或压力测试放大问题。

## 八、极简口诀

**先分层再动手，症状定工具；**

**编译看首错，链接看符号；**

**加载看 ldd，崩溃看 core；**

**最小复现加二分，假设实验再修复。**
