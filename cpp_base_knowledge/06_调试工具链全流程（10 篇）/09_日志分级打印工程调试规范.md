# 日志分级打印工程调试规范

## 一、前言

日志是线上排障的主要证据。好的日志能回答：**什么时候、哪个进程/线程、什么请求、发生了什么、上下文是什么**。坏的日志只有一句 "error"。

核心总纲：**日志分级、结构化、带上下文、可控制、可轮转。** 日志不是越多越好，而是关键路径必须有关键信息。

## 二、日志级别

| 级别 | 用途 | 生产默认 |
|---|---|---|
| FATAL | 进程无法继续 | 必须 |
| ERROR | 请求/任务失败，需要处理 | 必须 |
| WARN | 可恢复异常、降级、重试 | 必须 |
| INFO | 关键业务事件、启动/关闭 | 必须 |
| DEBUG | 调试细节、内部状态 | 按需开启 |
| TRACE | 极细粒度，高频路径 | 默认关闭 |

原则：

- ERROR 只记录"需要人处理"的错误，不要滥用；
- WARN 记录"发生了但不致命"的异常；
- INFO 记录状态变化和关键结果；
- DEBUG/TRACE 用于定位，生产默认关闭，可按模块/请求动态开启。

## 三、日志内容

### 1. 必备字段

- 时间戳（带时区，毫秒/微秒）；
- 级别；
- 进程名/PID/线程 ID；
- 模块/文件/行号；
- 消息；
- 上下文（请求 ID、用户 ID、连接 ID、关键参数）。

### 2. 结构化日志

```json
{"ts":"2026-11-11T10:00:00.123+08:00","level":"ERROR","pid":1234,
 "tid":5678,"trace_id":"abc123","module":"order",
 "msg":"payment failed","order_id":10086,"code":5003}
```

机器可解析，便于检索和聚合；比纯文本更推荐。

### 3. 关联 ID

一次请求跨越多个服务/线程时，用 `trace_id`/`request_id` 串联。入口生成，透传到下游。

## 四、性能与安全

### 1. 性能

- 热路径避免字符串拼接和格式化，先判断级别再打印；
- 异步日志/批量写入，避免阻塞业务线程；
- 高频日志做采样/限流；
- 避免在锁内做 IO；
- 大对象不要整个打印。

```cpp
if (logger.level() <= Level::DEBUG) {
    logger.debug("state: {}", dump_state());
}
```

### 2. 安全

- 不记录密码、token、密钥、身份证、银行卡；
- 敏感字段脱敏；
- 日志文件权限控制；
- 防日志注入（换行、控制字符转义）。

### 3. 可靠性

- 关键日志写后 `flush`，崩溃时不丢；
- 日志轮转（按大小/日期），保留期和磁盘配额；
- 磁盘满时的降级策略；
- 多线程/多进程写同一文件要加锁或按进程拆分。

## 五、线程与信号安全

- 日志库本身要线程安全；
- 信号处理函数中**只能调用 async-signal-safe 函数**，`printf`、`malloc`、大部分日志库都不安全；
- 信号处理里设置标志位，主循环再打印；
- fork 后子进程的日志缓冲要处理，避免重复输出。

## 六、常见错误

### 1. 只打印 "error"

没有上下文，无法定位。至少记录操作、ID、错误码、关键参数。

### 2. 日志级别滥用

所有信息都是 ERROR，导致告警疲劳；或者关键错误用 DEBUG，生产看不到。

### 3. 在循环里打印海量日志

性能下降、磁盘爆满。加采样/限流，或降级到 TRACE。

### 4. 打印敏感信息

密码/token 泄漏到日志，是常见安全事故。

### 5. 日志与异常重复

捕获异常时打印一次，上层再打印一次，同一错误刷屏。约定只在处理层记录。

### 6. 日志没 flush 就崩溃

关键路径日志丢失。用同步/立即 flush 的日志器，或崩溃前 flush。

## 七、工程规范建议

1. 统一日志库和格式，禁止裸 `printf` 上线。
2. 级别语义写进团队规范。
3. 每个请求入口生成 trace_id，贯穿全链路。
4. 关键状态变化、错误、重试、降级必须有日志。
5. 敏感字段统一脱敏函数。
6. 日志轮转和保留策略纳入部署配置。
7. 线上支持动态调整级别（按模块/请求）。
8. 对日志做监控：错误率、关键字告警。

## 八、面试标准简答

### 1. 日志级别怎么划分？

FATAL/ERROR/WARN/INFO/DEBUG/TRACE。FATAL 进程无法继续，ERROR 需要处理，WARN 可恢复异常，INFO 关键事件，DEBUG/TRACE 调试细节。生产默认 INFO 及以上，按需动态开启低级别。

### 2. 为什么推荐结构化日志？

字段固定、机器可解析，便于检索、聚合、告警和链路追踪；纯文本依赖正则，维护成本高。

### 3. 日志对性能有什么影响？

格式化、字符串拼接、IO 和锁都可能拖慢业务。应先判断级别、异步写入、采样限流、避免锁内 IO，关键日志才同步 flush。

### 4. 信号处理函数里能打日志吗？

不能随意打。信号处理只能调用 async-signal-safe 函数，`printf`/`malloc` 等可能死锁。应设置标志位，由主循环打印，或用 `write` 写预格式化缓冲区。

## 九、极简口诀

**级别分明不滥用，ERROR 要人管；**

**结构化带 trace_id，关键上下文齐全；**

**热路径先判级，敏感字段脱敏；**

**轮转保留配好，信号里别 printf。**
