# data/bss 段初始化与零填充原理

## 一、前言

全局变量和静态变量放哪里？为什么有的占文件空间、有的不占？为什么未初始化变量是 0，而未初始化的局部变量是随机值？

核心总纲：**有非零初值 → `.data`（占文件）；零初值或未初始化 → `.bss`（不占文件，加载时补零）。** 局部变量在栈上，不受此规则保护。

## 二、.data 段

### 1. 存放内容

- 有非零初值的全局变量；
- 有非零初值的静态变量（包括函数内 static）；
- 有非零初值的静态成员变量。

```c
int g_count = 42;            // .data
static int s_mode = 1;       // .data
const char* msg = "hello";   // 指针本身在 .data，字符串在 .rodata
```

### 2. 文件与内存

`.data` 的初值必须保存在 ELF 文件中：

- `p_filesz` 覆盖初值；
- 加载器把文件内容复制到内存；
- 每个进程一份私有映射（`MAP_PRIVATE`），写入触发 COW；
- 修改只影响本进程。

### 3. 大小

```bash
size app
# text    data     bss     dec     hex filename
# 1234    8       16      ...
```

`data` 列包含 `.data` 和 `.rodata`（GNU size 的口径），具体分布用 `readelf -S` 看。

## 三、.bss 段

### 1. 存放内容

- 未初始化的全局/静态变量；
- 显式初始化为 0 的全局/静态变量；
- C 的 tentative definition（传统上进入 COMMON，GCC 10 起 `-fno-common` 后进入 .bss）。

```c
int g_zero;              // .bss
int g_explicit_zero = 0; // .bss（编译器会优化到 .bss）
static int s_zero;       // .bss
```

### 2. 为什么不占文件空间

`.bss` 全是 0，没必要在文件里存一堆 0：

- section 类型是 `SHT_NOBITS`；
- `sh_offset` 存在但文件中没有实际内容；
- 在 `PT_LOAD` 中，`p_memsz > p_filesz`，差值就是 `.bss`；
- 加载器映射匿名零页，或把对应的页清零。

```bash
readelf -S app | grep -A1 '\.bss'
# [Nr] Name  Type      Address          Off    Size
#      .bss  NOBITS    0000000000004010 003010 000008
```

### 3. 零页与 COW

内核通常把所有 `.bss` 映射到同一个全局零页（只读），第一次写入时触发缺页，才分配真实物理页。所以：

- 未触碰的 `.bss` 不占物理内存；
- 多个进程的零页可以共享；
- 大 `.bss` 会增加虚拟大小和启动映射，但不一定立即占物理内存。

## 四、.rodata 与常量

```c
const int k = 10;              // C++：通常 .rodata；C 中 const 全局有外部链接
const char* s = "literal";     // 字符串字面量在 .rodata
```

- `.rodata` 只读，写入触发 `SIGSEGV`；
- 字符串字面量不能修改：

```c
char* p = "hello";
p[0] = 'H';      // 崩溃，p 指向 .rodata
char q[] = "hello";  // q 是栈上数组，可修改
```

C++ 的虚表、RTTI、部分常量指针会进入 `.data.rel.ro`（重定位后只读），启动时由动态链接器填充地址，之后由 RELRO 保护为只读。

## 五、static 局部变量

```c
void foo(void) {
    static int call_count = 0;   // 在 .data（有初值）或 .bss（无初值）
    call_count++;
}
```

- 生命周期是整个程序，不是函数调用；
- 存储位置不是栈，而是 `.data`/`.bss`；
- 第一次进入函数前已完成初始化（C 的静态初始化是编译期常量；C++ 的动态初始化有线程安全保护）；
- C++11 起，函数内 static 的动态初始化是线程安全的（编译器生成 guard 变量）。

## 六、C++ 全局对象的初始化

### 1. 初始化阶段

1. **零初始化**：程序加载时，`.bss` 清零；
2. **静态初始化**：常量表达式初始化，编译期完成，进入 `.data`；
3. **动态初始化**：需要运行时代码的初始化（构造函数），由 `.init_array` 中的函数在 `main` 前执行。

```cpp
int a = 42;                    // 静态初始化，.data
std::string s = "hello";       // 动态初始化，构造函数在 main 前执行
```

### 2. 初始化顺序问题

不同编译单元的动态初始化顺序**未定义**。一个全局对象的构造函数如果访问另一个编译单元的全局对象，可能访问到未初始化状态（静态初始化顺序灾难）。

常见规避：

- 用函数内 static（Meyers Singleton）；
- 显式初始化函数；
- 避免跨编译单元的全局对象依赖。

### 3. 析构

C++ 全局对象析构通过 `__cxa_atexit` 注册，在 `exit` 时逆序执行；`_exit` / 信号终止不会执行。

## 七、COMMON 与 -fno-common

C 语言中，文件作用域的 `int x;` 是 tentative definition：

- 传统 GCC 把它放进 `COMMON` 段，多个编译单元的同名 COMMON 由链接器合并；
- GCC 10 起默认 `-fno-common`，直接放入 `.bss` 并成为强定义；
- 老代码在头文件写 `int x;`、多个源文件包含，升级编译器后会报 `multiple definition`。

```bash
gcc -fcommon ...        # 临时恢复旧行为（不推荐长期使用）
nm app | grep ' C '     # 查看 COMMON 符号
```

正确做法：头文件写 `extern`，一个 `.c` 定义。

## 九、常见问题

### 1. 全局变量没初始化却是 0

因为它在 `.bss`，加载时被清零。这是 C/C++ 标准保证的（静态存储期对象零初始化）。

### 2. 局部变量没初始化为什么是随机值

局部变量在栈上，栈内存来自之前的函数调用，不保证清零。未定义行为，必须显式初始化。

### 3. 大数组放全局还是局部

全局大数组进 `.bss`（不占文件），但会占虚拟内存，首次写入才分配物理页；局部大数组直接压栈，容易栈溢出。大缓冲区优先堆分配或全局 `.bss`。

### 4. .bss 太大有什么影响

- 可执行文件不变大（不占文件）；
- 进程启动映射时间增加；
- 虚拟内存和可能的物理内存增加；
- 某些嵌入式加载器需要启动代码手动清零 `.bss`，漏掉会导致全局变量是垃圾值。

### 5. 为什么 static 变量能跨调用保持值

它不在栈上，而在 `.data`/`.bss`，生命周期等于程序运行期，函数调用不会销毁。

## 十、面试标准简答

### 1. .data 和 .bss 的区别？

`.data` 存放有非零初值的全局/静态变量，初值占文件空间，加载时从文件复制；`.bss` 存放零初始化/未初始化变量，不占文件空间，加载时补零。

### 2. 为什么 .bss 不占文件空间？

内容全是 0，没必要存储。ELF 用 `SHT_NOBITS` 表示，`p_filesz` 不包含它，`p_memsz` 包含；加载器直接映射零页或清零。

### 3. 全局变量和局部变量的初始化规则？

全局/静态变量属于静态存储期，未显式初始化会被零初始化（放 `.bss`）；局部自动变量在栈上，未初始化时值不确定，使用是未定义行为。

### 4. C++ 全局对象什么时候构造？

先零初始化，再静态初始化（常量表达式），最后在 `main` 前由 `.init_array` 执行动态初始化（构造函数）。不同编译单元的动态初始化顺序未定义。

## 十一、极简口诀

**有初值进 data，零初值进 bss；**

**bss 是 NOBITS，filesz 小 memsz 大；**

**全局零初始化，局部栈上靠自觉；**

**static 局部不在栈，C++ 全局构造在 main 前。**
