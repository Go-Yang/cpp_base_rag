# 程序退出资源回收底层机制

## 一、前言

程序退出分两种：

- **正常退出**：`return`、`exit`、`_exit`；
- **异常退出**：信号终止、`abort`。

关键区别在于：**用户态清理（atexit、析构、stdio 刷新）是否执行**，以及**内核回收了哪些资源**。

核心总纲：**exit 走清理流程，_exit 直接进内核；无论怎么退，内核都会回收地址空间、文件描述符等资源，但不回收持久化资源。**

## 二、正常退出路径

### 1. main 返回

```c
int main(void) {
    return 0;
}
```

编译器/启动代码把返回值传给 `exit(status)`：

1. 执行 `atexit` / `on_exit` 注册的函数，**逆序**；
2. 执行 C++ 全局对象析构（通过 `__cxa_atexit` 注册）；
3. 刷新并关闭所有 stdio 流；
4. 调用 `_exit(status)` 系统调用。

### 2. exit()

```c
void exit(int status);
```

行为同上：先做用户态清理，再进内核。`status & 0xFF` 成为进程退出码，shell 通过 `$?` 获取。

### 3. _exit() / _Exit()

```c
void _exit(int status);
void _Exit(int status);
```

直接调用 `exit_group` 系统调用：

- 不执行 atexit 回调；
- 不执行 C++ 析构；
- 不刷新 stdio 缓冲区；
- 不关闭用户态资源（内核会关闭 fd，但用户态缓冲丢失）。

典型用途：`fork` 后子进程立即退出、信号处理函数中避免重入、确定不需要清理的场景。

### 4. return、exit、_exit 对比

| 方式 | atexit | C++ 析构 | stdio 刷新 | 内核回收 |
|---|---|---|---|---|
| `return` from main | 是 | 是 | 是 | 是 |
| `exit()` | 是 | 是 | 是 | 是 |
| `_exit()` / `_Exit()` | 否 | 否 | 否 | 是 |
| `abort()` | 否 | 否 | 否 | 是 |
| 信号默认终止 | 否 | 否 | 否 | 是 |

## 三、异常退出路径

### 1. abort()

```c
void abort(void);
```

- 先解除 SIGABRT 的阻塞，然后 `raise(SIGABRT)`；
- 默认动作是终止进程并可能产生 core；
- 不执行 atexit、析构、stdio 刷新；
- 常用于断言失败、不可恢复错误。

### 2. 信号终止

- `SIGTERM`：默认终止，不清理；
- `SIGINT`：Ctrl+C，默认终止；
- `SIGKILL`：不可捕获、不可忽略，直接杀死；
- `SIGSEGV` / `SIGABRT`：可能产生 core。

信号处理函数可以做有限清理，但不能依赖它完成所有资源释放（尤其 SIGKILL）。最佳实践是：关键资源用 RAII/`atexit` 兜底，持久化资源显式释放。

## 四、atexit 与析构顺序

### 1. atexit 注册

```c
#include <stdlib.h>

void cleanup(void) {
    // 退出时执行
}

int main(void) {
    atexit(cleanup);
    return 0;
}
```

- 可以注册多个，**后注册先执行**（LIFO）；
- 最多注册数量由实现限制（POSIX 要求至少 32 个）；
- `exit` 过程中再次调用 `exit` 行为未定义。

### 2. C++ 全局对象析构

- 编译器为每个全局对象注册 `__cxa_atexit`；
- 析构顺序与构造顺序相反；
- 不同编译单元的构造顺序未定义，析构顺序也就不可依赖；
- `_exit` / 信号终止不会执行析构。

### 3. 共享库卸载

`dlclose` 引用归零时执行库的析构器；但如果库被 `RTLD_NODELETE` 或静态 TLS 保留，析构可能不执行。

## 五、内核回收了什么

进程终止时，内核会：

1. **销毁地址空间**：释放所有 VMA、页表，回收匿名页；
2. **关闭文件描述符**：引用计数减一，最后一个引用关闭时释放文件对象；
3. **解除内存映射**：文件映射的脏页会回写（取决于映射类型）；
4. **终止其他线程**：整个线程组被销毁；
5. **清理信号、定时器、锁**：进程私有的内核对象；
6. **唤醒父进程**：发送 `SIGCHLD`，父进程 `wait` 回收僵尸；
7. **记录退出状态**：退出码/终止信号保存在 task 结构，直到被 wait。

### 内核不回收的东西

- **POSIX 命名共享内存**：`shm_open` 创建的对象会一直存在，直到 `shm_unlink`；
- **POSIX 命名信号量**：`sem_open` 创建的对象需要 `sem_unlink`；
- **System V IPC**：共享内存、信号量、消息队列不会因进程退出自动删除（除非 `IPC_RMID` 或 `SEM_UNDO` 调整）；
- **临时文件**：需要 unlink 或由清理机制处理；
- **子进程**：变成孤儿，被 init/systemd 收养；
- **网络端口**：TCP 连接进入 TIME_WAIT，端口短期内不可复用；
- **文件锁**：`flock`/`fcntl` 锁通常在 fd 关闭时释放，但语义依赖实现。

## 六、僵尸进程与孤儿进程

- **僵尸**：子进程已退出，父进程尚未 `wait`，保留 task 结构；
- **孤儿**：父进程先退出，子进程被 init/systemd 收养（PID 1）；
- 大量僵尸会耗尽 PID 表，需要父进程正确 `waitpid` 或设置 `SIGCHLD` 处理；
- 容器里 PID 1 不回收僵尸会导致容器内僵尸堆积。

## 七、stdio 缓冲与数据丢失

```c
printf("important data");   // 写入 stdio 缓冲区
_exit(0);                   // 缓冲区未刷新，数据丢失
```

- `exit` 会刷新缓冲区；
- `_exit` / `abort` / 信号终止不会；
- `fork` 后父子进程各自有一份缓冲区副本，可能导致重复输出。

需要确保落盘时显式 `fflush` 或 `fsync`。

## 八、常见问题

### 1. 用 _exit 后日志丢了

stdio 缓冲区未刷新。改用 `exit`，或先 `fflush(NULL)`。

### 2. kill -9 后析构没执行

SIGKILL 不可捕获，进程没有机会做用户态清理。关键资源不能只依赖析构；要有持久化/恢复机制。

### 3. 僵尸进程堆积

父进程没有 `wait`。检查父进程是否忽略 `SIGCHLD`、是否在循环里 `waitpid(-1, ..., WNOHANG)`。

### 4. 共享内存泄漏

POSIX 共享内存不会自动删除。确保 `shm_unlink`；System V 用 `ipcrm`。

### 5. 端口无法立即复用

TCP 主动关闭方进入 TIME_WAIT，持续 2MSL。可用 `SO_REUSEADDR`，但要理解副作用。

### 6. 退出码不对

`main` 返回、`exit(status)` 的 status 只有低 8 位有效；shell 的 `$?` 最大 255。被信号终止时，shell 显示 `128 + 信号值`。

## 九、排查命令

| 目的 | 命令 |
|---|---|
| 查看退出码 | `./app; echo $?` |
| 跟踪退出系统调用 | `strace -e trace=exit_group ./app` |
| 查看僵尸 | `ps -el | grep Z` |
| 查看共享内存 | `ipcs -m` / `ls /dev/shm` |
| 查看信号量 | `ipcs -s` |
| 查看打开的文件 | `lsof -p <pid>` |
| 查看 core | `file core` / `gdb ./app core` |
| 检查 atexit 执行 | 在回调里打日志/断点 |

## 十、工程建议

1. 关键数据写入后显式 `fflush` + `fsync`，不要依赖退出时刷新。
2. 资源释放优先 RAII；C 代码用统一的 cleanup 函数 + `atexit` 兜底。
3. 信号处理函数只做 async-signal-safe 操作，复杂清理放到主循环。
4. 子进程必须被 `wait`，避免僵尸。
5. POSIX 共享内存/信号量使用后 `shm_unlink`/`sem_unlink`。
6. 不要依赖析构完成关键持久化；进程可能被 SIGKILL。
7. 容器中确保 PID 1 正确回收子进程（用 tini 或应用自己 wait）。

## 十一、面试标准简答

### 1. exit 和 _exit 的区别？

`exit` 是 C 库函数，先执行 atexit 回调、C++ 析构、刷新 stdio，再调用 `_exit`；`_exit` 是系统调用封装，直接终止进程，不做任何用户态清理。

### 2. 进程退出后内核回收了哪些资源？

地址空间、页表、匿名内存、文件描述符、线程、信号/定时器等内核对象都会回收；但命名共享内存、命名信号量、System V IPC、临时文件、子进程等不会自动清理。

### 3. 什么是僵尸进程？

子进程已退出但父进程没有 `wait`，内核保留其退出状态和 task 结构。父进程 `waitpid` 后僵尸才消失；父进程先退出则孤儿被 init 收养。

### 4. atexit 的执行顺序？

后注册的先执行（LIFO）。C++ 全局对象析构通过 `__cxa_atexit` 注册，顺序与构造相反；`_exit`/信号终止不会执行。

## 十二、极简口诀

**return/exit 走清理，_exit 直接进内核；**

**atexit 后进先出，析构刷缓冲；**

**内核收地址和 fd，命名 IPC 不会收；**

**kill -9 无清理，关键数据先落盘。**
