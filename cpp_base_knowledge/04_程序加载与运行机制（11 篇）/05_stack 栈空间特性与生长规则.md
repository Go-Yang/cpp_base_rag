# stack 栈空间特性与生长规则

## 一、前言

栈是函数调用的"工作台"：保存返回地址、参数、局部变量、寄存器现场。它由编译器自动管理，分配和释放只是移动栈指针，所以极快。

核心总纲：**每个线程一份栈，x86-64 向低地址增长，默认上限 8MB，越界触发 SIGSEGV。** 栈上变量随函数返回失效，返回局部变量地址是经典错误。

## 二、栈的硬件与 ABI 基础

### 1. 寄存器

- `rsp`：栈指针，指向当前栈顶（低地址端）；
- `rbp`：帧指针，指向当前栈帧底部（可选，`-fomit-frame-pointer` 可省）；
- `rip`：指令指针，`call` 会把返回地址压栈。

### 2. 生长方向

x86-64 的栈**向低地址增长**：

```text
高地址
+------------------+
| 调用者的栈帧      |
+------------------+
| 返回地址          |  <- call 压入
+------------------+
| 保存的 rbp        |  <- push rbp
+------------------+
| 局部变量          |
| ...              |  <- rsp 下移
+------------------+
低地址
```

`push` 先减 `rsp` 再写入；`pop` 先读出再增 `rsp`。

### 3. 调用约定（System V AMD64）

- 前 6 个整型/指针参数放 `rdi, rsi, rdx, rcx, r8, r9`，浮点参数放 XMM 寄存器；
- 多余参数从右到左压栈；
- 返回值放 `rax`（浮点 `xmm0`）；
- 调用前 `rsp` 需 16 字节对齐（`call` 压入返回地址后，进入函数时 `rsp % 16 == 8`）。

### 4. 栈帧内容

典型栈帧：

1. 函数参数（超出寄存器的部分）；
2. 返回地址；
3. 保存的 `rbp`；
4. 局部变量；
5. 临时空间（对齐、溢出参数区）。

### 5. 红区（Red Zone）

System V AMD64 规定 `rsp` 以下 128 字节为红区，叶子函数可以临时使用而不调整 `rsp`。信号处理和函数调用可能覆盖它，所以不能跨调用依赖。

## 三、栈空间的管理

### 1. 主线程栈

- 位于用户空间顶端附近（`0x7fff...`）；
- 初始大小由 `RLIMIT_STACK` 决定，常见 8MB：

```bash
ulimit -s          # KB
ulimit -s 16384    # 临时改为 16MB
```

- 栈底（低地址端）有一页**保护页**（`PROT_NONE`），越界访问触发 `SIGSEGV`；
- 内核允许栈 VMA 在缺页时向下扩展，但不能越过保护页和 rlimit。

### 2. 线程栈

- 每个线程有独立栈，位于 mmap 区；
- glibc 默认线程栈大小 8MB（受 `ulimit` 影响），可用 `pthread_attr_setstacksize` 调整；
- 线程栈也有保护页；
- 主线程栈和线程栈不是同一块内存。

### 3. 栈的物理分配

栈也是按需分页：先建立 VMA，访问到新页才分配物理页。所以"栈用了多少"看实际触碰的页，不是 `rsp` 的跨度。

## 四、进程启动时的栈

程序刚开始执行时，内核已经把启动信息放在栈顶：

```text
高地址
+------------------+
| 参数字符串、环境变量字符串 |
+------------------+
| AT_NULL (0,0)    |
| auxv 键值对       |
| NULL             |
| envp[] 指针      |
| NULL             |
| argv[] 指针      |
| argc             |  <- rsp 指向这里
+------------------+
低地址
```

`_start` 从这里取出 `argc`、`argv`、`envp`，再交给 `__libc_start_main`。环境变量、辅助向量（auxv）都在这块区域。

## 五、栈溢出与保护

### 1. 栈溢出

常见原因：

- 巨大的局部数组：`char buf[16 * 1024 * 1024];`
- 深递归；
- `alloca` / VLA 过大；
- 无限递归没有终止条件。

现象：访问保护页 → `SIGSEGV`；或覆盖相邻数据导致更隐蔽的错误。

### 2. 缓冲区溢出

向栈上数组写入超过其大小的数据，会覆盖：

- 相邻局部变量；
- 保存的 `rbp`；
- 返回地址。

这是经典漏洞。防护手段：

- 编译器栈保护：`-fstack-protector-strong`（默认常见）；
- 栈不可执行：`PT_GNU_STACK` 标记 `RW`，没有 `X`；
- ASLR、PIE；
- 安全函数（`strncpy_s`、`snprintf`）；
- 静态分析 + ASAN。

### 3. 栈保护 canary

编译器在返回地址前放一个随机值（canary），函数返回前检查：

```text
*** stack smashing detected ***: terminated
```

说明栈上缓冲区溢出覆盖了 canary。用 gdb 看 `__stack_chk_fail` 的调用栈。

### 4. Stack Clash

攻击者通过大幅移动 `rsp` 跳过保护页，访问到其他映射。防护：`-fstack-clash-protection`，内核也增加了 guard gap。

## 六、常见错误

### 1. 返回局部变量地址

```c
char* bad(void) {
    char buf[32] = "hello";
    return buf;        // 函数返回后栈帧失效，悬空指针
}
```

修复：用 `static`、堆分配，或由调用者传入缓冲区。

### 2. 局部变量未初始化

栈内存是复用的，未初始化值不确定。不要假设为 0。

### 3. 大对象放栈上

```c
void foo(void) {
    int arr[1000000];   // 约 4MB，接近栈上限，容易崩
}
```

改用 `malloc` / `std::vector`（堆），或增大栈。

### 4. 递归深度失控

每个递归帧都占栈，深度过大必然溢出。改为迭代或显式栈。

### 5. 线程栈太小

默认 8MB，但高并发线程或深调用链可能需要调整：

```c
pthread_attr_t attr;
pthread_attr_init(&attr);
pthread_attr_setstacksize(&attr, 16 * 1024 * 1024);
```

## 八、面试标准简答

### 1. 栈的生长方向？

x86-64 向低地址增长，`rsp` 指向当前栈顶。`push` 先减 `rsp` 再写入，`pop` 先读再增。

### 2. 函数调用时栈发生了什么？

`call` 压入返回地址并跳转；被调函数保存 `rbp`、分配局部变量空间；返回时恢复 `rsp`/`rbp`，`ret` 弹出返回地址。整个过程只是移动指针。

### 3. 为什么栈上分配比堆快？

栈分配只是 `sub rsp, N`，释放是恢复 `rsp`；堆分配要走 `malloc` 的元数据、空闲链表、系统调用（brk/mmap），还有锁和碎片问题。

### 4. 栈溢出怎么防？

避免大局部数组和深递归；开启栈保护 canary、栈不可执行、ASLR/PIE；使用安全字符串函数；用 ASAN 检测；必要时增大线程栈或改堆分配。
