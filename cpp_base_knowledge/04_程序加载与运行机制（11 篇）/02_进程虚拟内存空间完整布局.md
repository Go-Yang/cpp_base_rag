# 进程虚拟内存空间完整布局

## 一、前言

每个进程都以为自己独占一整块内存，实际上看到的是内核通过页表映射出来的**虚拟地址空间**。理解布局是排查段错误、内存泄漏、地址随机化、栈溢出等问题的基础。

核心总纲：**虚拟地址连续，物理内存离散；权限按页控制，访问按需分配。** 进程地址空间从低到高大致是：代码 → 数据 → 堆 → mmap 区 → 栈 → 内核。

## 二、x86-64 地址空间

x86-64 目前使用 48 位虚拟地址（可扩展 57 位）：

- 用户空间：低半区，`0x0000000000000000` ~ `0x00007fffffffffff`，约 128TB；
- 内核空间：高半区，`0xffff800000000000` 以上；
- 中间是没有映射的 canonical hole，访问会触发 `SIGSEGV`。

页大小通常 4KB，页表四级：PML4 → PDPT → PD → PT。TLB 缓存地址翻译结果，缺页时由内核处理。

## 三、典型进程布局（x86-64 Linux）

从低地址到高地址：

```text
0x0000000000000000  空指针区（未映射，访问即崩）
        ↓
[可执行文件映射]
  .text / .rodata      r-x / r--   代码和只读常量
  .data / .bss         rw-         全局/静态变量
        ↓
[heap]                rw-           brk 堆，向高地址增长
        ↓
[mmap 区]             各种权限      共享库、mmap 文件、线程栈、匿名映射
        ↓             向低地址增长
[stack]                rw-          主线程栈，向低地址增长
[vvar] / [vdso]        r-- / r-x    内核提供的时间/系统调用加速
        ↑
0x00007fffffffffff  用户空间顶端
        ↓
内核空间（不可直接访问）
```

几点说明：

- 非 PIE 可执行文件通常从 `0x400000` 开始；PIE 可执行文件的基址随机；
- 共享库映射在 mmap 区，地址随机；
- 主线程栈从高地址开始向下增长，默认上限 8MB；
- 线程栈也在 mmap 区，每个线程一份；
- `[vdso]` 是内核映射的一段用户态代码，加速 `gettimeofday` 等调用；
- `[vsyscall]` 在 `0xffffffffff600000`，历史遗留机制。

## 四、VMA：内核如何描述内存

每个进程的 `mm_struct` 维护一棵 VMA 树（`vm_area_struct`），每项描述一段连续虚拟内存：

- 起止地址；
- 权限（读/写/执行）；
- 是否共享；
- 背后是文件还是匿名内存；
- 对应的文件偏移（文件映射时）。

```bash
cat /proc/<pid>/maps
```

输出示例：

```text
55f3a2c00000-55f3a2c01000 r--p 00000000 08:01 123456 /app
55f3a2c01000-55f3a2c02000 r-xp 00001000 08:01 123456 /app
55f3a2c02000-55f3a2c03000 r--p 00002000 08:01 123456 /app
55f3a2c03000-55f3a2c04000 r--p 00002000 08:01 123456 /app
55f3a4c00000-55f3a4c21000 rw-p 00000000 00:00 0      [heap]
7f1b2c000000-7f1b2c021000 rw-p 00000000 00:00 0
7ffd3a5f6000-7ffd3a617000 rw-p 00000000 00:00 0      [stack]
7ffd3a61b000-7ffd3a61f000 r--p 00000000 00:00 0      [vvar]
7ffd3a61f000-7ffd3a621000 r-xp 00000000 00:00 0      [vdso]
```

字段含义：地址范围、权限、文件偏移、设备号、inode、路径名。

## 五、按需分页与写时复制

### 1. 按需分页（demand paging）

`malloc` 返回的地址、`mmap` 映射的区域，开始时只是 VMA，**并没有分配物理页**。第一次读写触发缺页异常，内核才分配物理页：

- 匿名页：分配清零页；
- 文件页：从页缓存读取，必要时回写；
- 只读页：共享映射，同一文件多进程共用。

所以"申请了 1GB 内存"不等于"立即占用 1GB 物理内存"，RSS 才反映实际驻留。

### 2. 写时复制（COW）

`fork` 后父子进程共享只读页；任一方写入时触发缺页，内核复制一页再改。这样 fork 的开销与修改量相关，而不是与内存大小相关。

`/proc/<pid>/smaps` 里能看到 `Shared_Clean`、`Shared_Dirty`、`Private_Dirty` 等细分。

## 六、栈与堆的布局细节

### 1. 栈

- 主线程栈在用户空间顶端附近，向下增长；
- 栈底有一页保护页（`PROT_NONE`），越界触发 `SIGSEGV`；
- 默认大小由 `ulimit -s` 决定，常见 8MB；
- 线程栈在 mmap 区，大小由 `pthread_attr_setstacksize` 或默认值决定。

### 2. 堆

- `brk` 从可执行文件 `.bss` 之后开始向上扩展；
- glibc 的小块分配走 `brk` 主 arena；
- 大块分配、线程 arena 走 `mmap`；
- `[heap]` 只是 `brk` 区域，不代表所有 malloc 内存。

## 七、32 位与 64 位差异

| 维度 | 32 位 | 64 位 |
|---|---|---|
| 用户空间 | 约 3GB（3G/1G 划分） | 约 128TB |
| 地址位 | 32 位 | 48 位（可扩展） |
| 库地址 | 随机熵较小 | 随机熵大 |
| `mmap` 位置 | 通常向高地址增长 | 向低地址增长 |

32 位地址空间小，容易出现 `mmap` 失败、ASLR 熵不足、地址碎片等问题。

## 八、排查命令

| 目的 | 命令 |
|---|---|
| 查看进程内存映射 | `cat /proc/<pid>/maps` |
| 查看内存明细 | `cat /proc/<pid>/smaps` |
| 汇总映射 | `pmap -x <pid>` |
| 查看 VMA | `pmap <pid>` |
| gdb 查看映射 | `info proc mappings` |
| 查看段布局 | `readelf -l app` |
| 查看内存统计 | `cat /proc/<pid>/status | grep -E 'VmSize\|VmRSS'` |
| 查看缺页统计 | `cat /proc/<pid>/stat` 的 `majflt`/`minflt` |

## 九、常见问题

### 1. 段错误到底访问了哪里

先看 core/gdb 的崩溃地址，再对照 `/proc/<pid>/maps` 看该地址属于哪个 VMA、权限是否匹配。访问未映射地址或写只读页都会 `SIGSEGV`。

### 2. 为什么空闲内存比程序申请的小

按需分页 + COW：VSZ（虚拟大小）包含未实际分配的映射，RSS（驻留）才是物理内存占用。

### 3. 为什么大数组在栈上会崩

栈默认 8MB，超过保护页触发 `SIGSEGV`。改用堆分配，或增大 `ulimit -s`，或调线程栈大小。

### 4. 为什么地址每次运行都不同

ASLR 随机化了 PIE 基址、共享库、栈、mmap 区域。调试时可用 `setarch -R` 或 gdb 的 `set disable-randomization on` 关闭。

## 十、面试标准简答

### 1. 进程虚拟地址空间怎么布局？

从低到高：未映射区、可执行文件代码/只读数据、已初始化/未初始化数据、堆（向高增长）、mmap 区（共享库/线程栈/匿名映射，向低增长）、主线程栈（向低增长）、vDSO/vvar，顶端是内核空间。

### 2. 为什么每个进程都有独立地址空间？

页表把虚拟地址映射到不同物理页，进程间隔离。共享库的只读代码页可以映射到同一物理页，既能共享又不会互相篡改。

### 3. VSZ 和 RSS 的区别？

VSZ 是虚拟地址空间大小，包含尚未分配物理页的映射；RSS 是当前驻留在物理内存中的页大小。按需分页导致 VSZ 通常远大于 RSS。

### 4. 什么是 COW？

写时复制。`fork` 或 `mmap(MAP_PRIVATE)` 后父子进程共享只读页，任一方写入时内核复制该页，保证各自独立。它让 fork 的开销与实际修改量相关。

## 十一、极简口诀

**低地址代码数据堆，高地址栈往下长；**

**mmap 夹在中间段，共享库和线程栈；**

**虚拟连续物理散，按需分页 COW 管；**

**maps 看布局，smaps 看驻留。**
