# 宏函数与普通函数差异及踩坑

## 一、前言

宏函数在**预处理阶段**做纯文本替换，普通函数在**编译/链接/运行阶段**执行。两者看起来相似，底层模型完全不同：

- 宏：没有类型检查、没有调用栈、参数可能被多次求值；
- 函数：有类型检查、单次求值、可调试、有调用约定。

核心总纲：**宏是文本替换，不是函数调用。** 能用 `inline` 函数、`constexpr`、模板替代时，优先不用宏。

## 二、执行模型

### 1. 宏函数

```c
#define MAX(a, b) ((a) > (b) ? (a) : (b))
```

预处理后，调用点被文本替换：

```c
int r = MAX(x, y);
// 展开为：int r = ((x) > (y) ? (x) : (y));
```

- 没有函数实体、没有调用栈；
- 参数是文本，不进行类型检查；
- 每个使用点都展开一份代码，可能增大体积。

### 2. 普通函数

```c
int max(int a, int b) { return a > b ? a : b; }
```

- 参数先求值，再传递；
- 有类型检查；
- 有函数符号，可调试、可断点；
- 只有一份实现，多处调用复用。

### 3. inline 函数

```cpp
inline int max(int a, int b) { return a > b ? a : b; }
```

- 有类型检查、单次求值、可调试；
- 编译器可以选择内联展开，也可以生成 out-of-line 副本；
- 是宏函数的最佳替代品（C++）。

## 三、宏的常见坑

### 1. 参数重复求值

```c
#define MAX(a, b) ((a) > (b) ? (a) : (b))

int i = 0;
int r = MAX(i++, 10);
// 展开：((i++) > (10) ? (i++) : (10))
// i 可能自增两次
```

- 函数参数只求值一次；宏参数可能求值零次、一次或多次；
- 带副作用（`i++`、函数调用、赋值）的表达式禁止作为宏参数。

### 2. 运算符优先级

```c
#define SQR(x) x * x

SQR(1 + 2)   // 展开为 1 + 2 * 1 + 2 = 5，不是 9
```

修复：参数和整体都加括号：

```c
#define SQR(x) ((x) * (x))
```

### 3. 多语句宏与分号

```c
#define LOG_AND_RETURN(x) do { \
    log(x);                     \
    return x;                   \
} while (0)
```

- 用 `do { ... } while (0)` 包裹多语句宏，保证在 `if/else` 中作为单条语句使用；
- 不要写成 `{ ... }` 后直接跟分号，也不要让宏自带分号。

### 4. 宏名冲突

宏是全局文本替换，宏名与变量/函数/类型同名会误替换：

```c
#define max(a, b) ...
int max = 10;   // 被替换，编译错误
```

- 宏名统一大写并用项目前缀；
- 避免用常见短名（`min`、`max`、`count`）。

### 5. 调试困难

- 宏在预处理后消失，调试器默认看不到；
- GCC `-g3` 可以保留宏信息，`gdb` 的 `info macro` / `macro expand` 可查看；
- 但宏展开后的报错位置仍可能指向调用点，排查不如函数直观。

### 6. 可变参数宏的空参数问题

```c
#define LOG(fmt, ...) printf(fmt, __VA_ARGS__)

LOG("hello");   // 展开为 printf("hello", )，语法错误
```

解决方案：

- GNU 扩展：`##__VA_ARGS__`（空参数时删除前面的逗号）；
- C++20/C23：`__VA_OPT__(,)`。

```c
#define LOG(fmt, ...) printf(fmt __VA_OPT__(,) __VA_ARGS__)
```

## 四、宏的合理用途

宏不是一无是处，以下场景仍然常用：

- 头文件守卫；
- 条件编译（平台/调试开关）；
- 字符串化 `#x`、token 拼接 `a##b`；
- 日志宏，自动带上 `__FILE__`、`__LINE__`；
- 编译期断言（C11 `_Static_assert` / C++ `static_assert` 已替代部分宏）；
- 生成重复代码（X-Macro）。

## 五、宏与函数的选型

| 场景 | 建议 |
|---|---|
| 有类型、有参数运算 | 普通函数 / inline 函数 |
| 需要单次求值、副作用安全 | 函数 |
| 需要类型检查、可调试 | 函数 |
| 需要字符串化/拼接/条件编译 | 宏 |
| 需要零开销的小函数 | inline / constexpr（C++） |
| 日志带文件行号 | 宏（或封装成模板/函数 + 宏取位置） |

## 六、工程规范

1. 能用 `inline`/`constexpr`/模板就不用宏；
2. 带参宏的参数和整体必须加括号；
3. 多语句宏用 `do { ... } while (0)`；
4. 宏参数禁止副作用表达式；
5. 宏名大写 + 项目前缀；
6. 可变参数宏处理空参数；
7. 用 `gcc -E` 查看展开结果；
8. 在 CI 中开启 `-Wall -Wextra`，关注宏相关警告。

## 七、面试简答

### 1. 宏函数和普通函数的区别？

宏在预处理阶段做文本替换，没有类型检查、没有调用栈，参数可能多次求值；普通函数在运行期调用，参数先求值一次，有类型检查和调试信息。

### 2. 为什么 MAX(i++, 10) 有问题？

宏参数被文本替换到表达式中，`i++` 可能出现两次，导致自增两次。函数参数只会求值一次。

### 3. 如何写好多语句宏？

用 `do { ... } while (0)` 包裹，保证宏在语法上是一条语句，能安全地放在 `if/else` 后面。

### 4. 可变参数宏没有可变参数时怎么办？

GNU 用 `##__VA_ARGS__` 删除多余逗号；C++20/C23 用 `__VA_OPT__(,)`。

## 八、极简口诀

**宏是文本替换，不是函数调用；**

**参数可能多次算，括号必须全包住；**

**多语句 do-while，宏名大写加前缀；**

**能 inline 就别宏，展开结果 -E 看。**
