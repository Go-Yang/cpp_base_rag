# include守卫与pragma once工程规范

## 一、前言

`#include` 在预处理阶段是**纯文本拷贝**：把头文件内容原样粘贴到包含位置，不识别语法、不做去重。同一个头文件被多次包含，就会重复粘贴，引发类型/变量/函数重复定义。

头文件守卫就是防止重复粘贴的机制：

- 传统守卫：`#ifndef` / `#define` / `#endif`；
- 编译器扩展：`#pragma once`；
- 工程上也可两者同时使用。

核心总纲：**守卫解决"同一翻译单元内重复包含"；它不解决"同一实体的多份定义"（那需要头文件只放声明）。**

## 二、传统守卫

```c
#ifndef MYLIB_UTIL_H
#define MYLIB_UTIL_H

// 头文件内容：类型、声明、宏、模板、inline 函数

#endif // MYLIB_UTIL_H
```

执行逻辑：

1. 第一次包含：宏未定义，进入内容并定义宏；
2. 后续包含：宏已定义，整段跳过。

优点：

- 标准 C/C++，所有编译器支持；
- 可跨文件系统/符号链接路径工作（只要宏名一致）。

缺点：

- 宏名冲突会导致头文件被错误跳过；
- 需要手动维护，命名不规范容易撞名。

## 三、#pragma once

```c
#pragma once

// 头文件内容
```

- 非标准，但 GCC/Clang/MSVC 等主流编译器都支持；
- 由编译器根据文件身份（路径/inode）判断是否已包含；
- 不需要宏名，避免宏冲突。

注意：

- 同一文件通过不同路径/符号链接被包含时，个别实现可能识别为不同文件；
- 极老旧或特殊交叉编译环境可能不支持；
- 它不是 C/C++ 标准的一部分，但工程上广泛使用。

## 四、双重守卫

```c
#pragma once
#ifndef MYLIB_UTIL_H
#define MYLIB_UTIL_H

// 内容

#endif
```

双重守卫在支持 `#pragma once` 的编译器上走快速路径，在不支持的编译器上靠宏守卫兜底。代价是略微冗余，没有功能副作用。

是否使用取决于团队规范：

- 跨平台/老旧工具链：`#ifndef` 或双重守卫；
- 现代桌面/服务端：单独 `#pragma once` 也可以。

## 五、守卫解决不了的问题

### 1. 头文件里定义实体

```c
// bad.h
int g_count = 0;          // 每个包含者一份定义 → multiple definition
void helper(void) { }     // 同上
```

守卫只能防止**同一翻译单元重复包含**，不能防止**多个翻译单元各包含一次**。修复：头文件只放声明；函数加 `inline`；变量用 `extern` 或 C++17 `inline`。

### 2. 宏名冲突

两个头文件用了同一个守卫宏：

```c
// a.h
#ifndef UTIL_H
#define UTIL_H
...
#endif

// b.h
#ifndef UTIL_H      // 撞名
#define UTIL_H
...
#endif
```

包含 `a.h` 后再包含 `b.h`，`b.h` 会被整体跳过，出现"类型未定义"等奇怪错误。规范：宏名包含项目/模块/文件路径，例如 `MYPROJ_UTIL_LOG_H`。

### 3. 循环包含

A.h 包含 B.h，B.h 包含 A.h：

- 有守卫时不会无限递归，但其中一个头文件会先被跳过，导致类型不完整；
- 解决：前置声明、把依赖下沉到 `.cpp`、拆分公共类型。

### 4. 同一文件不同路径

符号链接、大小写差异、相对/绝对路径可能导致 `#pragma once` 识别失败或守卫宏不一致。统一包含路径和命名规范。

## 六、头文件自包含

好的头文件应当**自包含**：单独包含它不会报未定义类型/标识符。

```cpp
// widget.h
#pragma once
#include <string>        // 用到 std::string，就包含它
#include <vector>

class Widget {
    std::string name_;
    std::vector<int> data_;
public:
    void draw();
};
```

原则：

- 用到完整类型就包含对应头文件；
- 只需要指针/引用且不访问成员时，可用前置声明减少依赖；
- 不要依赖"包含顺序"或"别人已经包含过"。

## 七、工程规范

1. 所有头文件加守卫；
2. 守卫宏名全局唯一，包含项目/模块/文件名；
3. 守卫宏不要以下划线开头（保留给实现）；
4. 头文件只放声明、类型、模板、inline 函数；
5. 头文件自包含，包含它所需的依赖；
6. 优先前置声明减少编译依赖；
7. 统一包含路径，避免同一文件多路径。

## 八、面试简答

### 1. #ifndef 守卫和 #pragma once 的区别？

`#ifndef` 是标准宏守卫，靠宏名判断，跨编译器兼容；`#pragma once` 是编译器扩展，靠文件身份判断，简洁但非标准。两者都能防止同一翻译单元重复包含。

### 2. 为什么加了守卫还会 multiple definition？

守卫只防止同一翻译单元内重复包含。如果头文件里定义了变量/函数，多个翻译单元各包含一次，仍会各生成一份定义。修复是头文件只放声明，定义放源文件。

### 3. 守卫宏冲突会怎样？

后包含的头文件因为宏已定义而被整体跳过，导致类型/声明缺失，出现"未知类型""未定义标识符"等错误，甚至链接错误。守卫宏要加项目/模块前缀保证唯一。

### 4. 头文件为什么要自包含？

因为包含顺序不应影响正确性。自包含的头文件单独包含也能通过编译，减少隐式依赖和循环包含问题。

## 九、极简口诀

**include 是文本拷贝，重复包含会重定义；**

**ifndef 靠宏名，pragma once 靠文件；**

**守卫只防单 TU 重复，头文件只放声明；**

**宏名加前缀，头文件要自包含。**
