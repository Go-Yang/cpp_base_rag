# 全局变量、局部变量、静态变量生命周期

## 一、前言

变量行为由两个概念共同决定：

- **作用域（scope）**：代码里哪个位置能看见这个名字；
- **存储期（storage duration）**：对象在运行时活多久、何时分配/释放。

两者相互独立：函数内的 `static` 变量作用域是局部的，但存储期是整个程序。

核心总纲：**作用域管"看得见"，存储期管"活得久"。** 全局/静态变量是静态存储期，局部自动变量是自动存储期。

## 二、四种存储期

| 存储期 | 何时分配 | 何时释放 | 典型对象 |
|---|---|---|---|
| 自动（automatic） | 进入作用域 | 离开作用域 | 普通局部变量 |
| 静态（static） | 程序加载时 | 程序退出 | 全局变量、static 变量 |
| 线程（thread） | 线程启动 | 线程结束 | `thread_local` |
| 动态（dynamic） | `malloc`/`new` | `free`/`delete` | 堆对象 |

## 三、全局变量

```c
int g_count = 42;    // .data，静态存储期
int g_zero;          // .bss，零初始化
```

- 作用域：文件作用域，整个编译单元可见；其他文件需 `extern` 声明；
- 存储期：程序加载到退出；
- 初始化：静态存储期对象在 `main` 前零初始化，再用常量表达式初始化；
- 析构（C++）：全局对象通过 `__cxa_atexit` 在 `exit` 时逆序析构；
- 风险：全局可变状态导致耦合、并发竞争、测试污染。

### 静态全局变量

```c
static int g_private;   // 内部链接，只在本编译单元可见
```

存储期不变，作用域仍是文件作用域，但其他编译单元无法通过 `extern` 引用。

## 四、局部自动变量

```c
void foo(void) {
    int x;          // 未初始化，值不确定
    int y = 10;     // 初始化
}                   // 离开作用域，生命周期结束
```

- 作用域：块作用域；
- 存储期：进入块到离开块；
- 通常在栈上，分配/释放只是移动栈指针；
- 未初始化的局部变量值不确定，读取是未定义行为；
- 不能返回局部变量的地址/引用（函数返回后对象已销毁）。

## 五、静态局部变量

```c
void count(void) {
    static int n = 0;
    n++;
}
```

- 作用域：函数内（块作用域）；
- 存储期：整个程序；
- 存储位置：`.data`（有非零初值）或 `.bss`（零初值）；
- **存储分配发生在程序加载时**，不是第一次调用时；
- 初始化：
  - C：常量初值在 `main` 前完成；
  - C++：常量初始化在 `main` 前；动态初始化（需要运行时计算）在第一次执行到声明处完成；
  - C++11 起，动态初始化是线程安全的（编译器生成 guard 变量）；
- 析构（C++）：在 `exit` 时逆序析构。

```cpp
Logger& logger() {
    static Logger instance;   // C++11：首次调用时线程安全地构造
    return instance;
}
```

这是 Meyers Singleton 的基础。

## 六、静态成员（C++）

```cpp
struct Config {
    static int version;      // 属于类，不属于对象
    static int get();
};
int Config::version = 1;     // 类外定义
```

- 静态成员变量只有一份，所有对象共享；
- C++17 起可写 `inline static int version = 1;` 在类内定义；
- 静态成员函数没有 `this`，不能访问非静态成员；
- 静态成员的初始化顺序与全局对象类似，跨编译单元未定义。

## 七、thread_local（C++11 / C11）

```cpp
thread_local int tls_counter = 0;
```

- 每个线程一份，线程启动时初始化，线程结束时析构；
- 避免共享状态和锁竞争；
- 注意线程池中线程复用，thread_local 会在不同任务之间保留值；
- 动态库中使用静态 TLS 可能遇到加载限制。

## 八、初始化顺序问题

### 1. 静态初始化顺序灾难

```cpp
// a.cpp
extern std::string g_name;
std::string g_greeting = "hi " + g_name;

// b.cpp
std::string g_name = "foo";
```

不同编译单元的动态初始化顺序未定义，`g_name` 可能尚未构造。

规避：

- 用函数内 static（首次使用时初始化）；
- 显式初始化函数；
- 避免跨编译单元的全局对象依赖。

### 2. 析构顺序

- 同一编译单元内逆序析构；
- 跨编译单元顺序未定义；
- 全局对象析构时访问已析构对象会崩溃。

## 九、常见错误

### 1. 返回局部变量地址

```c
char* bad(void) {
    char buf[16] = "hello";
    return buf;      // 悬空指针
}
```

修复：返回 `static`、堆内存，或由调用者传入缓冲区。

### 2. 认为局部变量默认清零

局部自动变量不清零，值不确定。静态存储期变量才零初始化。

### 3. static 变量线程竞争

函数内 static 的初始化是线程安全的，但之后的读写仍需同步。

### 4. 大数组放栈上

局部大数组容易栈溢出；静态/全局大数组会占 `.bss`（不占文件，但占虚拟内存，首次写入分配物理页）。

## 十、面试简答

### 1. 全局变量和局部变量的生命周期？

全局变量是静态存储期，程序加载时分配、退出时释放；普通局部变量是自动存储期，进入作用域分配、离开释放；函数内 static 是静态存储期但作用域局部。

### 2. 函数内 static 变量什么时候初始化？

存储分配在程序加载时。C 的常量初值在 `main` 前完成；C++ 的常量初始化在 `main` 前，动态初始化在第一次执行到声明处（C++11 起线程安全）。

### 3. 什么是静态初始化顺序灾难？

不同编译单元的全局对象动态初始化顺序未定义。一个对象的构造函数访问另一个编译单元的全局对象时，后者可能尚未初始化，导致未定义行为。用函数内 static 或显式初始化规避。

### 4. 局部变量没初始化为什么是随机值？

自动存储期变量在栈上，栈内存复用之前调用的数据，不保证清零。读取未初始化变量是未定义行为。

## 十一、极简口诀

**作用域管看见，存储期管活多久；**

**全局 static 活到老，局部自动出栈就没；**

**静态局部加载时分地，C++ 首次执行才构造；**

**局部不清零，跨单元初始化顺序不定。**
