# extern跨文件符号引用规范

## 一、extern底层核心本质

extern 是**编译期符号声明指令**，不分配内存、不产生实体、不参与初始化，仅作用是：告知编译器「该变量/函数的实体定义存在于当前工程其他位置」。

C/C\+\+ 工程严格遵循**声明与定义分离原则**：extern 负责声明，源码全局实体负责定义，链接阶段统一匹配符号。

## 二、声明与定义严格区分（核心准则）

### 1\. 定义（Definition）

触发**内存分配、符号生成、初始化**，一个工程内全局符号**有且只能有一个定义**，违反触发多重定义链接错误。

```c
int g_num;        // 无初始化：BSS段定义
int g_val = 100;  // 带初始化：DATA段定义
```

### 2\. 声明（Declaration）

仅告知编译器符号类型与名称，不分配内存，可在工程内多处重复声明。

```c
extern int g_num;
extern int g_val;

```

## 三、extern修饰变量完整机制

### 1\. 跨文件引用流程

1. 文件A：定义全局变量，生成全局符号，分配内存；

2. 文件B：通过 extern 声明外部符号，编译阶段通过类型校验；

3. 链接阶段：链接器匹配全局符号表，完成符号重定位，关联外部实体地址。

### 2\. 关键特性

- extern 声明的变量**无默认初始化**，完全依赖外部定义；

- 仅全局变量可被 extern 跨文件引用，局部变量不支持；

- static 全局变量为文件私有符号，extern 无法引用、无法跨文件链接。

## 四、extern修饰函数机制

C/C\+\+ 所有普通函数**默认自带 extern 属性**，默认全局可见。

### 1\. 隐式声明

直接写函数原型等价于 extern 声明：

```c
// 完全等价 extern int func(int a);
int func(int a);

```

### 2\. static函数隔离规则

static 修饰的函数为文件级私有符号，仅当前文件可用，外部无法声明、无法调用、链接器检索不到该符号。

## 五、头文件中的extern工程规范

### 1\. 标准工程写法

头文件统一放 **extern 声明**，源文件单独放**唯一定义**。

```c
// global.h
extern int g_config;

// global.c
int g_config = 0;

```

优势：多文件include头文件只会加载声明，不会重复定义，彻底规避多重定义报错。

### 2\. 致命错误写法

头文件直接定义全局变量，多文件include后，每个编译单元都会生成一份定义，链接报错 multiple definition。

## 六、弱符号与强符号对extern的影响

- **强符号**：带初始化的全局定义、函数定义；

- **弱符号**：无初始化全局变量定义；

- extern 声明属于**无符号实体**，不参与强弱判定。

链接规则：多弱符号可合并，强弱共存取强符号，多强符号直接报错。

## 七、高频报错场景与根治方案

### 1\. multiple definition 多重定义

**根因**：头文件写变量定义、多文件重复定义全局符号。

**解决方案**：头文件统一extern声明，源文件唯一定义。

### 2\. undefined reference 未定义引用

**根因**：仅extern声明，工程内无真实定义；或定义文件未参与编译链接。

**解决方案**：补充全局定义、确认对应源文件加入编译列表。

### 3\. 无法引用static全局变量

**根因**：static全局符号作用域锁定当前文件，不进入全局符号表。

**解决方案**：去除static修饰，或通过文件内接口函数导出数据。

## 八、C与C\+\+混编extern"C"特殊规范

C\+\+支持函数重载，会对函数名**名字改编**，C语言无改编规则，混编会导致符号名不匹配、链接失败。

```c
// 头文件兼容C/C++
#ifdef __cplusplus
extern "C" {
#endif

void c_func(int a);

#ifdef __cplusplus
}
#endif
```

extern "C" 作用：强制C\+\+编译器以C语言规则生成符号，关闭名字改编，实现混编链接兼容。

## 九、最终工程落地规范

1. 所有跨文件全局变量：**头文件extern声明，源文件唯一定义**；

2. 不需要跨文件访问的全局变量/函数，一律加static私有化；

3. 禁止在头文件定义全局实体，杜绝多文件重复定义；

4. C/C\+\+混编场景，对外C接口必须包裹 extern "C"；

5. 仅声明不定义的extern变量，禁止直接赋值初始化。
