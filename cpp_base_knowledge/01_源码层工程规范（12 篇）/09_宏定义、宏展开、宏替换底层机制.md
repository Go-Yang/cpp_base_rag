# 宏定义、宏展开、宏替换底层机制

## 一、前言

宏的全部行为发生在**预处理阶段**。预处理器不理解类型、作用域、函数，只按规则做 token 级替换。

核心总纲：**宏是 token 替换，不是文本字符串替换。** 理解"参数预扫描、字符串化、token 拼接、重扫描、禁止自递归"这几个步骤，才能看懂宏展开的真实结果。

## 二、两类宏

### 1. 对象宏

```c
#define MAX_LEN 1024
#define DEBUG_MODE
```

- 无参数，出现即替换；
- 空宏常用于条件编译标记；
- 替换在 token 层进行，不会替换字符串字面量或标识符的一部分。

### 2. 函数宏

```c
#define SQR(x) ((x) * (x))
#define MAX(a, b) ((a) > (b) ? (a) : (b))
```

- 参数是 token 序列；
- 调用必须带括号，否则不展开；
- 展开时先对参数做预处理（宏展开），再替换到宏体，最后重新扫描展开结果。

## 三、展开步骤

以 `#define MAX(a,b) ((a)>(b)?(a):(b))` 和 `MAX(x, y)` 为例：

1. **识别调用**：宏名后跟 `(`，匹配参数列表；
2. **参数预扫描**：参数本身如果是其他宏，先展开（除非用于 `#` 或 `##`）；
3. **替换**：把参数 token 替换到宏体中的形参位置；
4. **重扫描**：对替换后的结果再次扫描，展开其中出现的其他宏；
5. **禁止自递归**：正在展开的宏名在本次展开中被"涂蓝"，不会无限递归。

```c
#define A 1
#define B A + 1
B          // 展开为 1 + 1
```

## 四、字符串化 # 与拼接 ##

### 1. 字符串化

```c
#define STR(x) #x
STR(hello)        // "hello"
STR(1 + 2)        // "1 + 2"（不计算）
```

- `#` 把参数字符串化；
- 参数前后的空白会被规范化；
- 参数中的 `"` 和 `\` 会被转义。

### 2. token 拼接

```c
#define CAT(a, b) a##b
CAT(foo, bar)     // foobar
```

- `##` 把两个 token 拼成一个；
- 拼接结果必须是合法 token，否则行为未定义/报错；
- 不能拼接字符串字面量和注释；
- 常见用途：生成变量名/函数名。

### 3. 宏参数的展开时机

`#` 和 `##` 的参数**不会先展开**：

```c
#define STR(x) #x
#define X 42
STR(X)        // "X"，不是 "42"

#define CAT(a,b) a##b
#define X 42
CAT(X, 1)     // X1，不是 421
```

需要先展开时，加一层间接宏：

```c
#define STR_IMPL(x) #x
#define STR(x) STR_IMPL(x)
STR(X)        // "42"
```

## 五、可变参数宏

```c
#define LOG(fmt, ...) printf(fmt, __VA_ARGS__)
```

问题：没有可变参数时展开为 `printf(fmt, )`，语法错误。

解决方案：

- GNU 扩展 `##__VA_ARGS__`：空参数时删除前面的逗号；
- C++20/C23 `__VA_OPT__(,)`：有参数时展开逗号，无参数时展开为空。

```c
#define LOG(fmt, ...) printf(fmt __VA_OPT__(,) __VA_ARGS__)
```

## 六、宏重定义与 #undef

```c
#define FOO 1
#undef FOO
#define FOO 2
```

- 同名宏重定义，如果 token 序列完全相同，允许；
- 不同则报错（编译器可能给警告/错误）；
- `#undef` 取消定义，后续不再替换；
- 头文件/第三方库可能定义同名宏，注意命名前缀。

## 七、常见坑

### 1. 优先级

```c
#define SQR(x) x * x
SQR(1 + 2)     // 1 + 2 * 1 + 2 = 5
```

参数和整体都要加括号。

### 2. 多次求值

```c
#define MAX(a, b) ((a) > (b) ? (a) : (b))
MAX(i++, 10)   // i++ 可能执行两次
```

### 3. 宏体中的逗号

```c
#define FOO(a, b) ...
FOO({1, 2}, 3)   // 花括号里的逗号可能被当作参数分隔
```

用括号包裹复合字面量，或改用函数/模板。

### 4. 宏与作用域

宏没有作用域，从定义点到最后都生效；头文件里的宏会污染包含者。用 `#undef` 或命名前缀控制。

### 5. 调试

```bash
gcc -E app.c -o app.i      # 查看预处理结果
gcc -dM -E - < /dev/null   # 查看编译器预定义宏
```

GCC `-g3` 可以让 gdb 显示宏信息（`info macro`、`macro expand`），但展开后的报错位置仍可能指向调用点。

## 八、工程规范

1. 宏名大写，加项目/模块前缀；
2. 带参宏的参数和整体加括号；
3. 多语句宏用 `do { ... } while (0)`；
4. 避免副作用参数；
5. 能用 `inline`/`constexpr`/模板就不用宏；
6. 宏定义集中在专门头文件，避免污染；
7. 用 `-E` 检查展开结果，用 `-dM` 检查预定义宏。

## 九、面试简答

### 1. 宏展开的过程？

识别宏调用 → 参数预扫描（除非用于 `#`/`##`）→ 替换到宏体 → 重新扫描展开结果 → 正在展开的宏不再递归。`#` 字符串化、`##` 拼接 token。

### 2. 为什么 STR(X) 得到 "X" 而不是 "42"？

因为 `#` 的参数不会先展开，直接字符串化 token `X`。需要两层宏：外层展开参数，内层字符串化。

### 3. 宏的副作用问题？

宏参数是文本替换，可能被求值多次（如 `MAX(i++, 10)`），也可能因为优先级缺少括号而改变语义。函数参数只求值一次，且有类型检查。

### 4. 可变参数宏没有参数怎么办？

GNU 用 `##__VA_ARGS__`，C++20/C23 用 `__VA_OPT__(,)`，避免展开出多余逗号。

## 十、极简口诀

**宏是 token 替换，先扫参数再重扫；**

**# 字符串化，## 拼 token；**

**# 和 ## 不展开参数，间接宏解一层；**

**参数整体加括号，副作用别进宏。**
