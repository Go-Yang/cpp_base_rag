# 结构体、联合体内存对齐规则

## 一、前言

结构体大小不等于成员大小之和。编译器会插入填充字节，保证每个成员按自身对齐要求存放，并让结构体大小是最大对齐的整数倍。

核心总纲：**成员按自身对齐排布，结构体按最大对齐取整；顺序不同，大小可能差很多。** 对齐是 ABI 和性能要求，打包/重排要谨慎。

## 二、对齐规则

### 1. 三条基本规则

1. 每个成员的偏移必须是该成员对齐值的整数倍；
2. 结构体总大小必须是最大成员对齐值的整数倍；
3. 编译器可以在成员之间和末尾插入填充。

### 2. 示例

```c
struct A {
    char  a;   // offset 0
    int   b;   // 需要 4 对齐 → offset 4，填充 3 字节
    char  c;   // offset 8
};             // 最大对齐 4 → 总大小 12
```

```c
struct B {
    int   b;   // offset 0
    char  a;   // offset 4
    char  c;   // offset 5
};             // 填充 2 字节 → 总大小 8
```

同样的成员，重排后从 12 字节降到 8 字节。

### 3. 对齐值由类型决定

- `char`：1；
- `short`：2；
- `int`：4；
- `long`：平台相关（LP64 为 8，LLP64/Windows 为 4）；
- 指针：4（32 位）或 8（64 位）；
- `double`：通常 8；
- `long double`：x86-64 通常 16；
- SIMD 类型：16/32/64，取决于类型和编译选项。

**不要背"最大对齐 8"这种固定规则**，对齐由类型和 ABI 决定，平台差异很大。

### 4. 数组与嵌套结构体

```c
struct S {
    char a[10];   // 元素对齐 1，整体对齐 1
    int b;        // 需要 4 对齐
};
```

- 数组的对齐等于元素的对齐，不是数组长度；
- 嵌套结构体的对齐等于其成员的最大对齐；
- 嵌套结构体的偏移也必须是其对齐的整数倍。

## 三、查看与验证

```c
#include <stddef.h>
offsetof(struct A, b);    // 4
sizeof(struct A);         // 12
```

编译期断言：

```cpp
static_assert(sizeof(struct A) == 12);
static_assert(offsetof(struct A, b) == 4);
```

工具：

```bash
pahole app           # 显示结构体布局和空洞
gcc -Wpadded ...     # 提示填充（噪声较大）
```

## 四、数据模型与平台差异

| 模型 | 平台 | int | long | 指针 |
|---|---|---|---|---|
| LP64 | Linux/macOS 64 位 | 4 | 8 | 8 |
| LLP64 | Windows 64 位 | 4 | **4** | 8 |
| ILP32 | 32 位 | 4 | 4 | 4 |

跨平台代码不要假设 `long` 是 8 字节；需要固定宽度时用 `<stdint.h>` 的 `int32_t`/`int64_t`。

## 五、手动控制对齐

### 1. #pragma pack

```c
#pragma pack(push, 1)
struct Packed {
    char a;
    int  b;     // offset 1，未对齐
};
#pragma pack(pop)
```

或：

```c
struct __attribute__((packed)) Packed {
    char a;
    int  b;
};
```

- 取消填充，结构体大小可能等于成员大小之和；
- 代价：成员可能未对齐。

### 2. alignas / alignof（C++11）

```cpp
struct alignas(16) Vec4 {
    float x, y, z, w;
};
```

- 提高对齐要求；
- 可用于 SIMD、缓存行对齐；
- 堆分配要用 `aligned_alloc`/`posix_memalign`/对齐版 `operator new`。

### 3. 未对齐访问的风险

- x86 通常能处理未对齐访问，但可能变慢；
- ARM/MIPS 等架构可能触发总线错误（取决于架构和配置）；
- 原子操作、引用绑定、取地址可能要求对齐；
- 编译器可能生成逐字节访问，性能下降。

协议解析建议用 `memcpy` 到对齐的局部变量，而不是直接解引用 packed 指针。

## 六、联合体

### 1. 大小规则

- union 的大小至少是最大成员的大小；
- 最终大小要向上对齐到最大成员对齐值的整数倍。

```c
union U {
    char buf[13];   // 大小 13，对齐 1
    int  val;       // 大小 4，对齐 4
};
// 最大大小 13，最大对齐 4 → 向上取整到 16
```

### 2. 活跃成员与读取规则

- union 同一时刻只有一个活跃成员；
- **C**：读取非活跃成员是类型双关，结果由实现定义/未指定（不是标准 UB）；
- **C++**：读取非活跃成员通常是未定义行为（common initial sequence 例外）；
- 用 memcpy 做类型双关更安全、可移植。

```c
uint32_t u = 0x12345678;
float f;
memcpy(&f, &u, sizeof f);   // 明确的类型双关
```

## 七、ABI 与序列化

- 公开结构体的布局是 ABI 的一部分，改变成员顺序/类型会破坏二进制兼容；
- 跨库传递结构体时，双方必须使用相同的对齐/pack 设置；
- 网络协议/文件格式不要直接按内存布局发送结构体，字段逐个序列化更可靠；
- `#pragma pack(1)` 的结构体不适合直接做指针解引用，先 memcpy 到对齐对象。

## 八、面试简答

### 1. 结构体对齐规则？

每个成员偏移是其对齐值的整数倍；结构体总大小是最大对齐值的整数倍；编译器在成员间和末尾插入填充。重排成员（大的在前）可减少填充。

### 2. 如何减少结构体内存浪费？

按对齐从大到小排列成员；用 `offsetof`/`pahole` 检查；必要时用位域/打包（注意未对齐风险）；不要为省字节破坏 ABI。

### 3. long 一定占 8 字节吗？

不一定。Linux/macOS 64 位是 LP64（long=8），Windows 64 位是 LLP64（long=4），32 位通常是 4。跨平台用 `<stdint.h>` 固定宽度类型。

### 4. union 的大小怎么算？

至少是最大成员大小，并向上对齐到最大成员对齐值的整数倍。读非活跃成员在 C 中是实现定义/未指定，在 C++ 中通常是 UB。

## 九、极简口诀

**成员按自身对齐，结构按最大取整；**

**大成员放前面，填充自然变少；**

**long 平台不同，固定宽度用 stdint；**

**union 大小看最大，读非活跃 C++ 是 UB。**
