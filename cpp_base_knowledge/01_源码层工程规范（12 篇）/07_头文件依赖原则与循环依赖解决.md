# 头文件依赖原则与循环依赖解决

## 一、前言

`#include` 在预处理阶段是**纯文本拷贝**：预处理器不识别类型、类、函数，只把目标文件内容原样粘贴进来。因此头文件问题的本质是：

- 重复粘贴（重复包含）；
- 顺序错乱（依赖未满足）；
- 循环粘贴（循环依赖）。

核心总纲：**头文件必须自包含；用到完整类型就包含，能用前置声明就前置声明；循环依赖靠前置声明、下沉实现、拆分公共类型解决。**

## 二、头文件自包含

一个头文件单独包含时，应当不依赖任何"之前已经包含过的东西"：

```cpp
// widget.h
#pragma once
#include <string>
#include <vector>

class Widget {
    std::string name_;
    std::vector<int> data_;
public:
    void draw();
};
```

原则：

- 头文件的声明/定义用到了某个类型的完整定义，就必须包含对应头文件；
- 只用到指针/引用且不访问成员时，可以用前置声明；
- 不要依赖包含顺序。

## 三、前置声明

```cpp
// 只需要指针/引用，不需要完整定义
class Engine;      // 前置声明

class Car {
    Engine* engine_;   // 可以
public:
    void set_engine(Engine* e);
};
```

适用：

- 成员是指针/引用；
- 函数参数/返回值是指针/引用；
- 不需要在头文件中访问该类型的成员、调用方法、计算大小。

不适用：

- 成员是值类型（需要完整定义和大小）；
- 继承基类（需要完整定义）；
- 内联函数体里访问成员/调用方法（需要完整定义）；
- 模板参数需要完整类型时（取决于用法）。

好处：

- 减少编译依赖，加快增量编译；
- 降低循环依赖风险。

## 四、循环依赖

### 1. 典型场景

```cpp
// a.h
#include "b.h"
class A { B b_; };

// b.h
#include "a.h"
class B { A a_; };
```

两个头文件互相包含，且成员是值类型。这是**不可能同时成立**的：A 的大小依赖 B，B 的大小依赖 A。

### 2. 解决方案

#### 方案一：改成指针/引用 + 前置声明

```cpp
// a.h
class B;
class A { B* b_; };

// b.h
class A;
class B { A* a_; };
```

如果确实需要双向值包含，说明设计有问题，应重新划分职责。

#### 方案二：依赖下沉到 .cpp

头文件只暴露必要接口，具体类型的包含和实现放源文件：

```cpp
// a.h
class B;                 // 前置声明
class A {
    B* b_;
public:
    void do_work();
};

// a.cpp
#include "b.h"
void A::do_work() { b_->run(); }
```

#### 方案三：拆分公共类型

把双方共同依赖的类型抽到独立头文件，A、B 都只依赖公共层，不再互相依赖。

#### 方案四：pimpl（编译防火墙）

```cpp
// widget.h
class Widget {
    struct Impl;
    std::unique_ptr<Impl> impl_;
public:
    Widget();
    ~Widget();
    void draw();
};
```

实现细节完全隐藏在 `.cpp`，头文件依赖最小。

## 五、包含顺序

常见规范：

1. 当前源文件对应的头文件；
2. C 标准库；
3. C++ 标准库；
4. 第三方库；
5. 项目内其他头文件。

好处：当前头文件不依赖其他包含也能通过，暴露自包含性问题。具体顺序可按团队规范调整，但同一项目要统一。

## 六、减少头文件依赖

- 用前置声明替代包含；
- 用 `const T&` / `T*` 参数减少值类型依赖；
- 用 pimpl 隐藏实现；
- 用接口类/依赖注入降低耦合；
- 避免在头文件里包含"大而全"的聚合头；
- 用 include-what-you-use（IWYU）检查多余/缺失的包含；
- 预编译头（PCH）可以加速编译，但不改变依赖关系。

## 七、常见错误

### 1. 头文件只声明、不包含依赖

"头文件尽量不 include"是错误建议。自包含要求头文件包含它声明所需的定义；否则包含顺序一变就编译失败。

### 2. 循环包含 + 值成员

A 包含 B，B 包含 A，且成员是值类型，无法通过前置声明解决，必须改设计（指针/引用、下沉实现、拆分公共类型）。

### 3. 前置声明后使用成员

```cpp
class Engine;
class Car {
    Engine engine_;   // 错误：需要完整定义
};
```

前置声明只能用于指针/引用，不能用于值成员。

### 4. 头文件里定义实体

头文件放函数/变量定义会导致 multiple definition；模板和 inline 函数是例外。

## 八、面试简答

### 1. 头文件为什么要自包含？

因为包含顺序不应影响正确性。自包含的头文件单独包含也能编译，减少隐式依赖和"换个文件就报错"的问题。

### 2. 前置声明的适用场景？

只需要指针/引用、不需要完整定义时使用；成员是值类型、继承、内联访问成员、需要 sizeof 时必须包含完整定义。

### 3. 如何解决头文件循环依赖？

用前置声明 + 指针/引用；把实现和依赖下沉到 `.cpp`；拆分公共类型到独立头文件；用 pimpl 隐藏实现。值类型的双向依赖无法只靠前置声明解决，必须改设计。

### 4. 为什么头文件里定义变量会多重定义？

头文件内容被复制到每个包含它的编译单元，每个单元都生成一份定义，链接时冲突。头文件只放声明，定义放源文件。

## 九、极简口诀

**include 是文本拷贝，头文件要自包含；**

**指针引用可前置，值成员必须完整；**

**循环依赖三招解：前置、下沉、拆公共；**

**pimpl 做防火墙，包含顺序要统一。**
