# 预处理所有指令完整解析

## 一、前言

预处理是编译的第一阶段：处理以 `#` 开头的指令、展开宏、包含头文件、裁剪条件编译分支，输出一个不再含预处理指令的翻译单元。

核心总纲：**预处理只做 token 级文本处理，不理解类型和作用域。** 但"文本处理"不等于"无脑字符串替换"——宏展开有明确的 token 规则。

## 二、预处理指令总览

| 类别 | 指令 |
|---|---|
| 文件包含 | `#include` |
| 宏定义 | `#define`、`#undef` |
| 条件编译 | `#if`、`#ifdef`、`#ifndef`、`#elif`、`#else`、`#endif` |
| 诊断 | `#error`、`#warning` |
| 编译器控制 | `#pragma` |
| 行号/文件名 | `#line` |

注意：`defined` 不是指令，而是 `#if`/`#elif` 中的运算符。

## 三、#include

### 1. 两种形式

```c
#include <stdio.h>      // 系统/标准头文件
#include "my_header.h"  // 自定义头文件
```

GCC 的搜索顺序（简化）：

- `"..."`：当前文件所在目录 → `-iquote` 目录 → `-I` 目录 → 系统目录；
- `<...>`：`-I` 目录 → 系统目录（不搜索当前文件目录）；
- `-isystem` 用于系统级第三方头文件，抑制部分警告。

### 2. 行为

- 预处理阶段把头文件内容原样包含（token 化之后）；
- 嵌套包含递归处理；
- 用 include guard / `#pragma once` 防止重复包含；
- 注意：`#include` 是文本包含，不是模块导入。

## 四、#define / #undef

### 1. 对象宏

```c
#define MAX_LEN 1024
```

### 2. 函数宏

```c
#define SQR(x) ((x) * (x))
```

- 参数和整体加括号；
- 避免副作用参数；
- 多语句宏用 `do { ... } while (0)`。

### 3. 字符串化与拼接

```c
#define STR(x) #x
#define CAT(a, b) a##b
```

- `#` 把参数变成字符串；
- `##` 拼接 token；
- `#`/`##` 的参数不会先展开，需要间接宏。

### 4. 取消定义

```c
#undef MAX_LEN
```

用于避免宏污染、局部覆盖。

## 五、条件编译

```c
#if defined(_WIN32)
    // Windows
#elif defined(__linux__)
    // Linux
#else
    #error "unsupported platform"
#endif
```

- `#if` 支持整数常量表达式、`defined`、比较、逻辑运算；
- 条件为假的分支在预处理阶段被删除，不参与编译；
- 必须成对使用 `#endif`；
- 注意宏展开后的值，未定义标识符在 `#if` 中按 0 处理（`-Wundef` 可警告）。

## 六、#error / #warning

```c
#ifndef __cplusplus
#error "this header requires C++"
#endif

#warning "deprecated API"
```

- `#error` 终止编译；
- `#warning` 输出警告（GCC 扩展，C23 标准化为 `#warning`）；
- 常用于平台/编译器/配置校验。

## 七、#pragma

```c
#pragma once
#pragma pack(push, 1)
#pragma GCC diagnostic push
#pragma GCC diagnostic ignored "-Wunused-parameter"
#pragma GCC diagnostic pop
```

- `#pragma` 是编译器特定的；
- `#pragma once`：头文件只包含一次；
- `#pragma pack`：控制结构体对齐；
- `#pragma GCC diagnostic`：局部开关警告；
- C++11 提供 `_Pragma("...")` 可在宏中使用。

## 八、#line

```c
#line 100 "generated.c"
```

- 修改编译器记录的当前行号和文件名；
- 常用于代码生成器、预处理器输出；
- `__LINE__`、`__FILE__` 会随之变化。

## 九、预定义宏

| 宏 | 含义 |
|---|---|
| `__FILE__` | 当前源文件名 |
| `__LINE__` | 当前行号 |
| `__DATE__` | 编译日期 |
| `__TIME__` | 编译时间 |
| `__cplusplus` | C++ 标准版本（如 201703L） |
| `__STDC__` | C 标准 |
| `__STDC_VERSION__` | C 标准版本 |
| `__GNUC__` / `__clang__` / `_MSC_VER` | 编译器标识 |
| `_WIN32` / `__linux__` / `__APPLE__` | 平台标识 |

查看编译器预定义宏：

```bash
gcc -dM -E - < /dev/null
clang -dM -E - < /dev/null
```

## 十、查看预处理结果

```bash
gcc -E app.c -o app.i       # 输出预处理结果
gcc -E -P app.c             # 不输出行标记
gcc -E -dM app.c            # 只输出宏定义
```

- `.i` 文件能看到头文件展开、宏替换、条件编译裁剪后的真实代码；
- 排查宏问题、头文件问题、条件编译问题，先看 `.i`。

## 十一、常见错误

### 1. 缺 `#endif` / 条件嵌套错乱

```text
error: unterminated conditional directive
```

### 2. 宏参数未加括号

展开后优先级错误，运行结果异常。

### 3. 多行宏续行符后带空格

```c
#define FOO(x) do { \
    bar(x);          \
} while (0)
```

`\` 必须是行尾最后一个字符，后面不能有空格/Tab。

### 4. 头文件重复包含

缺守卫导致重定义；用 `#pragma once` 或 `#ifndef`。

### 5. 条件编译把代码裁没了

`#ifdef` 拼写错误、宏未定义、`#endif` 位置错误。用 `-E` 查看最终代码。

### 6. 宏污染

头文件里的宏影响包含者；用前缀命名、`#undef`、只在需要处定义。

## 十二、工程规范

1. 头文件必须加守卫；
2. 宏名大写 + 项目前缀；
3. 带参宏参数/整体加括号；
4. 多语句宏用 `do { ... } while (0)`；
5. 条件编译加缩进/注释，保证配对；
6. 优先 `constexpr`/`inline`/模板替代宏；
7. 用 `-E`、`-dM` 排查预处理问题。

## 十三、面试简答

### 1. 预处理做了什么？

处理 `#include`、`#define`、条件编译等指令，展开宏、包含头文件、删除注释、裁剪分支，输出不含预处理指令的翻译单元。

### 2. `#include "..."` 和 `<...>` 的区别？

双引号先搜索当前文件目录和 `-iquote`/`-I` 目录，再搜索系统目录；尖括号只搜索 `-I` 和系统目录，不搜索当前文件目录。

### 3. `defined` 是指令吗？

不是，它是 `#if`/`#elif` 中的运算符，用于判断宏是否定义。

### 4. 如何查看宏展开后的代码？

`gcc -E` 生成 `.i` 文件；`gcc -dM -E` 查看所有预定义宏。

## 十四、极简口诀

**include 粘文本，define 换 token；**

**条件编译裁分支，error 拦、warning 提；**

**pragma 给编译器，line 改行号；**

**排查宏和头文件，先看 -E 的 .i。**
