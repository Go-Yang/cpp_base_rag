# C/C++ 语法差异与混编基础规则

## 一、前言

" C++ 是 C 的超集"是一句流传很广但不准确的话。C++ 从 C 演化而来，大量语法兼容，但**不是严格超集**：有些 C 代码在 C++ 中不合法，有些行为语义不同。

核心总纲：**C 和 C++ 是两门语言，共享大部分语法；混编的关键是统一链接规则（extern "C"）和 ABI，而不是假设代码可以无脑互编。**

## 二、C 与 C++ 的主要差异

### 1. 类型与转换

| 维度 | C | C++ |
|---|---|---|
| `void*` 转换 | 可隐式转为任意对象指针 | 必须显式转换 |
| 隐式函数声明 | C89 允许（C99 起约束违规） | 完全禁止 |
| 函数原型 | 可写 `f()` 不声明参数 | `f()` 表示无参数，`f(void)` 同义 |
| 字符字面量 | `'a'` 是 int 类型 | `'a'` 是 char 类型 |
| 布尔类型 | C99 起 `_Bool` | 内置 `bool` |

```c
void* p = malloc(100);
int* q = p;        // C 合法；C++ 报错，需要 (int*)p
```

### 2. const 的链接属性

- C：文件作用域 `const` 默认外部链接；
- C++：命名空间作用域 `const` 默认内部链接；要跨编译单元共享需 `extern`。

```cpp
// C++ 头文件
extern const int kMax;   // 声明
// 一个 .cpp
extern const int kMax = 100;   // 定义
```

### 3. 结构体与类型名

- C：`struct Foo` 的类型名是 `struct Foo`，通常需要 `typedef` 才能写 `Foo`；
- C++：`struct Foo` 直接引入类型名 `Foo`，且 struct 是类的一种（默认 public）。

### 4. C++ 独有特性

- 函数重载、默认参数、命名空间；
- 引用、类、继承、多态、模板；
- 异常、RTTI、`new/delete`；
- `constexpr`、lambda、auto、范围 for；
- 标准库容器/算法/智能指针。

这些特性依赖 **name mangling** 和 C++ ABI，不能直接暴露给 C。

### 5. C 独有/不同的特性

- 变长数组（VLA，C99；C++ 标准不支持，GCC 作为扩展）；
- 复合字面量、指定初始化器（C99；C++20 才部分支持）；
- `restrict` 限定符；
- 隐式函数声明（旧标准）；
- `_Generic`、`_Atomic`（C11）。

## 三、name mangling 与 extern "C"

### 1. 符号名差异

```cpp
void func(int);       // C++ 符号类似 _Z4funci
extern "C" void cfunc(int);  // 符号就是 cfunc
```

- C++ 把命名空间、类、参数类型编码进符号名，以支持重载；
- C 不做修饰，函数名就是符号名；
- 因此 C++ 调用 C 函数、C 调用 C++ 函数，默认符号对不上。

### 2. extern "C" 的作用

`extern "C"` 是**语言链接规范**，只影响：

- 符号名（关闭 C++ mangling）；
- 调用约定/ABI（按 C 规则）。

它**不改变**函数参数类型、默认参数、函数体语法。例如：

```cpp
extern "C" void f(std::string s);   // 可以编译；C 代码无法调用
extern "C" void g(int x = 1);       // 默认参数是 C++ 特性，C 调用必须传参
```

所以"extern "C" 禁止使用 C++ 类型/默认参数"是错误说法。正确说法是：**C 调用方只能使用 C 兼容的签名**。

### 3. 标准混编头文件模板

```c
#ifndef MYLIB_H
#define MYLIB_H

#ifdef __cplusplus
extern "C" {
#endif

void mylib_init(void);
int  mylib_process(const char* input);

#ifdef __cplusplus
}
#endif

#endif
```

- C++ 编译器看到 `extern "C"`，按 C 链接规则生成/查找符号；
- C 编译器忽略 `__cplusplus` 块，按普通 C 声明处理。

### 4. extern "C" 的限制

- 不能用于重载函数（链接名相同，无法区分）；
- 不能修饰类成员函数（成员函数有 C++ 链接）；
- 变量也可以加 `extern "C"`（影响符号名）；
- 函数指针类型也可以指定 C 链接。

## 四、混编的构建方式

```bash
# C 源文件用 gcc 编译
gcc -c c_part.c -o c_part.o

# C++ 源文件用 g++ 编译
g++ -c cpp_part.cpp -o cpp_part.o

# 最终用 g++ 链接，确保链接 C++ 运行库
g++ c_part.o cpp_part.o -o app
```

- 用 `gcc` 链接 C++ 目标文件会缺少 `libstdc++` 等依赖；
- 反过来用 `g++` 链接纯 C 目标文件通常没问题；
- 混编库的 ABI 要一致（编译器版本、C++ 标准库、`_GLIBCXX_USE_CXX11_ABI`）。

## 五、高频混编问题

### 1. undefined reference to `foo()`

C++ 按 `_Z3foov` 查找，C 库只导出 `foo`。修复：头文件加 `extern "C"`。

### 2. C 调用 C++ 类/模板/重载失败

这些特性没有稳定的 C 符号。修复：提供 C 风格的包装函数，内部再调用 C++ 实现。

### 3. 跨语言传递 C++ 对象

`std::string`、`std::vector`、异常不能跨 C ABI 安全传递。修复：用 C 兼容类型（`const char*`、指针 + 长度、输出缓冲区）在边界转换。

### 4. ABI 不匹配

C++ 标准库/编译器版本不同、`_GLIBCXX_USE_CXX11_ABI` 不同，会导致符号找不到或崩溃。混编双方必须使用兼容的工具链和编译选项。

### 5. C 头文件缺少 `extern "C"` 保护

C++ 包含 C 头文件时，声明被按 C++ 规则修饰，链接失败。修复：C 头文件统一加 `__cplusplus` 条件块。

## 六、面试简答

### 1. C++ 是 C 的超集吗？

不是严格超集。大量 C 代码可以编译为 C++，但 `void*` 隐式转换、隐式函数声明、VLA、复合字面量、`restrict` 等在 C++ 中不合法或语义不同；C++ 还有引用、重载、模板等 C 没有的特性。

### 2. extern "C" 的作用是什么？

告诉 C++ 编译器按 C 的语言链接规则处理声明：关闭 name mangling，使用 C 符号名和调用约定。它只影响链接，不改变参数类型或函数体。

### 3. 为什么 C++ 调用 C 函数会 undefined reference？

C++ 默认对函数名做 mangling（如 `foo` → `_Z3foov`），而 C 库导出的是裸名 `foo`。链接器按 mangled 名找不到定义。用 `extern "C"` 声明即可。

### 4. C 能直接调用 C++ 的类和模板吗？

不能。类和模板没有稳定的 C ABI/符号。需要在 C++ 侧提供 `extern "C"` 的包装函数，用 C 兼容类型传参，内部再使用 C++ 特性。

## 七、极简口诀

**C++ 不是 C 超集，类型链接都有差异；**

**C 符号裸名走，C++ 名字被修饰；**

**混编头加 extern "C"，边界只传 C 类型；**

**C 用 gcc、C++ 用 g++，链接统一 g++。**
