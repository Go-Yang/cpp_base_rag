# 未定义弱符号、强符号机制

## 一、前言

链接器解析同名符号时，并不是简单地"有两个就报错"。ELF 把符号分成**强符号（STB_GLOBAL）**和**弱符号（STB_WEAK）**，解析规则因此有了优先级。

核心总纲：**强定义压弱定义，多强必报错，多弱选其一，未定义弱引用解析为 0。** 弱符号是"可选依赖"的底层实现机制。

## 二、强符号与弱符号的定义

### 1. 什么产生强符号

- 普通的全局函数定义；
- 普通的全局变量定义；
- 非 static、非 inline 的全局实体。

```c
int g_count = 0;          // 强符号
void foo(void) { }        // 强符号
```

### 2. 什么产生弱符号

- 显式标注 `__attribute__((weak))` 的函数/变量；
- C++ 模板的隐式实例化、inline 函数的 out-of-line 副本（COMDAT 弱符号）；
- 编译器/链接器内部生成的弱符号，如 `__gmon_start__`。

```c
__attribute__((weak)) int g_default = 0;
__attribute__((weak)) void on_event(int code) { /* 默认实现 */ }
```

### 3. 弱引用

只声明、不定义，允许链接时不存在：

```c
extern void optional_hook(void) __attribute__((weak));
// 或
extern void optional_hook(void) __attribute__((weakref("optional_hook")));
```

## 三、符号解析规则

| 场景 | 结果 |
|---|---|
| 一个强定义 + 多个弱定义 | 选强定义，弱定义被忽略 |
| 多个强定义 | `multiple definition` 报错 |
| 多个弱定义 | 任选一个（通常先遇到的），不报错 |
| 只有定义（强/弱），无引用 | 正常链接 |
| 强引用 + 无定义 | `undefined reference` |
| 弱引用 + 无定义 | 解析为地址 0，不报错 |
| 弱引用 + 有定义 | 正常解析到定义 |

关键区别：**弱引用允许符号不存在**，这是它和普通（强）引用的本质差异。

## 四、弱符号的典型用途

### 1. 库提供可覆盖的默认实现

库提供弱默认函数，应用程序提供同名强函数即可覆盖：

```c
// library.c
__attribute__((weak)) int platform_init(void) {
    return 0;              // 默认空实现
}

int app_start(void) {
    return platform_init(); // 链接时优先绑定强符号
}

// app.c
int platform_init(void) {
    return 42;              // 强符号，覆盖库里的弱实现
}
```

### 2. 可选钩子/回调

```c
// library.c
extern void on_packet(void) __attribute__((weak));

void handle_packet(void) {
    if (on_packet) {        // 必须先判空
        on_packet();
    }
}
```

### 3. 特性探测（运行时判断库版本/能力）

```c
extern int new_api_supported(void) __attribute__((weak));

if (new_api_supported && new_api_supported()) {
    // 使用新接口
} else {
    // 回退到旧接口
}
```

glibc 内部大量使用这种模式（如 `__gmon_start__`）。

### 4. 替换/拦截默认行为

`LD_PRELOAD` 加载的库提供同名符号，会覆盖后面加载的库中的定义，这是符号 interposition 的基础（详见《全局符号冲突底层成因》）。

## 五、必须注意的坑

### 1. 未定义弱函数不能直接调用

```c
extern void maybe(void) __attribute__((weak));

maybe();        // 错误：符号不存在时地址为 0，直接调用会段错误

if (maybe) {    // 正确：先判空
    maybe();
}
```

### 2. 弱引用不会抽取静态库成员

如果只存在**弱引用**，链接器不会为了满足它去抽取静态库成员。只有当其他强引用需要该成员时，它才会被拉进来。结果可能是：你以为链接了默认实现，实际 `weak` 地址为 0。

### 3. 弱定义不是"保证存在"

弱定义会被强定义覆盖；多个弱定义选谁都可能。不要依赖"我定义了一份弱符号，所以一定有"。

### 4. 编译器优化与判空

对弱函数取地址后判空是标准做法，但要注意：

- 若同一编译单元内已有强定义，符号必然存在，判空可能被优化掉；
- 不同编译/链接选项下地址可能延迟绑定，判空要在调用前做，而不是缓存一个可能为 0 的函数指针后再延迟调用。

### 5. C++ 中的限制

`__attribute__((weak))` 是编译器扩展，不是标准 C++。它可以用于函数和变量，但跨平台可移植性差（MSVC 用 `__declspec(selectany)` 等不同机制）。工程上更推荐显式的注册/工厂模式。

## 六、查看与排查

### 1. nm 中的符号类型

| 字母 | 含义 |
|---|---|
| `W` / `w` | 弱定义（函数/对象） |
| `V` / `v` | 弱对象（weak object） |
| `U` | 未定义引用 |
| `T` / `D` / `B` / `R` | 强定义 |

```bash
nm -C libfoo.a | grep ' W \| w \| V \| v '
nm -C --defined-only *.o | grep ' W '
```

### 2. readelf 查看 binding

```bash
readelf -s libfoo.so | grep WEAK
readelf -s app | grep optional_hook
```

### 3. 确认弱引用是否被解析

```bash
gcc main.o -lfoo -Wl,--trace-symbol=optional_hook -o app
objdump -d app | grep optional_hook
```

### 4. 运行时确认

```bash
gdb ./app
(gdb) p optional_hook
$1 = (void (*)(void)) 0x0
```

## 七、工程建议

1. 用弱符号实现"可选钩子"可以，但必须判空；更推荐显式注册回调，行为可预测。
2. 不要把弱符号当作跨平台机制，MSVC/Clang 的行为和写法不同。
3. 库的默认实现用弱符号时，要在文档里写清楚"应用可覆盖"。
4. 排查"符号有时存在有时不存在"时，先看 `nm` 的 `W/w` 和 `U`，再看链接顺序和是否链接了静态库。
5. 安全关键代码避免依赖弱符号的隐式行为，显式配置更可靠。

## 八、面试标准简答

### 1. 强符号和弱符号的解析规则？

多个强定义报错；强定义优先于弱定义；多个弱定义任选其一；强引用无定义报 undefined reference；弱引用无定义解析为 0；弱引用有定义则正常绑定。

### 2. 弱符号有什么用？

实现可覆盖的默认实现、可选钩子、运行时特性探测和符号拦截。glibc、插件系统、兼容层都大量使用。

### 3. 未定义弱符号为什么能链接通过？

链接器允许弱引用悬空，把它解析为地址 0。代价是运行时必须判空，否则调用空地址会崩溃。

### 4. 弱符号和静态库一起用有什么坑？

未定义的弱引用不会触发静态库成员抽取。如果库里只有弱定义、程序只有弱引用，该成员可能根本不会被链接进来。

**静态库不被弱引用拉，nm 看 W 和 U。**
