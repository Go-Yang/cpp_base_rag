# 全局符号冲突底层成因

## 一、前言

符号冲突有两种表现，性质完全不同：

- **静态链接期**：多个强符号同名 → `multiple definition`，直接报错；
- **动态链接期**：多个库导出同名符号 → 不报错，但运行时可能调用了"错误的那一个"，行为诡异。

核心总纲：**静态冲突是"链接器选不出来"，动态冲突是"链接器替你选了"。** 后者更危险，因为没有报错。

## 二、静态链接下的符号冲突

### 1. 强符号同名

两个 `.o` 或静态库导出同一个强符号，链接器只能报 `multiple definition`。详见《multiple definition 多重定义根治方案》。

### 2. 静态库与对象文件重复

同一份代码既被编译成 `.o` 直接链接，又被打进 `.a` 被抽取，符号会重复。

### 3. 多个静态库包含同一份第三方源码

例如两个组件都内嵌了同一个 `json.cpp`，链接时同名符号冲突。修复：抽成公共库，或给符号加前缀/内部链接。

## 三、动态链接下的符号冲突

### 1. 全局符号命名空间

动态链接器把所有参与加载的共享对象放在一个**全局符号作用域**里，同名符号只保留一个绑定。查找顺序大致是：

1. 可执行文件自身；
2. 按 `DT_NEEDED` 顺序的依赖库；
3. 依赖的依赖（广度优先）。

**第一个找到的定义胜出**，后面的同名定义不会报错，只会被忽略。

### 2. 符号 interposition（符号介入）

上面的规则意味着：一个库内部调用 `bar()`，实际绑定的可能不是自己依赖的 `bar`，而是更早加载的另一个库提供的 `bar`。这就是符号介入。

经典例子：

- `LD_PRELOAD` 预加载的库可以替换 `malloc`、`open`、`gettimeofday`；
- 两个库都实现了 `log()`，先加载的那个生效；
- 同一个库被加载两个版本，先加载的版本生效，后加载版本的符号被忽略。

### 3. GOT 与绑定时机

- 默认惰性绑定：第一次调用时解析，之后固定；
- `-Wl,-z,now` 启动时全部绑定；
- `LD_BIND_NOW=1` 强制立即绑定；
- 绑定结果取决于**解析时的全局作用域**，不是库自己的视角。

### 4. -Bsymbolic

共享库内部对自己定义的符号发起引用时，默认也可能被外部 interpose。用 `-Bsymbolic`（或 `-Bsymbolic-functions` 只对函数）可以让库内引用优先绑定到自己的定义：

```bash
gcc -fPIC -shared -Wl,-Bsymbolic -o libfoo.so foo.c
```

代价：破坏 interposition 能力，也可能导致跨库的单例/类型信息出现两份（C++ 的 RTTI、异常、单例尤其危险）。非必要不要开。

### 5. 符号可见性

隐藏不需要导出的符号，是避免冲突最根本的手段：

```bash
gcc -fPIC -fvisibility=hidden -shared -o libfoo.so foo.c
```

```c
__attribute__((visibility("default")))
int foo_api(void);       // 只导出明确标记的接口
```

也可以用 version script 精确控制导出名单：

```text
{
    global:
        foo_api;
        bar_api;
    local:
        *;
};
```

```bash
gcc -shared -Wl,--version-script=foo.map -o libfoo.so foo.o
```

### 6. dlopen 的作用域

```c
dlopen("libplugin.so", RTLD_NOW | RTLD_LOCAL);   // 默认：符号不进入全局作用域
dlopen("libplugin.so", RTLD_NOW | RTLD_GLOBAL);  // 符号加入全局，可能与已有符号冲突
```

- `RTLD_LOCAL`：插件符号自成一域，适合多插件隔离；
- `RTLD_GLOBAL`：后续加载的库可以解析到它，容易引发冲突；
- `RTLD_DEEPBIND`：优先在自身依赖里查找，自成一个作用域（glibc 扩展，慎用）。

## 四、C++ 特有的冲突

### 1. ODR 违规

同一个类/模板/内联函数在两个共享库里定义不一致（字段不同、实现不同），链接器不会报错，但：

- 对象大小不一致 → 内存越界；
- 虚表布局不一致 → 调用错函数；
- `typeid`/`dynamic_cast` 失效；
- 单例出现两份。

### 2. RTTI 与 type_info 符号

跨库使用多态时，`type_info` 符号必须全程序唯一。使用 `-fvisibility=hidden` 或不同 ABI 编译的库，可能出现 `type_info` 无法匹配，`dynamic_cast` 返回空。

### 3. 标准库/第三方库多版本共存

同一个库的两个版本被不同依赖加载（SONAME 不同），两套全局对象、两套分配器并存，容易出现"释放了另一个堆的对象"这类崩溃。

## 五、排查流程

### Step 1：确认符号在哪些库中导出

```bash
nm -D --defined-only libfoo.so | grep ' foo$'
nm -D --defined-only libbar.so | grep ' foo$'
objdump -T libfoo.so | grep foo
```

### Step 2：看运行时实际绑定到谁

```bash
LD_DEBUG=symbols,bindings ./app 2>&1 | grep -A3 'symbol=foo'
```

### Step 3：用 dladdr 反查符号归属

```c
#include <dlfcn.h>

Dl_info info;
if (dladdr((void*)foo, &info)) {
    printf("foo 来自 %s\n", info.dli_fname);
}
```

### Step 4：检查加载了哪些库及顺序

```bash
ldd ./app
LD_DEBUG=libs ./app 2>&1 | grep 'calling init'
```

### Step 5：检查导出控制

```bash
readelf --dyn-syms libfoo.so | grep foo
readelf -V libfoo.so | head -40      # 符号版本
nm -C --defined-only libfoo.a | grep foo
```

## 六、解决方案速查

| 场景 | 方案 |
|---|---|
| 静态库同名符号 | 加前缀、内部链接、合并公共库、`objcopy --prefix-symbols` |
| 动态库无意 interpose | `-fvisibility=hidden` + 显式导出；version script |
| 库内引用被外部覆盖 | `-Bsymbolic-functions`（注意副作用） |
| 插件互相干扰 | `dlopen(..., RTLD_LOCAL)`；避免 `RTLD_GLOBAL` |
| 同库多版本共存 | 提升 SONAME、隔离进程、统一依赖树 |
| C++ ODR 冲突 | 统一编译选项/ABI；隐藏内部类型；C 接口做边界 |
| 需要主动拦截 | `LD_PRELOAD`（只在受控场景） |

## 七、预防规范

1. 共享库默认 `-fvisibility=hidden`，只导出明确的 API。
2. 用 version script 管理导出符号，避免内部符号泄漏。
3. C 接口统一加库前缀，不要用 `init`、`log`、`open` 这类通用名。
4. 插件加载默认 `RTLD_LOCAL`，不要随手 `RTLD_GLOBAL`。
5. 跨库传递 C++ 对象时保证 ABI 与编译选项一致，最好用 C 接口隔离。
6. 不要在同一进程里加载同一库的多个不兼容版本。
7. 慎用 `-Bsymbolic`，使用前评估单例、RTTI 和 interposition 的影响。

## 八、面试标准简答

### 1. 动态链接时同名符号怎么解析？

动态链接器维护全局符号作用域，按"可执行文件 → DT_NEEDED 顺序 → 间接依赖"的顺序查找，第一个找到的定义胜出，后面的同名定义被忽略。所以不会报 multiple definition，而是可能悄悄绑错。

### 2. 什么是符号 interposition？

一个库对某符号的引用，在运行时被解析到另一个更早加载的库中的同名定义。`LD_PRELOAD` 拦截 `malloc` 就是典型应用；无意发生的 interposition 会导致调用到错误实现。

### 3. -Bsymbolic 有什么用？有什么风险？

让共享库内部的引用优先绑定到本库定义，避免被外部同名符号覆盖。风险是破坏 interposition，可能导致全局单例/类型信息出现多份，C++ 场景尤其危险。

### 4. 如何避免全局符号冲突？

隐藏内部符号（`-fvisibility=hidden`）、显式导出 API、加前缀/命名空间、使用 version script、插件用 `RTLD_LOCAL`、避免同库多版本共存。核心原则是：**只导出必须导出的符号。**

## 九、极简口诀

**全局作用域先到先得，同名符号后面的让；**

**隐藏符号加前缀，version script 控导出；**

**LD_DEBUG 查绑定，dladdr 认归属。**
