# 链接脚本基础原理与段分配

## 一、前言

链接脚本（linker script）告诉链接器：

- 输入的目标文件里有哪些 section；
- 把它们合并成哪些输出 section；
- 每个输出 section 放到哪个地址/内存区域；
- 定义哪些符号（如 `_start`、`__bss_start`）。

桌面/服务器开发通常用默认脚本，几乎不碰它；嵌入式、内核、Bootloader、自定义内存布局则必须手写。

核心总纲：**链接脚本就是一张"内存地图"：谁放到哪、按什么顺序、地址是多少。** 排查"段溢出、地址错误、启动即崩"时，先看这张图。

## 二、默认链接脚本

链接器自带一份默认脚本，可以直接查看：

```bash
ld --verbose | head -80          # GNU ld 默认脚本
gcc -Wl,--verbose -o app main.o 2>&1 | head -80
```

默认脚本决定了普通 Linux 程序里 `.text`、`.rodata`、`.data`、`.bss` 的排列和地址。大多数应用不需要替换它。

指定自定义脚本：

```bash
gcc main.o -T my.ld -o app
# 或
ld -T my.ld -o app main.o
```

## 三、链接脚本核心语法

### 1. MEMORY：声明内存区域

```ld
MEMORY
{
    FLASH (rx)  : ORIGIN = 0x08000000, LENGTH = 512K
    RAM   (rwx) : ORIGIN = 0x20000000, LENGTH = 128K
}
```

- `r` 读、`w` 写、`x` 执行；
- 区域名在 `SECTIONS` 里用 `> 区域名` 引用；
- 放不下时链接器报 `region 'FLASH' overflowed by N bytes`。

### 2. SECTIONS：描述段布局

```ld
SECTIONS
{
    .text : {
        *(.text*)
        *(.rodata*)
    } > FLASH

    .data : {
        *(.data*)
    } > RAM AT> FLASH

    .bss (NOLOAD) : {
        *(.bss*)
        *(COMMON)
    } > RAM

    _end = .;
}
```

关键点：

- `*(.text*)`：把所有输入文件的 `.text` 及 `.text.*` 合并；
- `> FLASH`：运行地址（VMA）在 FLASH；
- `AT> FLASH`：加载地址（LMA）在 FLASH，常用于 `.data` 的初值存放；
- `(NOLOAD)`：`.bss` 不占文件空间，加载时不需要从文件读；
- `.`：位置计数器，表示当前地址；`_end = .` 定义一个符号。

### 3. VMA 与 LMA

这是嵌入式最容易混的两个概念：

- **VMA（Virtual/Link Address）**：变量运行时所在地址（RAM）；
- **LMA（Load Address）**：镜像里初值存放的地址（FLASH）。

`.data` 的初值在 FLASH（LMA），运行时必须搬到 RAM（VMA）。启动代码负责：

1. 把 `.data` 从 FLASH 复制到 RAM；
2. 把 `.bss` 清零；
3. 设置栈指针，跳 `main`。

如果启动代码没做这两步，全局变量会是乱值，程序表现为"进 main 就崩"。

### 4. KEEP：防止被裁剪

开启 `--gc-sections` 后，没人引用的 section 会被删除。注册表、中断向量表、init 段等需要保留：

```ld
.init_array : {
    KEEP(*(.init_array))
    KEEP(*(SORT(.init_array.*)))
} > FLASH
```

### 5. ALIGN 与对齐

```ld
.data : ALIGN(16) { ... } > RAM
```

`.text` 尾部与 `.data` 起始通常需要按页/缓存行对齐；`ALIGN(4)` 是 ARM 常见要求。

### 6. PROVIDE、ENTRY、ASSERT

```ld
ENTRY(_start)                       // 指定入口符号

PROVIDE(__stack_top = ORIGIN(RAM) + LENGTH(RAM));
PROVIDE(__heap_start = _end);       // 仅当被引用且未定义时才定义

ASSERT(_end <= ORIGIN(RAM) + LENGTH(RAM), "RAM overflow")
```

### 7. 自定义 section

```c
__attribute__((section(".initcall")))
static void my_init(void) { /* ... */ }
```

```ld
.initcall : {
    __initcall_start = .;
    KEEP(*(.initcall))
    __initcall_end = .;
} > FLASH
```

启动代码遍历 `__initcall_start` 到 `__initcall_end` 逐个调用，实现注册机制。Linux 内核的 `initcall`、很多嵌入式框架都用这个套路。

C 标准还提供 `__start_<section>` / `__stop_<section>` 符号（section 名必须是合法 C 标识符）：

```c
extern char __start_mysec[], __stop_mysec[];   // section 名为 "mysec"
```

## 四、链接脚本常见报错

### 1. region overflowed

```text
region `RAM' overflowed by 4096 bytes
```

段总大小超过 MEMORY 声明的 LENGTH。检查全局数组、栈/堆预留、对齐填充是否过大。

### 2. section overlaps

两个输出段地址区间重叠。通常是 `ORIGIN`/`LENGTH` 写错，或没给 `.bss`、堆栈留空间。

### 3. undefined reference to `_start`

入口符号没定义。检查 `ENTRY`、启动文件（`startup.s`）是否参与链接，以及 C 符号名是否带下划线。

### 4. cannot find linker script / unrecognized option

`-T` 路径不对，或把脚本传给了编译器而非链接器。用 `-Wl,-T,my.ld` 或直接调用 `ld`。

### 5. orphan section 警告

```text
warning: orphan section `.foo' from `a.o' placed in `.text'
```

输入段没有被脚本显式接住，链接器按启发式规则放置。可能造成地址/权限不符合预期。显式加规则或检查段名拼写。

### 6. .data 初值丢失

VMA/LMA 配置或启动复制代码有误。用 `readelf -l` 看 LOAD 段地址，用调试器确认 `.data` 初值是否被搬到 RAM。

## 五、排查命令

| 目的 | 命令 |
|---|---|
| 查看默认脚本 | `ld --verbose` |
| 查看段布局 | `readelf -S app` |
| 查看段地址/大小 | `objdump -h app` |
| 查看程序头/加载地址 | `readelf -l app` |
| 生成链接 map | `-Wl,-Map=link.map` |
| 查看符号地址 | `nm -n app` |
| 查看反汇编地址 | `objdump -d app` |

`-Wl,-Map=link.map` 会详细列出每个输入段被放到哪个输出段、地址是多少，是排查段布局的第一工具。

## 六、工程建议

1. 桌面/服务器程序优先用默认脚本，只在确有需要时替换。
2. 嵌入式项目把内存布局写成显式 `MEMORY`，并加 `ASSERT` 做编译期容量校验。
3. 启动代码与链接脚本必须成对维护：`.data` 复制、`.bss` 清零、栈顶符号要一致。
4. 开启 `--gc-sections` 时，注册表/向量表用 `KEEP` 保护。
5. 自定义段名和符号名写进文档，避免"段悄悄被 gc 掉"。
6. 升级工具链后重新检查默认脚本行为，尤其是 `COMMON` 和 orphan section 规则。

## 七、面试标准简答

### 1. VMA 和 LMA 的区别？

VMA 是变量运行时所在地址，LMA 是镜像中初值的加载地址。嵌入式里 `.data` 的 VMA 在 RAM、LMA 在 FLASH，启动代码必须把初值从 FLASH 复制到 RAM；`.bss` 不占镜像，启动时清零。

### 2. 链接脚本的作用是什么？

控制输入段如何合并成输出段、每个输出段放在哪个内存区域、地址是多少，并定义入口和边界符号。它决定程序的内存布局，是嵌入式启动能否正常工作的基础。

### 3. KEEP 有什么用？

开启 `--gc-sections` 后，没有引用的段会被回收。`KEEP` 强制保留指定段，常用于中断向量表、initcall 注册表和构造函数表。

### 4. 如何在 C 里使用自定义段？

用 `__attribute__((section("name")))` 把变量/函数放进指定段，在链接脚本里接住该段并定义起止符号；或用 `__start_name` / `__stop_name` 自动符号遍历。常用于注册表和初始化函数表。

**gc-sections 会误删，注册表加 KEEP；**

**段溢出查 map，地址不对看 readelf -l。**
