# 符号解析与重定位完整机制

## 一、前言

链接器的工作可以概括为两件事：

1. **符号解析**：把每个目标文件里的"未定义符号"和某个"已定义符号"对应起来；
2. **重定位**：确定每个 section 和符号的最终地址，把指令/数据里预留的占位值改写为真实地址。

核心总纲：**符号解析决定"用谁的"，重定位决定"填什么地址"。** 前者出错是 undefined reference / multiple definition，后者出错是 relocation error。

## 二、ELF 中与链接相关的结构

### 1. section

| section | 内容 |
|---|---|
| `.text` | 可执行指令 |
| `.rodata` | 只读常量、字符串 |
| `.data` | 已初始化全局/静态变量 |
| `.bss` | 未初始化全局/静态变量（不占文件空间） |
| `.symtab` | 完整符号表（链接/调试用，可被 strip） |
| `.dynsym` | 动态符号表（运行时用，不可 strip） |
| `.rela.text` | 代码段重定位项 |
| `.rela.dyn` | 动态重定位项 |
| `.got` / `.got.plt` | 全局偏移表 |
| `.plt` | 过程链接表 |

### 2. 符号表条目

每个符号包含：

- **name**：符号名（C++ 为 mangled 名）；
- **value**：地址或偏移；
- **size**：大小；
- **binding**：`LOCAL`（文件内）、`GLOBAL`（强符号）、`WEAK`（弱符号）；
- **type**：`FUNC`、`OBJECT`、`NOTYPE`、`SECTION`、`FILE`；
- **visibility**：`DEFAULT`、`HIDDEN`、`PROTECTED`、`INTERNAL`；
- **section index**：`SHN_UNDEF` 表示未定义，`SHN_ABS` 表示绝对值，`SHN_COMMON` 表示公共符号。

## 三、符号解析

### 1. 规则

链接器按以下优先级解析同名符号：

1. 一个强定义 + 多个弱定义 → 选强定义；
2. 多个强定义 → `multiple definition` 报错；
3. 多个弱定义 → 任选一个（通常是先遇到的），不报错；
4. 只有未定义引用，没有定义 → `undefined reference`；
5. 未定义的**弱引用** → 解析为地址 0，不报错（调用前必须判空）。

### 2. 静态库成员的抽取

静态库不是"整包参与链接"，而是按需抽取：

- 链接器维护未定义符号集合；
- 只有当某个成员能定义集合中的符号时，才抽取该成员；
- 抽取后加入该成员的新未定义符号，继续扫描；
- **扫描过的归档不会回头重扫**，这就是静态库顺序问题的根源。

### 3. C 与 C++ 的差异

- C：符号名就是函数名，`int foo(int)` 的符号是 `foo`；
- C++：经过 name mangling，`int foo(int)` 的符号是 `_Z3fooi`，命名空间、类、参数类型都会进入符号名；
- 因此 C++ 调用 C 函数必须用 `extern "C"`，否则按 mangled 名查找必然失败。

## 四、重定位

### 1. 为什么需要重定位

编译单个 `.c` 时，编译器不知道：

- 外部函数/变量最终在哪个地址；
- 本文件的代码会被放到可执行文件的哪个位置；
- 引用的全局变量相对于当前指令有多远。

所以编译器先填 0 或占位值，并生成一条重定位记录："这里有一个引用，类型是 X，指向符号 Y，链接时请把地址填进来。"

### 2. 重定位的执行时机

- **静态链接**：链接器在生成可执行文件时完成所有重定位，地址固定；
- **动态链接**：链接期只处理一部分，外部符号留到加载期由动态链接器处理（GOT/PLT）。

### 3. 常见 x86-64 重定位类型

| 类型 | 含义 | 典型场景 |
|---|---|---|
| `R_X86_64_64` | 填 64 位绝对地址 | 指针常量、数据段引用 |
| `R_X86_64_32` / `32S` | 填 32 位绝对地址 | 小代码模型、非 PIC |
| `R_X86_64_PC32` | 填相对当前指令的 32 位偏移 | 同模块函数/变量调用 |
| `R_X86_64_PLT32` | 指向 PLT 项的 PC 相对偏移 | 外部函数调用 |
| `R_X86_64_GOTPCREL` | 指向 GOT 项的 PC 相对偏移 | PIC 下访问外部变量 |
| `R_X86_64_GLOB_DAT` | 动态符号的绝对地址 | 动态库数据符号 |
| `R_X86_64_JUMP_SLOT` | 动态函数地址 | PLT 惰性绑定 |
| `R_X86_64_RELATIVE` | 基址 + 加数 | PIE / 共享库内部指针 |
| `R_X86_64_COPY` | 从共享库复制数据到可执行文件 | 可执行文件引用共享库全局变量 |

### 4. 典型重定位报错

#### relocation truncated to fit: R_X86_64_PC32

PC 相对寻址只有 32 位，符号距离超过 ±2GB 时溢出。常见于超大程序、`-mcmodel=large` 配置错误、把代码/数据放到相隔很远的自定义段。

#### relocation R_X86_64_32 against ... can not be used when making a shared object

共享库必须用 PIC 编译。某个 `.o` 没加 `-fPIC`，里面含绝对地址重定位，链接器拒绝生成 `.so`。修复：所有参与共享库的源文件和静态库都用 `-fPIC` 重新编译。

#### text relocations

共享库的代码段出现需要运行时修改的重定位，破坏只读共享。用 `-fPIC` 重新编译，或用 `readelf -d` 检查是否有 `TEXTREL`。

## 五、GOT 与 PLT

### 1. 为什么需要它们

PIC 代码不能写死外部符号地址。解决方式是：

- 在数据段建一张 **GOT（Global Offset Table）**，存放外部符号的真实地址；
- 代码通过 GOT 间接访问；
- 函数调用先跳到 **PLT（Procedure Linkage Table）** 中的小跳板，由跳板读 GOT 并跳转。

### 2. 惰性绑定流程

1. 第一次调用 `foo` → 跳到 `foo@plt`；
2. PLT 项跳转到 GOT 中预置的解析器入口；
3. 动态链接器解析 `foo` 的真实地址，写回 GOT；
4. 再次调用直接经 GOT 跳转，不再解析。

```bash
readelf -r app | grep JUMP_SLOT     # 查看需要惰性绑定的函数
objdump -d -j .plt app              # 查看 PLT 内容
```

关闭惰性绑定、启动时全部解析：

```bash
-Wl,-z,now        # 立即绑定
-Wl,-z,relro      # GOT 只读化，配合 now 使用
```

## 六、排查命令

| 目的 | 命令 |
|---|---|
| 查看符号表 | `readelf -s a.o` |
| 查看动态符号 | `readelf --dyn-syms libfoo.so` |
| 查看重定位项 | `readelf -r a.o` |
| 反汇编并显示重定位 | `objdump -dr a.o` |
| 查看未定义符号 | `nm -u -C a.o` |
| 查看归档成员与符号 | `nm -C libfoo.a` |
| 查看节区布局 | `readelf -S app` |
| 查看程序头 | `readelf -l app` |

## 七、常见问题定位表

| 现象 | 可能原因 | 排查 |
|---|---|---|
| `undefined reference` | 符号没有定义 / 库没链接 / 顺序错误 | `nm -u`、`nm -C lib`、检查链接命令 |
| `multiple definition` | 同一强符号多处定义 | `nm --defined-only`、map 文件 |
| `relocation truncated to fit` | PC 相对偏移溢出 | 检查代码模型、段布局、大对象 |
| `can not be used when making a shared object` | 未使用 `-fPIC` | 全量重编 `-fPIC` |
| `symbol lookup error`（运行期） | 动态符号未解析、版本不匹配 | `LD_DEBUG=symbols`、`ldd -r` |

## 八、面试标准简答

### 1. 符号解析和重定位分别是什么？

符号解析是把未定义符号与某个定义绑定；重定位是在确定各 section 最终地址后，把指令/数据中的占位值改写为符号的真实地址。前者解决"用谁"，后者解决"填哪"。

### 2. 什么是 GOT 和 PLT？

GOT 是存放外部符号地址的表，PLT 是函数调用的跳板。PIC 代码通过 PLT/GOT 间接调用外部函数，实现加载地址无关和惰性绑定。

### 3. 为什么共享库必须用 -fPIC？

共享库加载地址不确定，且要被多个进程映射到不同地址。非 PIC 代码包含绝对地址重定位，无法在加载时安全修正，链接器会拒绝生成共享库或产生文本重定位。

### 4. relocation truncated to fit 怎么解决？

通常是寻址范围溢出：PC 相对重定位只能覆盖 ±2GB。检查是否把代码/数据放到了过远的自定义段、是否该用 `-mcmodel=medium/large`、是否生成了超大目标文件。

## 九、极简口诀

**符号解析定归属，强胜弱、多重报错；**

**重定位填真地址，PC 相对怕超 2G；**

**共享库要 PIC，GOT 存址 PLT 跳；**

**readelf -r 看重定位，nm -u 查未定义。**
