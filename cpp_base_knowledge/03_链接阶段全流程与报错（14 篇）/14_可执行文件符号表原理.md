# 可执行文件符号表原理

## 一、前言

符号表是链接器、加载器、调试器、性能工具共用的"地址簿"。理解它，才能看懂 `nm`、`readelf -s`、`objdump -t` 的输出，也才能真正定位 `undefined reference`、`multiple definition`、`symbol lookup error`。

核心总纲：**符号表记录"名字 → 地址/大小/绑定/类型"的映射；静态符号表给链接和调试用，动态符号表给运行期加载用。**

## 二、ELF 中的两张符号表

### 1. `.symtab`：完整符号表

- 包含局部符号、全局符号、文件符号、section 符号；
- 链接器用它做符号解析；
- 调试器和性能工具用它做地址到函数名的映射；
- **可以被 `strip` 删除**，不影响程序运行。

### 2. `.dynsym`：动态符号表

- 只包含运行期需要的符号：导出的定义和需要导入的引用；
- 动态链接器用它解析符号；
- **不能被 strip 删除**，否则程序无法加载；
- 与 `.dynstr`（动态字符串表）配套。

```bash
readelf -s app           # 通常是 .symtab（如果没被 strip）
readelf --dyn-syms app   # 只看 .dynsym
nm -D app                # 动态符号
nm app                   # 静态符号表（若存在）
```

## 三、符号表条目结构

每个符号条目（`Elf64_Sym`）主要字段：

| 字段 | 含义 |
|---|---|
| `st_name` | 名字在字符串表中的偏移 |
| `st_value` | 符号地址或偏移；ET_DYN 中是相对基址的偏移 |
| `st_size` | 符号大小（函数字节数、对象大小） |
| `st_info` | 高 4 位 binding，低 4 位 type |
| `st_other` | 低 2 位 visibility |
| `st_shndx` | 所属 section 索引 |

### 1. binding（绑定）

| 值 | 含义 |
|---|---|
| `LOCAL` | 文件内可见（static、匿名命名空间） |
| `GLOBAL` | 全局强符号 |
| `WEAK` | 弱符号 |

### 2. type（类型）

| 值 | 含义 |
|---|---|
| `NOTYPE` | 未指定 |
| `OBJECT` | 变量/对象 |
| `FUNC` | 函数 |
| `SECTION` | section 符号 |
| `FILE` | 源文件名 |
| `COMMON` | 公共符号（tentative definition） |
| `TLS` | 线程局部存储变量 |

### 3. section index 特殊值

| 值 | 含义 |
|---|---|
| `SHN_UNDEF` | 未定义符号（需要别处提供） |
| `SHN_ABS` | 绝对值，不参与重定位 |
| `SHN_COMMON` | 公共符号，链接器分配 |
| `SHN_XINDEX` | 实际索引在扩展表中 |

## 四、nm 输出字母速查

| 字母 | 含义 |
|---|---|
| `T` / `t` | 代码段中的定义（大写全局，小写局部） |
| `D` / `d` | 已初始化数据段 |
| `B` / `b` | 未初始化数据段（.bss） |
| `R` / `r` | 只读数据段（.rodata） |
| `U` | 未定义引用 |
| `W` / `w` | 弱定义（未标记为弱对象的） |
| `V` / `v` | 弱对象 |
| `C` | 公共符号 |
| `A` | 绝对地址符号 |
| `N` | 调试符号 |
| `?` | 未知 |

```bash
nm -C app | head -20          # -C 还原 C++ 名字
nm -u -C app                  # 只看未定义
nm --defined-only -C libfoo.a # 只看定义
nm -A *.o | grep foo          # 显示符号来自哪个文件
```

## 五、符号表与链接过程

### 1. 链接器怎么用符号表

- 收集所有输入文件的定义符号，建立全局符号表；
- 检查未定义符号（`SHN_UNDEF`）是否能被解析；
- 强/弱符号按规则选择；
- 分配地址后，把 `st_value` 填成最终地址；
- 重定位项引用符号表索引，链接器据此改指令。

### 2. 静态库的符号索引

`.a` 归档里有一个特殊的符号索引成员（archive map），记录"哪个符号在哪个 `.o` 成员里"。链接器靠它快速判断该抽取哪个成员。

```bash
ar t libfoo.a          # 成员列表
ar s libfoo.a          # 重建符号索引（ranlib 的等价操作）
nm -s libfoo.a         # 显示归档符号索引
```

如果归档索引损坏，链接器可能找不到明明存在的符号。重新执行 `ranlib` 或重新打包。

### 3. 动态库的符号导出

动态库的 `.dynsym` 只包含**导出**的符号。`-fvisibility=hidden` 会隐藏未显式导出的符号：

```bash
objdump -T libfoo.so | grep foo     # 动态符号表
readelf --dyn-syms libfoo.so
```

符号不可见时，即使定义存在，外部也无法链接/解析。

## 六、符号版本

动态库还维护版本信息：

- `.gnu.version_d`：本库定义的符号版本；
- `.gnu.version_r`：依赖库需要的符号版本；
- `.gnu.version`：每个动态符号对应的版本索引。

```bash
readelf -V libfoo.so        # 版本定义和需求
objdump -T libfoo.so | grep GLIBC
nm -D --with-symbol-versions libfoo.so
```

这就是 `GLIBC_2.34 not found`、`GLIBCXX_3.4.29 not found` 的来源。

## 七、strip 与调试信息

### 1. strip 删了什么

```bash
strip app                    # 删除 .symtab 和调试信息，保留 .dynsym
strip --strip-debug app      # 只删调试信息，保留 .symtab
strip --strip-unneeded app   # 删除重定位不需要的符号
```

strip 后：

- `nm app` 显示 `no symbols`；
- 程序仍能正常运行（依赖 `.dynsym`）；
- 崩溃栈里的函数名可能丢失，除非有单独的调试文件。

### 2. 分离调试信息

```bash
objcopy --only-keep-debug app app.debug
objcopy --strip-debug app
objcopy --add-gnu-debuglink=app.debug app
```

- `app.debug` 保留完整调试信息；
- `app` 体积变小；
- gdb 通过 `.gnu_debuglink` 或 build-id 自动找到调试文件。

### 3. build-id

链接时生成唯一 build-id，gdb 可以按 `/usr/lib/debug/.build-id/xx/yyyy.debug` 查找调试文件：

```bash
readelf -n app | grep 'Build ID'
```

## 八、PIE、ASLR 与符号地址

现代 Linux 默认生成 PIE（`ET_DYN`）。符号表里的 `st_value` 是**相对基址的偏移**，运行时真实地址 = 加载基址 + `st_value`。

```bash
file app                         # 看是否 PIE
readelf -h app | grep Type       # DYN 表示 PIE/共享库
nm app | grep main               # 显示偏移
```

调试时 gdb 会自动处理基址；自己解析符号表时要先找到加载基址（`/proc/<pid>/maps`、`dl_iterate_phdr`、`dladdr`）。

## 九、常见问题

### 1. nm 显示 no symbols

二进制被 strip 了。`nm -D` 看动态符号，或用调试文件。

### 2. 程序能跑但看不到函数名

`.symtab` 被删，只有 `.dynsym`；导出符号可见，内部函数不可见。用 `-rdynamic` 可以把可执行文件的符号导出到动态符号表，便于 backtrace/插件解析：

```bash
gcc main.c -rdynamic -o app
# 等价于 -Wl,--export-dynamic
```

### 3. undefined reference 但库里明明有符号

- 符号是 `LOCAL`（static），不参与全局解析；
- 符号被 `-fvisibility=hidden` 隐藏；
- 符号版本不匹配；
- 静态库归档索引损坏；
- 签名不同导致 mangled 名不同。

### 4. 两个库符号同名

动态符号表运行时按全局作用域解析，先加载者胜出；静态链接则可能 multiple definition。详见《全局符号冲突底层成因》。

## 十一、面试标准简答

### 1. .symtab 和 .dynsym 的区别？

`.symtab` 是完整符号表，包含局部/全局/调试符号，供链接和调试使用，可被 strip 删除；`.dynsym` 是动态符号表，只包含运行期导入/导出的符号，动态链接器依赖它，不能被删除。

### 2. strip 会影响程序运行吗？

不会。strip 删除的是 `.symtab` 和调试信息，动态链接所需的 `.dynsym` 保留。但之后 `nm` 看不到内部符号，调试和崩溃分析会受影响，需要单独的调试文件。

### 3. nm 的 U、T、W 分别代表什么？

`U` 是未定义引用；`T` 是代码段的已定义符号；`W` 是弱定义（弱符号）。大小写表示全局/局部（如 `T` 全局，`t` 局部）。

### 4. 为什么程序里能看到符号却链接不到？

符号可能是 LOCAL（static）不参与全局解析、被 visibility 隐藏、版本不匹配，或者声明与定义的 mangled 名不同。用 `readelf -s` 看 binding 和 visibility，用 `objdump -T` 看动态导出。
