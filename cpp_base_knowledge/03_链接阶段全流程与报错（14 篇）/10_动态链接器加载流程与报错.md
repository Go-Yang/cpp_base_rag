# 动态链接器加载流程与报错

## 一、前言

程序从 `execve` 到 `main` 之间，还有一整套动态链接器的工作。很多"链接成功、运行失败"的问题都发生在这个阶段。

核心总纲：**内核只负责把可执行文件和解释器映射进来，真正的找库、找符号、重定位由 `ld.so` 完成。** 报错发生在 `ld.so`，所以要用 `ldd`、`readelf -d`、`LD_DEBUG` 排查，而不是重编译。

## 二、完整加载流程

### 1. 内核阶段

1. shell 调用 `execve("./app", ...)`；
2. 内核读取 ELF header，校验格式与架构；
3. 按程序头 `PT_LOAD` 把可执行文件的各段映射进虚拟地址空间；
4. 找到 `PT_INTERP`，把动态链接器（如 `/lib64/ld-linux-x86-64.so.2`）也映射进来；
5. 内核把控制权交给动态链接器的入口，并通过辅助向量（auxv）传递 `AT_PHDR`、`AT_ENTRY`、`AT_BASE` 等信息。

此时还没有执行 `main`，C++ 全局构造器也还没跑。

### 2. 动态链接器阶段

`ld.so` 接管后：

1. **自举**：完成自身重定位（它不能依赖别人）；
2. **读取可执行文件的 `.dynamic`**：拿到 `DT_NEEDED`、`DT_RPATH`/`DT_RUNPATH`、`DT_INIT_ARRAY` 等；
3. **加载依赖**：按搜索顺序找到并 `mmap` 每个共享库，递归处理它们的依赖，建立 `link_map` 链表；
4. **建立全局符号作用域**：可执行文件 → 直接依赖 → 间接依赖，广度优先；
5. **重定位**：处理 `GLOB_DAT`、`JUMP_SLOT`、`RELATIVE`、`COPY` 等；函数符号默认惰性绑定，第一次调用才解析；
6. **TLS 初始化**：为主线程和共享库分配线程局部存储；
7. **执行构造器**：按依赖顺序调用各库的 `DT_INIT_ARRAY`（依赖库先于使用者，无依赖关系的库顺序不保证）；
8. **跳转入口**：进入 `_start`，由 `__libc_start_main` 调用 `main`。

### 3. 惰性绑定 vs 立即绑定

- 默认：函数符号第一次调用时经 PLT 解析，之后 GOT 缓存地址；
- `-Wl,-z,now` 或环境变量 `LD_BIND_NOW=1`：启动时全部解析；
- 立即绑定更容易在启动阶段暴露缺失符号，配合 `-z relro` 可让 GOT 只读。

### 4. 初始化顺序

- 依赖库的构造器先于使用者执行；
- 同一层的多个库，执行顺序由 `ld.so` 的拓扑排序决定，不应依赖；
- C++ 的全局对象构造器也在 `DT_INIT_ARRAY` 里；
- 如果构造器里访问了尚未初始化的其他全局对象，会出现"静态初始化顺序问题"。

## 三、常见报错与根因

### 1. cannot open shared object file

```text
error while loading shared libraries: libfoo.so.1: cannot open shared object file
```

库不存在、路径不在搜索路径、SONAME 链接缺失、架构不匹配。详见《动态库.so/.dll 依赖缺失报错》。

### 2. symbol lookup error: undefined symbol

```text
./app: symbol lookup error: ./app: undefined symbol: _ZN3foo3barEv
```

这是**运行期**找不到符号，常见于：

- `dlopen` 加载的插件依赖了未加载的库；
- 库版本不匹配，符号在新/旧版本里改名或删除；
- C++ ABI 不一致（`_GLIBCXX_USE_CXX11_ABI`）；
- 符号被 version script 隐藏。

和链接期 `undefined reference` 的区别：后者是链接时找不到，前者是运行时加载后解析失败。

### 3. version `GLIBC_2.34' not found

```text
./app: /lib64/libc.so.6: version `GLIBC_2.34' not found
```

程序在高版本 glibc 系统上编译，拿到低版本系统运行。glibc 符号版本只增不减，低版本无法提供高版本符号。解决办法：在目标最低版本系统/容器里编译，或使用静态链接/兼容工具链。不要试图拷贝新版 `libc.so.6`，极易搞坏系统。

### 4. version `GLIBCXX_3.4.29' not found

libstdc++ 版本不足。可以：

- 在旧系统/旧 GCC 下编译；
- 随程序分发更新的 `libstdc++.so.6` 并设置 RUNPATH；
- `-static-libstdc++` 静态链接 C++ 运行库（glibc 仍动态）。

### 5. wrong ELF class / Exec format error

32 位程序配 64 位库（或反之），或脚本缺少 shebang、错误架构镜像。用 `file`、`readelf -h` 检查。

### 6. failed to map segment from shared object

- 文件无读权限；
- 所在文件系统挂载了 `noexec`；
- SELinux/AppArmor 拦截；
- 32 位地址空间不足。

### 7. cannot allocate memory in static TLS block

`dlopen` 的库使用了静态 TLS 模型，但启动后才加载，TLS 空间已经分配完。修复：启动时直接链接该库，或用 `LD_PRELOAD` 预加载，或改用动态 TLS 模型编译。

### 8. relocation error

```text
relocation error: ... symbol ... version GLIBCXX_3.4.29 not defined
```

动态重定位失败，通常是库版本/ABI 不匹配，或 interposition 后符号版本对不上。

## 四、排查流程（命令化）

### Step 1：看依赖和搜索路径

```bash
readelf -d ./app | grep -E 'NEEDED|RPATH|RUNPATH'
ldd ./app
```

### Step 2：看符号版本需求

```bash
readelf -V ./app | head -60
objdump -T ./app | grep GLIBC
```

### Step 3：跟踪加载与符号解析

```bash
LD_DEBUG=libs ./app
LD_DEBUG=symbols,bindings ./app 2>&1 | grep -A3 'symbol=foo'
LD_DEBUG=versions ./app 2>&1 | grep -i 'version'
```

### Step 4：看系统调用层面

```bash
strace -f -e trace=openat,mmap ./app 2>&1 | grep -E 'libfoo|ENOENT'
```

### Step 5：直接调用加载器

```bash
/lib64/ld-linux-x86-64.so.2 --list ./app
/lib64/ld-linux-x86-64.so.2 --verify ./app
LD_SHOW_AUXV=1 ./app | head
```

### Step 6：dlopen 场景

```c
void* h = dlopen("./libplugin.so", RTLD_NOW | RTLD_LOCAL);
if (!h) {
    fprintf(stderr, "%s\n", dlerror());
}
```

## 六、预防规范

1. 在**目标系统最低版本**或对应容器中编译，避免 glibc 版本倒挂。
2. 发布前在干净环境执行 `ldd -r`，确认无 `not found` 和未解析符号。
3. 使用 `$ORIGIN` RUNPATH 随包分发依赖库。
4. C++ 跨系统分发时统一 ABI 和编译器版本；必要时 `-static-libstdc++`。
5. `dlopen` 插件使用 `RTLD_NOW` 尽早暴露符号问题，使用 `RTLD_LOCAL` 隔离符号。
6. 不要在构造器里依赖其他全局对象的初始化顺序。
7. 服务化部署时，环境变量写进 unit/容器配置，不依赖登录 shell。

## 七、面试标准简答

### 1. 程序从 execve 到 main 经历了什么？

内核映射可执行文件和动态链接器，把控制权交给 `ld.so`；`ld.so` 加载依赖库、建立全局符号作用域、完成重定位、初始化 TLS、执行各库构造器，最后跳转到 `_start`，由 `__libc_start_main` 调用 `main`。

### 2. 惰性绑定和立即绑定的区别？

惰性绑定在函数第一次调用时解析符号并写回 GOT，启动快但这之前不会暴露缺失符号；立即绑定（`-z now` / `LD_BIND_NOW`）在启动时解析全部符号，问题暴露早，配合 RELRO 可让 GOT 只读。

### 3. 运行期 undefined symbol 和链接期 undefined reference 有什么区别？

链接期是链接器在生成产物时找不到符号定义；运行期是动态链接器加载后解析动态符号失败，常见于插件依赖缺失、库版本/ABI 不匹配或符号被隐藏。排查工具也不同：前者看 `nm` 和链接命令，后者看 `ldd -r`、`LD_DEBUG`。

### 4. GLIBC 版本报错怎么解决？

glibc 向后兼容、不向前兼容。高版本系统编译的程序不能在低版本系统运行。解决方案是在低版本系统/容器中编译，或使用静态链接/兼容工具链；不要直接替换目标系统的 `libc.so.6`。

## 八、极简口诀

**内核映射交解释器，ld.so 找库填地址；**

**构造器跑完进 _start，最后才到 main；**

**缺库看 RUNPATH，缺符号看 LD_DEBUG；**

**GLIBC 只向后兼容，低版本系统上编译。**
