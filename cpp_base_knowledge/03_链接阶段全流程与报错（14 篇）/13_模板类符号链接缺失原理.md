# 模板类符号链接缺失原理

## 一、前言

模板是 C++ 里最容易出现"编译通过、链接失败"的语法特性。典型报错：

```text
undefined reference to `Stack<int>::push(int const&)'
```

源码看起来完全正确，问题在于：**模板不是代码，是生成代码的蓝图；编译器在实例化时必须看到完整定义。**

核心总纲：**模板的定义必须对每个实例化点可见，所以通常要放在头文件里。** 只把声明放头文件、定义放 `.cpp`，其他编译单元就只能生成未定义引用。

## 二、底层机制

### 1. 模板的实例化

- 模板本身不会被编译成机器码；
- 当代码使用 `Stack<int>` 时，编译器才**隐式实例化**出 `Stack<int>` 的成员函数；
- 实例化需要模板的完整定义，而不只是声明；
- 实例化结果是一个弱符号（COMDAT），多个编译单元重复实例化时由链接器合并。

### 2. 两阶段查找

模板的编译分两个阶段：

1. 模板定义解析阶段：检查非依赖名；
2. 实例化阶段：检查依赖名。

很多"模板语法错误"在这一步报出，但链接错误通常不是查找问题，而是**定义不可见**。

### 3. 为什么定义要放头文件

编译 `main.cpp` 时，编译器看到：

```cpp
#include "stack.h"     // 只有类声明和成员函数声明
Stack<int> s;
s.push(1);            // 需要 Stack<int>::push 的定义
```

如果 `stack.cpp` 里才有定义，`main.cpp` 看不到，只能生成：

```text
U Stack<int>::push(int const&)
```

链接时如果 `stack.cpp` 没有被编译进目标文件，或者虽然编译了但没有生成该实例化的强符号，就会报 undefined reference。

### 4. 显式实例化

如果确实想把实现藏在 `.cpp` 里，可以显式实例化：

```cpp
// stack.cpp
#include "stack.h"

template <typename T>
void Stack<T>::push(const T& value) { /* ... */ }

template class Stack<int>;      // 显式实例化定义，生成 Stack<int> 的全部成员
template class Stack<double>;
```

其他编译单元使用 `Stack<int>` 时，不再需要定义，直接引用已生成的符号。

### 5. extern template

在头文件里声明"这个实例化在别处生成"，避免每个编译单元重复实例化：

```cpp
// stack.h
extern template class Stack<int>;   // 抑制本编译单元的隐式实例化
```

```cpp
// stack.cpp
template class Stack<int>;          // 唯一定义
```

### 6. COMDAT 与 ODR

模板的隐式实例化是弱符号，链接器会合并同名实例。前提是所有编译单元看到的模板定义**完全一致**。如果不同编译单元因为宏、头文件版本不同看到了不同的模板定义，属于 ODR 违规，链接器可能任选一份，导致行为不一致、内存布局错乱。

## 三、高频场景

### 1. 定义放在 .cpp（最经典）

```cpp
// stack.h
template <typename T>
class Stack {
public:
    void push(const T& value);
};

// stack.cpp
template <typename T>
void Stack<T>::push(const T& value) { /* ... */ }

// main.cpp
Stack<int> s;
s.push(1);    // undefined reference to `Stack<int>::push(int const&)'
```

修复：把定义放回 `stack.h`；或在 `stack.cpp` 显式实例化 `template class Stack<int>;`。

### 2. 类模板成员函数定义在 .cpp

即使类定义在头文件，成员函数定义放在 `.cpp` 同样不可见：

```cpp
// stack.cpp
template <typename T>
void Stack<T>::pop() { /* ... */ }   // 其他 TU 实例化时看不到
```

修复同上。

### 3. 函数模板定义在 .cpp

```cpp
// util.h
template <typename T> T max(T a, T b);

// util.cpp
template <typename T> T max(T a, T b) { return a > b ? a : b; }

// main.cpp
max(1, 2);   // undefined reference to `int max<int>(int, int)'
```

修复：定义放头文件；或显式实例化 `template int max<int>(int, int);`。

### 4. 模板特化未声明

```cpp
// foo.h
template <typename T> struct Foo { void run(); };

// foo.cpp
template <> struct Foo<int> { void run(); };   // 特化只在这里可见
void Foo<int>::run() { }
```

其他编译单元不知道 `Foo<int>` 有特化，可能实例化主模板，链接到不同的符号，或出现 ODR 冲突。修复：特化声明放头文件。

### 5. 模板实现拆分到 .tpp/.ipp

工程上常用：

```cpp
// stack.h
template <typename T> class Stack { ... };

#include "stack.tpp"    // 在头文件末尾包含实现
```

`stack.tpp` 仍然是头文件的一部分，每个包含者都能看到定义。

### 6. 模板与共享库边界

- 模板实例在每个使用它的编译单元生成，弱符号合并；
- 如果库用 `-fvisibility=hidden`，模板实例可能被隐藏；
- 跨库传递模板类型时，确保 ABI/编译选项一致，否则 ODR 冲突。

## 四、排查流程

### Step 1：确认报错符号的完整名字

```bash
nm -C main.o | grep 'Stack<int>'
# U Stack<int>::push(int const&)   -> 未定义
```

### Step 2：确认定义是否在某处实例化

```bash
nm -C -A *.o | grep 'Stack<int>::push'
nm -C libfoo.a | grep 'Stack<int>::push'
```

### Step 3：确认头文件是否包含实现

```bash
g++ -E main.cpp | grep -A5 'class Stack'
```

### Step 4：检查是否显式实例化

```bash
grep -rn 'template class Stack' .
```

### Step 5：检查宏/头文件差异

```bash
g++ -dM -E main.cpp > main.macros
g++ -dM -E stack.cpp > stack.macros
diff main.macros stack.macros
```

不同宏导致模板定义不同，可能引发 ODR 问题。

## 五、修复方案速查

| 场景 | 修复 |
|---|---|
| 类模板/成员函数定义在 `.cpp` | 移到头文件，或显式实例化 |
| 函数模板定义在 `.cpp` | 移到头文件，或显式实例化 |
| 想让实现隐藏在 `.cpp` | 对已知类型显式实例化 |
| 重复实例化导致体积大 | `extern template` + 一处显式实例化 |
| 模板特化 | 特化声明放头文件，定义放 `.cpp` 并确保可见 |
| 跨库模板类型 | 统一 ABI/宏，评估可见性与 ODR |
| 想分离接口与实现 | `.tpp` / `.ipp` 在头文件末尾 include |

## 六、预防规范

1. 模板定义默认放头文件；实现较大时拆到 `.tpp` / `.ipp`。
2. 确实要隐藏实现时，用显式实例化，并在头文件 `extern template` 声明。
3. 模板特化必须在第一次使用前声明，声明放头文件。
4. 不同编译单元的模板定义必须完全一致，避免宏影响模板定义。
5. 跨共享库传递模板类型时，保证 ABI、编译选项和标准库版本一致。
6. 构建时关注模板实例化数量，必要时用 `extern template` 控制体积。

## 七、面试标准简答

### 1. 为什么模板定义通常要放在头文件？

模板在使用处实例化，编译器必须看到完整定义才能生成代码。如果定义在 `.cpp`，其他编译单元只看到声明，只能生成未定义引用，链接时就会失败。

### 2. 显式实例化有什么用？

它让编译器在指定位置为指定类型生成模板实例。这样可以：把实现隐藏在 `.cpp`、减少重复实例化、缩短编译时间、控制哪些类型被支持。配合 `extern template` 还能避免其他编译单元重复生成。

### 3. 模板为什么允许多个编译单元重复实例化？

模板实例化生成弱符号（COMDAT），链接器会把同名弱符号合并成一份。前提是所有实例化看到的模板定义一致，否则属于 ODR 违规。

### 4. 如何既隐藏模板实现又支持外部使用？

在 `.cpp` 中为每种需要的类型显式实例化，并在头文件用 `extern template` 声明。外部只能使用已实例化的类型；未实例化的类型会在链接期报错。
