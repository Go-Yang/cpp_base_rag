# 标准库缺失编译报错修复

## 一、前言

"标准库缺失"要分两层：

- **头文件缺失**：编译/预处理阶段找不到声明；
- **库文件缺失**：编译通过，链接阶段找不到实现。

核心总纲：**头文件管声明，库文件管实现；缺头文件编译报错，缺库文件链接报错。** 先看报错阶段，再决定装开发包还是加链接参数。

## 二、头文件 vs 库文件

| 资源 | 阶段 | 典型报错 | 修复 |
|---|---|---|---|
| 头文件 `.h` | 预处理/编译 | `No such file or directory` | 安装 `-dev`/`-devel` 包，补 `-I` |
| 静态库 `.a` | 链接 | `undefined reference`、`cannot find -lxxx` | 安装库、加 `-L/-l` |
| 动态库 `.so` | 链接/运行 | `cannot find -lxxx`、`cannot open shared object` | 安装运行库、设置 RPATH |

## 三、常见库与链接参数

### 1. libm（数学库）

```bash
gcc app.c -o app -lm
```

- `sqrt`、`pow`、`sin`、`cos` 等通常在 `libm`；
- 需要显式 `-lm`（放在对象文件之后）；
- 某些编译器会对常量表达式做内建优化，看起来"不加也行"，但不要依赖。

### 2. pthread（线程库）

```bash
gcc app.c -o app -pthread
```

- `-pthread` 同时设置编译宏和链接参数，优于只加 `-lpthread`；
- glibc 2.34 起 `libpthread` 合并进 `libc`，但 `-pthread` 仍是推荐写法；
- 旧系统必须链接。

### 3. libdl（动态加载）

```bash
gcc app.c -o app -ldl
```

- `dlopen`/`dlsym`/`dlclose` 在旧 glibc 中需要 `-ldl`；
- glibc 2.34 起合并进 `libc`；
- 可移植写法仍保留 `-ldl`。

### 4. C++ 标准库

```bash
g++ app.cpp -o app          # 推荐
gcc app.cpp -o app -lstdc++ # 不推荐，容易漏其他依赖
```

- `g++` 自动链接 `libstdc++` 和 C++ 运行期支持；
- `std::cout`、`operator new`、异常/RTTI 都依赖它；
- 跨库传递 C++ 对象时注意 ABI 和 `_GLIBCXX_USE_CXX11_ABI`。

### 5. 其他常见库

| 功能 | 参数 |
|---|---|
| 数学 | `-lm` |
| 线程 | `-pthread` |
| 动态加载 | `-ldl` |
| 实时扩展 | `-lrt`（旧 glibc） |
| 压缩 | `-lz` |
| 加密 | `-lcrypto`、`-lssl` |

## 四、Ubuntu/Debian 与 CentOS/RHEL

### Ubuntu/Debian

```bash
sudo apt update
sudo apt install build-essential
sudo apt install libfoo-dev     # 头文件 + 链接名 + 静态库
sudo apt install libfoo1        # 运行库（soname）
```

### CentOS/RHEL

```bash
sudo yum install gcc gcc-c++ make glibc-devel
sudo yum install foo-devel
```

注意：只装运行库（`libfoo1`）不会提供 `libfoo.so` 链接名/头文件，编译仍需 `-dev`/`-devel` 包。

## 五、库文件命名与链接

```text
libfoo.so        # 链接名（-lfoo 查找），通常来自 dev 包
libfoo.so.1      # SONAME，运行时记录
libfoo.so.1.2.3  # 真实文件
```

- `-lfoo` 找 `libfoo.so` 或 `libfoo.a`；
- `-L/path` 添加库搜索路径；
- 静态库/动态库同名时，链接器优先动态库；可用 `-Wl,-Bstatic`/`-Bdynamic` 指定。

```bash
gcc app.c -L/opt/foo/lib -lfoo -Wl,-rpath,'$ORIGIN/../lib' -o app
```

## 六、pkg-config

```bash
pkg-config --cflags --libs foo
gcc app.c $(pkg-config --cflags --libs foo) -o app
```

- 自动给出头文件/库路径和依赖；
- 缺少 `.pc` 文件时，检查 `PKG_CONFIG_PATH`。

## 七、常见问题

### 1. 装了库还是 `cannot find -lfoo`

- 只装了运行库，没装 dev 包（缺 `libfoo.so` 链接名）；
- `-L` 路径不对；
- 库架构不匹配（32/64 位、x86/ARM）；
- 库文件名不是 `libfoo.so`。

### 2. undefined reference to `sqrt`

- 没加 `-lm`；
- `-lm` 放在对象文件前面（静态库顺序问题）；
- 用了 C++ 但用 gcc 链接，缺 `-lstdc++`。

### 3. 编译通过，运行报 `cannot open shared object`

- 链接期找到了库，运行期搜索路径不对；
- 用 `$ORIGIN` RUNPATH 或 `ldconfig` 配置；
- 详见 03/动态库依赖缺失。

### 4. 静态库/动态库混用

- 同一个库既有 `.a` 又有 `.so`，默认选 `.so`；
- 需要静态链接时用 `-Wl,-Bstatic -lfoo -Wl,-Bdynamic`；
- 注意 glibc 全静态的 NSS/dlopen 限制。

### 5. C++ ABI 不匹配

- 预编译库与本地编译器 `_GLIBCXX_USE_CXX11_ABI` 不一致；
- 统一编译选项，或使用匹配的预编译包。

## 八、排查流程

1. 看报错阶段：头文件 → 编译；库 → 链接；运行 → 加载；
2. 确认库/头文件是否安装（dev 包）；
3. `ldconfig -p | grep foo`、`find / -name 'libfoo*'`；
4. 检查 `-L/-l`、链接顺序、架构；
5. 运行期检查 `ldd`、RPATH/RUNPATH。

## 九、面试简答

### 1. 头文件缺失和库文件缺失的区别？

头文件缺失是预处理/编译阶段找不到声明；库文件缺失是编译通过、链接阶段找不到实现。前者装 dev 包/补 `-I`，后者补 `-L/-l` 或安装库。

### 2. 为什么包含 math.h 还要 -lm？

`math.h` 只有声明，函数实现在 `libm`。需要链接器把 `libm` 加进来（`-lm`），且放在对象文件之后。

### 3. -pthread 和 -lpthread 的区别？

`-pthread` 同时设置编译期宏（如 `_REENTRANT`）和链接参数，是推荐写法；`-lpthread` 只加链接库。新 glibc 中 libpthread 已并入 libc，但 `-pthread` 仍建议保留。

### 4. 为什么 gcc 编译 C++ 会缺库？

`gcc` 不会自动链接 C++ 标准库；`g++` 会。C++ 项目直接用 `g++` 编译和链接。

## 十、极简口诀

**缺头编译挂，缺库链接瘫；**

**头管声明库管实现，dev 包别漏装；**

**数学 -lm、线程 -pthread，C++ 用 g++；**

**链接顺序对象前，运行路径 rpath。**
