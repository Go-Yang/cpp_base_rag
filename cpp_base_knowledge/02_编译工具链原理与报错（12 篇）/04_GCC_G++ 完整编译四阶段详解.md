# GCC/G++ 完整编译四阶段详解

## 一、前言

从 `.c`/`.cpp` 到可执行文件，GCC/G++ 经过四个阶段：

**预处理 → 编译 → 汇编 → 链接**

每个阶段有独立的输入/输出和报错边界。理解边界，才能看到报错就知道该查哪一层。

核心总纲：**预处理改文本，编译查语义，汇编翻指令，链接合全局。** 分步编译是定位复杂问题的最有效手段。

## 二、阶段一：预处理

### 1. 工作

- 处理 `#include`、`#define`、条件编译；
- 展开宏、删除注释、处理行接续；
- 输出不含预处理指令的翻译单元。

### 2. 命令与输出

```bash
gcc -E app.c -o app.i
```

### 3. 典型报错

- 头文件找不到；
- 宏参数/展开错误；
- 条件编译不配对；
- `#error`；
- 非法字符/编码。

## 三、阶段二：编译

### 1. 工作

- 词法分析、语法分析、语义分析；
- 类型检查、作用域检查、重载决议（C++）；
- 生成中间表示/汇编代码。

### 2. 命令与输出

```bash
gcc -S app.i -o app.s
# 或直接从源码：
gcc -S app.c -o app.s
```

### 3. 典型报错

- 语法错误；
- 类型不匹配；
- 未声明标识符；
- 参数不匹配；
- 模板/重载错误。

## 四、阶段三：汇编

### 1. 工作

- 汇编指令 → 机器码；
- 组织 section；
- 生成符号表和重定位项；
- 输出可重定位目标文件。

### 2. 命令与输出

```bash
gcc -c app.s -o app.o
```

### 3. 典型报错

- 内联汇编语法/约束错误；
- 目标架构/指令集不支持；
- 汇编语法错误；
- 文件损坏/工具链问题。

## 五、阶段四：链接

### 1. 工作

- 合并所有 `.o` 和库；
- 符号解析；
- 分配地址、完成重定位；
- 生成可执行文件/共享库。

### 2. 命令与输出

```bash
gcc app.o util.o -Llib -lfoo -o app
```

### 3. 典型报错

- `undefined reference`；
- `multiple definition`；
- 库找不到/顺序错误；
- 符号冲突；
- 动态库依赖问题（运行期）。

### 4. 关于"相对地址变绝对地址"

链接器会为可执行文件分配最终地址并修补重定位；但 PIE/共享库保留位置无关的重定位（如 `R_X86_64_RELATIVE`、`GLOB_DAT`），由动态链接器在加载时处理。不要简单说"链接就是把相对地址换成绝对地址"。

## 六、四阶段对照表

| 阶段 | 输入 | 输出 | 主要工作 | 典型报错 |
|---|---|---|---|---|
| 预处理 | `.c/.cpp` + 头文件 | `.i` | 宏展开、包含、条件编译 | 头文件缺失、宏错误 |
| 编译 | `.i` | `.s` | 语法/语义/类型检查、代码生成 | syntax/type error |
| 汇编 | `.s` | `.o` | 指令编码、段组织、重定位项 | 汇编语法、目标不匹配 |
| 链接 | `.o` + 库 | 可执行文件/`.so` | 符号解析、地址分配、重定位 | undefined/multiple definition |

## 七、gcc 与 g++

- `gcc` 默认按 C 编译，`g++` 默认按 C++ 编译；
- `g++` 链接时自动加入 C++ 标准库（`libstdc++`）；
- 用 `gcc` 链接 C++ 目标文件会缺 `libstdc++`，需要手动加 `-lstdc++`（不推荐）；
- 文件名后缀会影响默认语言，但可用 `-x` 显式指定；
- C++ 工程统一用 `g++` 编译和链接最省心。

```bash
gcc -c foo.cpp -o foo.o      # 可以编译
g++ foo.o -o app             # 用 g++ 链接
```

## 八、分步编译实战

```bash
gcc -E app.c -o app.i        # 1. 预处理
gcc -S app.i -o app.s        # 2. 编译
gcc -c app.s -o app.o        # 3. 汇编
gcc app.o -o app             # 4. 链接
```

- 卡在哪一步，就查哪一层；
- 保留 `.i`/`.s`/`.o` 便于对比和排查；
- 链接问题看符号和库顺序，不要改语法。

## 九、优化与 LTO

- 优化主要发生在编译阶段；
- 汇编阶段受优化结果影响，但正常代码不会因此报汇编错误；
- LTO（`-flto`）把优化推迟到链接期，跨编译单元优化；
- `-g` 生成调试信息，`-O0/-Og` 更适合调试。

## 十、面试简答

### 1. 简述 GCC 四阶段？

预处理展开文本和头文件；编译做语法/语义检查并生成汇编；汇编把汇编翻译成机器码生成 `.o`；链接合并目标文件和库、解析符号、完成地址分配和重定位。

### 2. 编译错误和链接错误的区别？

编译错误是单文件内的语法/类型/语义问题；链接错误是跨文件/库的符号问题（找不到定义、重复定义、库顺序/依赖）。

### 3. 为什么 .o 不能直接运行？

`.o` 是 `ET_REL` 可重定位文件，符号地址未最终分配，外部引用未解析，缺少程序入口和运行时布局，不能直接被内核加载执行。

### 4. 为什么 C++ 要用 g++ 链接？

`g++` 会自动链接 C++ 标准库并处理 C++ 运行期初始化；用 `gcc` 链接 C++ 目标文件会缺少 `libstdc++` 等依赖。

## 十一、极简口诀

**预处理裁文本，编译查语义；**

**汇编翻机器码，链接合全局；**

**单文件错在编译，跨文件错在链接；**

**分步编译定位，C++ 用 g++。**
