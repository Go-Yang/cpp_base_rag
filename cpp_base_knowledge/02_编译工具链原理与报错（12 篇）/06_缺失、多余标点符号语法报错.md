# 缺失、多余标点符号语法报错

## 一、前言

"符号"这个词在 C/C++ 里有两层含义，容易混淆：

1. **语法符号**：分号、括号、花括号、逗号、方括号等标点；
2. **链接符号**：函数/变量在目标文件中的名字（symbol）。

本文主要讲第一层：**语法符号缺失/多余导致的编译错误**；第二层（undefined reference / multiple definition）属于链接阶段，见 03 链接专题。

核心总纲：**语法符号错误会让语法树断裂，产生大量连锁报错；先修第一条，再重新编译。**

## 二、词法/语法层面的符号错误

### 1. 缺失分号

```c
int a = 1
int b = 2;   // 报错：expected ';' before 'int'
```

- 报错行往往在下一行；
- 优先检查报错行的上一行末尾。

### 2. 缺失/多余括号

```c
if (a > b {          // 缺少 ')'
    ...
}

int x = (1 + 2;      // 括号不匹配
```

- 小括号、中括号、花括号都要配对；
- 嵌套层级多时用编辑器括号匹配/格式化。

### 3. 缺失/多余花括号

```c
if (a)
    do_something();
    do_another();    // 缩进误导，实际不在 if 内
```

- 语法合法但逻辑错误；
- 工程规范建议所有分支/循环都加大括号。

### 4. 缺失逗号

```c
int a = 1 b = 2;     // 缺少逗号/分号
func(a b);           // 参数之间缺逗号
```

### 5. 多余分号

```c
if (a > b);          // 空语句，if 失效
{
    do_something();
}
```

- 编译通过，运行逻辑错；
- `for (...);` 也是常见坑。

### 6. 全角/中文标点

```c
int a = 1；          // 全角分号
if （a > b） {       // 全角括号
```

- 编译器报 `stray '\357'`、`invalid character` 等；
- 统一 UTF-8，禁用中文标点；
- 用 `grep -P '[\x{FF00}-\x{FFEF}]'` 查找全角字符。

### 7. 宏展开后的符号错误

```c
#define FOO(x) x + 1
int y = FOO(2) * 3;   // 展开为 2 + 1 * 3 = 5
```

宏缺括号导致优先级错误；用 `gcc -E` 查看展开结果。

### 8. 续行符错误

```c
#define FOO(x) do { \
    bar(x);          \   // 反斜杠后有空格 → 续行失败
} while (0)
```

`\` 必须是行尾最后一个字符。

## 三、链接符号层面的错误（简述）

如果你看到的是下面这些，说明不是语法符号问题，而是链接符号问题：

| 报错 | 含义 | 去向 |
|---|---|---|
| `undefined reference to 'foo'` | 找不到定义 | 03/undefined reference |
| `multiple definition of 'foo'` | 同一个强符号多处定义 | 03/multiple definition |
| `cannot find -lfoo` | 库文件找不到 | 03/库依赖 |
| `symbol lookup error`（运行期） | 动态符号解析失败 | 03/动态链接器 |

语法符号错误在编译期报出；链接符号错误在链接期/运行期报出，二者排查方法完全不同。

## 四、排查流程

1. **看第一条 error**：后续多为连锁伪报错；
2. **看报错行的上一行/上一代码块**：缺分号、括号未闭合常在这里；
3. **检查五类符号**：`;`、`()`、`{}`、`[]`、`,`；
4. **检查全角字符/编码**；
5. **宏问题用 `-E`**；
6. **格式化代码**：缩进/括号对齐能快速暴露不对称；
7. **修复后重新编译**，确认连锁错误消失。

## 五、常见误区

### 1. 从最后一条报错开始改

最后一条往往只是受害者。先修第一条。

### 2. 报错行没问题就跳过

语法错误经常"报在下一行"，真正的问题在上一行/上一代码块。

### 3. 忽略多余分号

`if (x);`、`for (...);` 编译不报错，但逻辑完全错误。开启 `-Wall` 不一定能发现，需要代码审查。

### 4. 宏展开的报错当成手写代码错误

宏展开后的代码与源码形态不同，先看 `.i`。

### 5. 把链接符号错误当语法错误

`undefined reference` 改源码语法没用，要看符号、库、链接顺序。

## 六、工程规范

1. 统一 UTF-8，禁止中文标点；
2. 所有 if/for/while 强制大括号；
3. 宏参数/整体加括号；
4. 多行宏 `\` 行尾无空格；
5. 提交前格式化代码；
6. CI 开启 `-Wall -Wextra`；
7. 区分编译期语法错误和链接期符号错误，用对应工具排查。

## 七、面试简答

### 1. 为什么少一个分号会报很多错误？

编译器流式解析，缺失分号让当前语句无法结束，后续代码被错误并入当前语法单元，产生大量连锁伪报错。修第一条即可。

### 2. 多余分号有什么危害？

`if (cond);` 让 if 作用于空语句，后续代码块无条件执行；编译不报错，运行逻辑错误。比缺失分号更隐蔽。

### 3. 语法符号错误和链接符号错误怎么区分？

语法符号错误在编译期报 `syntax error`/`expected`；链接符号错误在链接期报 `undefined reference`/`multiple definition`。前者改代码结构，后者查符号和库。

### 4. 如何快速定位符号配对错误？

用编辑器括号匹配、代码格式化、编译器首条报错定位；宏问题用 `gcc -E` 查看展开结果。

## 八、极简口诀

**缺符断语法，多符藏隐坑；**

**首错定根因，上行找元凶；**

**括号成对写，分号不落空；**

**语法改结构，链接查符号。**
