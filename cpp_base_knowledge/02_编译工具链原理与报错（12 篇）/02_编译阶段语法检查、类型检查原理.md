# 编译阶段语法检查、类型检查原理

## 一、前言

编译阶段把预处理后的 token 流转换成汇编代码，核心流程：

**词法分析 → 语法分析 → 语义分析 → 中间代码生成/优化 → 目标代码生成**

绝大多数语法错误、类型错误、作用域错误都在这里报出。

核心总纲：**词法管 token，语法管结构，语义管类型和规则。** 编译诊断发生在优化之前，所以"优化导致类型报错"是错误说法。

## 二、词法分析

- 把字符流切成 token；
- 识别关键字、标识符、数字、字符串、运算符、标点；
- 处理字面量类型、转义、数字后缀；
- 报错：非法字符、未闭合字符串/字符常量、无效数字。

```text
error: stray '\' in program
error: missing terminating " character
```

## 三、语法分析

- 按文法把 token 组装成抽象语法树（AST）；
- 检查括号/花括号/分号等结构；
- 报错：`syntax error`、`expected ';'`、`unmatched`。

语法错误通常行号较准，但宏展开会让报错位置指向宏调用点，而不是宏定义处。

## 四、语义分析

语义分析在 AST 上做：

- 名称查找/作用域；
- 类型检查与类型推导；
- 函数重载决议（C++）；
- 模板实例化（C++）；
- 访问控制（C++）；
- 常量表达式求值；
- 隐式转换检查；
- 初始化/赋值兼容性；
- 控制流检查（如 return 路径）。

### 1. 类型检查

```c
int a = 3.14;      // C/C++ 都允许，可能给警告（-Wconversion）
char* p = 100;     // C/C++ 都不允许（int 转指针），报错
void* v = malloc(10);
int* q = v;        // C 合法；C++ 报错，需要 (int*)v
```

C++ 不是"禁止所有隐式转换"，而是有明确的转换规则和重载决议；很多算术转换是合法的，只是可能丢失精度并触发警告。

### 2. 名称查找

- 未声明标识符：`undeclared identifier` / `was not declared in this scope`；
- 头文件缺失、拼写错误、命名空间错误；
- C++ 的 ADL、限定名、模板依赖名会让查找更复杂。

### 3. 函数调用检查

- 参数个数/类型是否匹配；
- 重载决议选哪个函数；
- 默认参数；
- 返回值是否被使用/忽略（`nodiscard`）。

### 4. 作用域与链接

- 同一作用域重复定义 → 编译错误；
- 跨编译单元重复定义 → 链接错误；
- static/匿名命名空间影响可见性；
- C++ 的 ODR 规则。

## 五、诊断级别

| 级别 | 含义 | 例子 |
|---|---|---|
| error | 编译失败 | 语法错误、类型不匹配 |
| warning | 可疑但可编译 | 隐式转换、未使用变量、隐式声明 |
| note | 补充信息 | 声明位置、候选函数 |
| pedantic | 标准符合性提示 | GNU 扩展 |

常用选项：

```bash
gcc -Wall -Wextra -Wconversion -Wshadow -Wpedantic -fsyntax-only app.c
```

- `-fsyntax-only`：只做语法/语义检查，不生成代码；
- `-Werror`：警告转错误；
- `-Wconversion`：隐式数值转换警告；
- `-Wsign-conversion`：有符号/无符号转换警告。

## 六、C 与 C++ 的检查差异

| 维度 | C | C++ |
|---|---|---|
| `void*` 转换 | 隐式允许 | 必须显式 |
| 函数重载 | 无 | 有，重载决议 |
| 隐式函数声明 | 旧标准允许 | 禁止 |
| const 链接 | 外部链接 | 默认内部链接 |
| 类型检查 | 相对宽松 | 更严格，但仍有大量合法隐式转换 |
| 模板/命名空间 | 无 | 有，语义分析更复杂 |

## 七、常见报错与根因

### 1. syntax error before/expected

- 缺分号/括号/花括号；
- 宏展开后结构错误；
- 关键字拼写错误；
- C++ 中把类型/变量用错位置。

### 2. undeclared identifier

- 忘记包含头文件；
- 拼写错误；
- 命名空间未限定；
- 声明顺序问题（C 中先使用后声明）。

### 3. invalid conversion / cannot convert

- 指针类型不匹配；
- `const` 限定丢失；
- C++ 中 `void*` 未显式转换；
- 构造函数/转换运算符不匹配。

### 4. no matching function for call

- 参数个数/类型不匹配；
- 重载决议失败；
- 模板推导失败；
- 缺少 `const`/引用限定。

### 5. redefinition

- 同一作用域重复定义；
- 头文件重复包含（编译期表现）；
- 宏/类型名冲突。

## 八、排查方法

1. 只看第一条 error，后续多为连锁反应；
2. 用 `-fsyntax-only` 快速检查；
3. 用 `-E` 确认宏展开后的代码；
4. 开启 `-Wall -Wextra`，区分错误与警告；
5. C++ 报错看候选函数/模板推导信息；
6. 最小化复现，逐步注释代码。

## 九、面试简答

### 1. 编译阶段包含哪些步骤？

词法分析、语法分析、语义分析、中间代码生成与优化、目标代码生成。语法/类型错误在词法/语法/语义阶段报出。

### 2. 语法错误和类型错误的区别？

语法错误是 token 序列不符合文法（缺分号、括号不匹配）；类型错误是结构合法但类型/语义规则不满足（参数不匹配、非法转换）。

### 3. C++ 中 `int a = 3.14;` 会报错吗？

通常不会。它是合法的隐式浮点转整型，可能触发 `-Wconversion` 警告；只有开启 `-Werror` 才变成错误。

### 4. 优化会导致类型检查错误吗？

不会。类型检查发生在优化之前；优化可能暴露未定义行为或触发编译器 bug，但不会产生新的类型诊断。

## 十、极简口诀

**词法切 token，语法组 AST；**

**语义查类型、作用域、重载；**

**诊断在优化前，警告不等于错误；**

**先看第一条，-fsyntax-only 快查。**
