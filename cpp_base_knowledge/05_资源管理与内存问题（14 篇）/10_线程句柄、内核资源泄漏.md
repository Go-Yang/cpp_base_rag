# 线程句柄、内核资源泄漏

## 一、前言

进程资源不只有内存和 fd。线程、内核对象、IPC 资源同样有限，泄漏后表现为：

- 线程数持续上涨，调度开销变大；
- `pthread_create` 返回 `EAGAIN`；
- 共享内存/信号量残留，机器重启才能清；
- 容器内资源配额被耗尽。

核心总纲：**线程要 join/detach，内核对象要 close/unlink/delete，IPC 要显式销毁。** 进程退出能回收大部分，但长周期服务必须在运行期管理。

## 二、线程资源泄漏

### 1. pthread 的两种收尾

```c
pthread_t tid;
pthread_create(&tid, NULL, worker, arg);
```

- **joinable（默认）**：线程结束后资源保留，直到 `pthread_join`；
- **detached**：线程结束后资源自动回收，不能 join。

```c
pthread_join(tid, NULL);                          // 等待并回收
pthread_detach(tid);                              // 分离，自动回收
```

只 create 不 join 也不 detach → 线程终止后仍占资源（类似僵尸线程）。

### 2. std::thread

```cpp
std::thread t(worker);
t.join();      // 或 t.detach();
```

`std::thread` 析构时如果仍 joinable，会调用 `std::terminate`。必须在销毁前 join 或 detach。

### 3. 常见泄漏场景

- 线程池只增不减，任务结束后线程不退出；
- 每请求创建一个线程，忘记 join；
- 异常路径跳过 join；
- detach 后线程访问已销毁的对象（悬空，不是资源泄漏但更危险）；
- 线程栈设置过大，线程数多时内存暴涨。

### 4. 线程栈

每个线程有独立栈（默认 8MB 虚拟）。线程泄漏会连带栈映射泄漏，RSS/VSZ 上涨。

### 5. 清理与取消

```c
pthread_cleanup_push(cleanup, arg);
// ...
pthread_cleanup_pop(1);
```

线程被取消或正常退出时执行清理函数。C++ 中优先用 RAII，但要注意线程取消时的析构行为。

## 三、内核资源泄漏

### 1. 文件描述符类

- `eventfd`、`timerfd`、`signalfd`、`inotify`、`epoll`、`memfd`；
- socket、pipe、文件；
- 都遵循 open/close 配对，详见《文件句柄泄漏成因与检测》。

### 2. 内存映射

```c
void* p = mmap(...);
munmap(p, size);
```

长期不 munmap 会占用虚拟地址空间；匿名映射被触碰后还占物理内存。

### 3. POSIX 共享内存 / 信号量

```c
int fd = shm_open(name, O_CREAT | O_RDWR, 0600);
shm_unlink(name);        // 名字删除，已有映射仍可用

sem_t* s = sem_open(name, O_CREAT, 0600, 1);
sem_unlink(name);
```

- 进程退出**不会**自动删除命名对象；
- 不 unlink 就永久留在 `/dev/shm`；
- 匿名共享内存（`mmap(MAP_SHARED|MAP_ANONYMOUS)`）随进程退出释放。

### 4. System V IPC

```bash
ipcs -m   # 共享内存
ipcs -s   # 信号量
ipcs -q   # 消息队列
ipcrm -m <shmid>
```

- 进程退出不会自动删除，除非显式 `IPC_RMID`；
- 信号量可用 `SEM_UNDO` 在进程退出时撤销操作，但对象本身仍在；
- 容器里残留的 IPC 会一直占资源。

### 5. POSIX 定时器

`timer_create` 创建的定时器需要 `timer_delete`；timerfd 用 close。

### 6. 文件锁

`flock`/`fcntl` 锁通常在 fd 关闭时释放；但 fork/exec 继承和锁语义要仔细处理。

### 7. 内核线程与 PID

- 线程/进程退出后未 wait 会留下僵尸（task 结构、PID）；
- 大量僵尸耗尽 PID 表；
- 容器 PID 1 要负责回收。

## 四、检测手段

| 资源 | 查看命令 |
|---|---|
| 线程数 | `ls /proc/<pid>/task | wc -l` |
| 线程列表 | `ps -eLf | grep <pid>` / `top -H -p <pid>` |
| 线程栈 | `pmap -x <pid>` |
| fd | `ls /proc/<pid>/fd | wc -l` / `lsof -p <pid>` |
| 共享内存 | `ipcs -m` / `ls -l /dev/shm` |
| 信号量 | `ipcs -s` / `ls -l /dev/shm/sem.*` |
| 消息队列 | `ipcs -q` |
| 内存映射 | `cat /proc/<pid>/maps` |
| 定时器 | `/proc/<pid>/timers` |
| 僵尸 | `ps -el | grep Z` |

### 监控思路

- 线程数、fd 数、VSZ/RSS 做长期曲线；
- 压测前后对比；
- 退出时检查 `/dev/shm` 和 `ipcs` 是否残留。

## 五、修复与预防

1. **线程 RAII 封装**：析构时 join 或 detach；优先使用线程池。
2. **不要每请求起线程**：用池化、异步 IO、协程。
3. **统一 close/unlink**：fd、shm、sem 都用 RAII 包装。
4. **明确生命周期**：谁创建谁销毁，跨模块传递要有约定。
5. **容器配置**：PID 1 用 tini/init 回收僵尸；设置资源限制。
6. **进程退出兜底**：atexit 清理命名 IPC；但不要依赖它处理 SIGKILL。
7. **压测与监控**：把线程数/fd 数纳入监控告警。

## 六、常见问题

### 1. 线程结束但资源不释放

默认 joinable，线程退出后保留退出状态和栈，直到 join。改为 detach 或 join。

### 2. std::thread 析构崩溃

仍 joinable 时析构调用 `std::terminate`。确保 join/detach。

### 3. /dev/shm 满

POSIX 共享内存未 unlink，或文件未删除。`df -h /dev/shm`、`ls -l /dev/shm` 定位。

### 4. 容器内 PID 耗尽

僵尸堆积或线程泄漏。检查 PID 1、`ps -el | grep Z`、线程数。

### 5. 线程数正常但 VSZ 很大

线程栈保留或 mmap 泄漏。看 `pmap`、`/proc/<pid>/maps`。

## 七、面试标准简答

### 1. pthread 线程默认 joinable 意味着什么？

线程结束后内核保留其资源（栈、退出状态），必须 `pthread_join` 回收，或创建时/之后 `pthread_detach` 让它自动回收。只 create 不处理会泄漏。

### 2. std::thread 析构时要注意什么？

析构时若仍 joinable，会调用 `std::terminate`。必须在此之前 `join()` 或 `detach()`；优先 RAII 封装或线程池。

### 3. 进程退出会自动清理共享内存吗？

匿名共享内存随进程退出释放；POSIX 命名共享内存和 System V IPC 不会自动删除，需要 `shm_unlink` / `ipcrm` / `IPC_RMID`。

### 4. 如何发现线程或内核资源泄漏？

监控线程数、fd 数、VSZ/RSS 曲线；用 `/proc/<pid>/task`、`lsof`、`ipcs`、`pmap` 检查；压测前后对比。

## 八、极简口诀

**线程 create 要 join 或 detach，否则资源不回收；**

**std::thread 不 join 会 terminate；**

**fd 要 close，shm/sem 要 unlink，SysV 要 IPC_RMID；**

**task 数看线程，ipcs 看残留。**
