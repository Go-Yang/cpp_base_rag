# 野指针、悬空指针成因与彻底规避

## 一、前言

两类指针问题经常被混为一谈：

- **野指针（wild pointer）**：指针从未初始化，指向随机地址；
- **悬空指针（dangling pointer）**：指针曾经有效，但指向的对象已经释放/失效。

核心总纲：**野指针是"没赋值"，悬空指针是"赋值过但对象没了"。** 二者都会导致随机崩溃、数据损坏，且问题现场往往远离真正的错误点。

## 二、野指针的成因

### 1. 未初始化

```c
int* p;        // 栈上随机值
*p = 42;       // 未定义行为，可能崩溃或悄悄改坏内存
```

### 2. malloc 后未检查

```c
char* p = malloc(n);
strcpy(p, src);   // malloc 失败返回 NULL，未检查直接崩溃
```

### 3. 错误类型转换

```c
int x = 42;
char* p = (char*)x;   // 把整数当地址
```

## 三、悬空指针的成因

### 1. free/delete 后继续使用

```c
char* p = malloc(100);
free(p);
strcpy(p, "hello");   // use-after-free
```

### 2. 返回局部变量地址

```c
char* bad(void) {
    char buf[64] = "hello";
    return buf;       // 函数返回后栈帧失效
}
```

### 3. 指向已销毁对象的成员

```cpp
Foo* p = new Foo;
delete p;
p->bar();             // 对象已销毁
```

### 4. 容器扩容导致指针/迭代器失效

```cpp
std::vector<int> v;
int* p = &v[0];
v.push_back(1);       // 可能重新分配，p 悬空
```

`std::vector` 扩容会移动元素，所有指针、引用、迭代器失效。`std::string`、`std::deque` 等也有类似规则。

### 5. realloc 移动内存

```c
p = realloc(p, bigger);   // 可能返回新地址，旧 p 失效
```

如果 realloc 失败返回 NULL，原指针也不能丢。

### 6. 多次释放/多个所有者

一个指针被 free 两次，或两个模块都认为自己拥有它并释放，产生 double free / 悬空。

### 7. 对象生命周期结束

- 指向临时对象；
- 指向已离开作用域的局部对象；
- 指向被 `erase` 的容器元素；
- 指向 `unique_ptr::release` 后无人管理的对象。

## 四、典型症状

- 随机崩溃，地址每次不同；
- 读写到其他变量，逻辑偶发错误；
- `free(): invalid pointer`、`double free or corruption`；
- 程序在毫无关系的位置崩溃；
- 调试器里变量值莫名其妙。

悬空指针最危险的地方：**释放后的内存可能立刻被分配器复用**，读到的是别人的数据，写坏的是别人的对象。

## 五、检测手段

### 1. ASAN

```bash
gcc -fsanitize=address -fno-omit-frame-pointer -g app.c -o app
```

- use-after-free、double-free、heap-buffer-overflow 都能精确报出分配/释放/访问三处栈；
- 开销约 2 倍，适合开发和 CI。

### 2. Valgrind

```bash
valgrind --tool=memcheck --track-origins=yes --leak-check=full ./app
```

能报 invalid read/write、use of uninitialised value，但程序变慢很多。

### 3. 编译器与库

- `-Wall -Wextra`：`-Wuninitialized`、`-Wreturn-local-addr`；
- `_GLIBCXX_DEBUG`：STL 迭代器/越界检查；
- `MALLOC_PERTURB_`：free 后填充垃圾值，让悬空使用更容易暴露；
- `MALLOC_CHECK_=3`：glibc 堆检查。

### 4. 调试器

```bash
gdb ./app
(gdb) watch *p
(gdb) bt
```

配合 core 查看崩溃地址属于哪个映射。

## 六、彻底规避

### 1. 初始化

```c
int* p = NULL;
```

C++ 用 `nullptr`。

### 2. 释放后置空（单所有者场景）

```c
free(p);
p = NULL;
```

注意：这只对**当前这个指针变量**有效，其他别名仍然悬空。多所有者场景要靠所有权设计。

### 3. RAII / 智能指针

- `std::unique_ptr`：独占所有权，离开作用域自动释放；
- `std::shared_ptr`：共享所有权，引用计数归零释放；
- `std::weak_ptr`：观察者，不延长生命周期；
- 容器存对象或智能指针，不存裸指针。

### 4. 不要返回局部变量地址

返回 `std::string`、`std::vector`，或由调用者传入缓冲区。

### 5. 容器操作后重新获取指针

扩容后旧指针/迭代器全部失效；需要稳定地址时用 `std::list`、`std::deque`（注意各自失效规则）或存索引。

### 6. 明确所有权

- 谁申请谁释放；
- 跨模块传递时用借用（borrow）语义，文档写清；
- 避免"两个模块都以为自己是 owner"。

### 7. 使用安全 API

- `std::span`、`std::string_view` 传递非拥有视图（注意生命周期）；
- 边界检查用 `.at()`；
- 避免裸 `memcpy` 到未校验大小的缓冲区。

## 七、面试标准简答

### 1. 野指针和悬空指针的区别？

野指针从未初始化，值不确定；悬空指针曾经指向有效对象，但对象已经释放或失效。前者是"没赋值"，后者是"对象没了"。

### 2. free 后把指针置 NULL 能解决问题吗？

只能保护这一个指针变量。其他指向同一块的别名仍然悬空；如果通过别名再次访问，照样出问题。根本解法是明确所有权 + RAII。

### 3. vector push_back 后原来的指针还能用吗？

不一定。扩容会导致重新分配，元素被移动，所有指针、引用、迭代器失效。需要稳定地址时用其他容器或存索引。

### 4. ASAN 如何检测 use-after-free？

ASAN 在分配块周围加红区，并在释放后把内存放入隔离区（quarantine），不立即复用；访问被释放的块时，影子内存标记会触发错误并打印分配/释放/访问栈。

## 八、极简口诀

**野指针没赋值，悬空指针对象亡；**

**free 之后别再用，置空只保单名；**

**容器扩容全失效，局部地址别返回；**

**所有权要明确，ASAN 查 UAF。**
