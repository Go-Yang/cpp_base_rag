# 内存碎片产生原理与工程优化

## 一、前言

内存碎片是指：**总空闲内存足够，但无法满足某个连续分配请求**，或者空闲内存分散导致实际占用偏高。

两类：

- **内部碎片**：分配器给的块比请求的大，差值是浪费；
- **外部碎片**：空闲块散落在已分配块之间，无法合并成大块。

核心总纲：**碎片来自"大小混杂 + 生命周期混杂 + 分配器策略"。** 优化方向不是"少 malloc"，而是让同类对象集中、生命周期一致。

## 二、内部碎片

### 1. 来源

- 对齐：malloc 按 16 字节对齐，请求 1 字节也占一个最小 chunk；
- chunk 头：glibc 每块有 `size` 等元数据；
- size class：分配器按大小类取整（jemalloc/tcmalloc 更明显）；
- 容器预留：`vector` 扩容按倍数增长，capacity 可能远大于 size。

### 2. 示例

```c
malloc(1);    // glibc 实际占用一个最小 chunk（约 32 字节）
```

大量小对象会产生显著内部碎片。

## 三、外部碎片

### 1. 产生过程

```text
初始：[ 空闲 64K ]
分配 A(16K)、B(16K)、C(16K)、D(16K)
释放 B、D：
[ A ][ 空闲16K ][ C ][ 空闲16K ]
现在请求 32K 连续内存 → 虽然总空闲 32K，但不相邻，失败或走 mmap
```

### 2. 加剧因素

- **大小混杂**：大小差异越大，越难复用；
- **生命周期混杂**：长生命周期对象夹在短生命周期对象之间，释放后留下空洞；
- **多线程 arena**：每个 arena 各自碎片，整体更碎；
- **频繁扩容**：容器反复 realloc，留下旧块；
- **fastbin 不合并**：小块先缓存，延迟合并。

### 3. 后果

- RSS 偏高；
- 大块分配失败或触发 mmap，增加系统调用；
- 缓存局部性变差；
- 极端情况下 OOM。

## 四、测量

### 1. glibc 统计

```c
malloc_stats();                 // 打印到 stderr
struct mallinfo2 mi = mallinfo2();
// mi.arena, mi.fordblks（空闲块）, mi.uordblks（已用）
```

### 2. /proc

```bash
grep -E 'VmRSS|VmSize' /proc/<pid>/status
cat /proc/<pid>/smaps | grep -A10 heap
pmap -x <pid>
```

### 3. 工具

- heaptrack：分配热点、峰值、泄漏；
- massif：堆随时间变化；
- jemalloc/tcmalloc 自带统计；
- `MALLOC_ARENA_MAX=1` 对比碎片变化。

### 4. 碎片指标

没有统一标准，常用：

- 空闲块平均大小、最大空闲块；
- `fordblks / arena`（空闲占比）；
- 请求大块失败率；
- RSS / 活跃对象字节数。

## 五、优化手段

### 1. 对象池 / 固定大小分配

同类型对象用固定大小池，避免大小混杂：

```cpp
template <typename T, size_t N>
class ObjectPool {
    std::array<std::aligned_storage_t<sizeof(T), alignof(T)>, N> storage;
    std::vector<T*> free_list;
public:
    T* acquire();
    void release(T* p);
};
```

适合高频创建/销毁的小对象（连接、消息、节点）。

### 2. slab / size-class 分配器

按大小分类，每类独立管理，减少外部碎片。jemalloc、tcmalloc 的核心思路。

### 3. 分离生命周期

- 长生命周期对象与短生命周期对象分开分配；
- 热数据/冷数据分开；
- 连接对象与请求对象分池。

### 4. 减少分配次数

- 批量分配；
- 容器 `reserve`；
- 复用缓冲区；
- 小对象合并分配（arena）。

### 5. 选择合适分配器

| 分配器 | 碎片/并发特点 |
|---|---|
| glibc | 通用，多 arena，碎片中等 |
| jemalloc | size class，低碎片，RSS 控制好 |
| tcmalloc | 线程缓存，小对象快 |
| mimalloc | 低延迟，通用 |

```bash
LD_PRELOAD=/usr/lib/x86_64-linux-gnu/libjemalloc.so.2 ./app
```

### 6. 分配器参数

```bash
MALLOC_ARENA_MAX=2 ./app       # 限制 arena，减少碎片和 RSS
```

```c
malloc_trim(0);                // 归还 brk 顶部空闲内存
```

### 7. 避免频繁扩容

`std::vector` 用 `reserve`；字符串预估大小；批量插入。

## 六、排查流程

1. 确认是碎片还是泄漏：活跃对象是否持续增长；
2. 看 `mallinfo2`：`uordblks` 与 `fordblks` 比例、最大空闲块；
3. 用 heaptrack/massif 找分配热点和大小分布；
4. 尝试 `MALLOC_ARENA_MAX=1`、`malloc_trim`、换 jemalloc 做对比；
5. 针对热点对象引入池化/固定大小分配；
6. 压测验证 RSS 和分配失败率。

## 七、常见问题

### 1. RSS 高但没泄漏

可能是分配器缓存 + 碎片。用 `malloc_trim`、限制 arena、换分配器验证；活跃对象数不增长就不是泄漏。

### 2. 为什么大量小块分配后大块分配失败

外部碎片：空闲块不连续。改用大块预分配、池化，或换分配器。

### 3. 多线程下碎片更严重

每个线程 arena 独立，空闲块不能跨 arena 复用。限制 arena 数或减少线程数可缓解。

### 4. 容器反复 push_back 会碎片吗

会。扩容导致旧块释放、新块分配，留下空洞。用 `reserve` 预估容量。

## 八、面试标准简答

### 1. 内部碎片和外部碎片的区别？

内部碎片是分配块大于请求造成的浪费（对齐、元数据、size class）；外部碎片是空闲块分散、无法合并成满足大请求的连续空间。

### 2. 内存碎片怎么产生？

大小混杂 + 生命周期混杂 + 分配器按需切分/合并策略，导致空闲块散落在已分配块之间；多 arena 和频繁扩容会加剧。

### 3. 如何减少内存碎片？

固定大小对象池、size-class 分配器、分离长短生命周期、批量分配、容器 reserve、限制 arena、使用 jemalloc/tcmalloc，必要时 malloc_trim。

### 4. 如何判断 RSS 高是泄漏还是碎片？

观察活跃对象数/分配统计是否持续增长。持续增长多为泄漏；活跃对象稳定但 RSS 高、`fordblks` 大且最大空闲块小，多为碎片/缓存。

**mallinfo 看空闲，jemalloc 做对比。**
