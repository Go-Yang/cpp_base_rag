# 全局内存、静态内存常驻风险

## 一、前言

全局变量、静态变量（包括函数内 `static`）属于**静态存储期**：程序启动时分配，进程退出前一直存在。它们放在 `.data` / `.bss`，不会被自动释放。

核心总纲：**全局/静态内存的生命周期等于进程，任何"只增不减"的全局容器都等价于泄漏。** 常驻本身不是错，错的是无界增长、隐式共享和初始化顺序。

## 二、存储与生命周期

| 对象 | 段 | 初始化时机 |
|---|---|---|
| 有非零初值的全局/静态 | `.data` | 加载时 |
| 零初始化/未初始化 | `.bss` | 加载时清零 |
| 函数内 `static`（C，常量初值） | `.data`/`.bss` | 加载时 |
| 函数内 `static`（C++ 动态初值） | `.data`/`.bss` | 首次执行到声明处（线程安全 guard） |
| C++ 全局对象（动态初值） | `.data`/`.bss` + `.init_array` | `main` 之前 |

析构：

- C++ 全局对象通过 `__cxa_atexit` 注册，`exit` 时逆序析构；
- 不同编译单元之间的构造/析构顺序**未定义**；
- `_exit`、信号终止不会执行析构。

## 三、常驻风险

### 1. 无界增长

```cpp
static std::map<int, Data> cache;   // 只插入，从不删除
```

长期服务中缓存持续增长，等同于泄漏。需要容量上限、TTL、LRU。

### 2. 隐式共享状态

全局变量被多个模块读写，数据流不可追踪，测试难以隔离，并发下容易竞争。

### 3. 静态初始化顺序灾难

```cpp
// a.cpp
extern std::string g_name;
std::string g_greeting = "hi " + g_name;   // g_name 可能尚未构造

// b.cpp
std::string g_name = "foo";
```

不同编译单元的动态初始化顺序未定义，访问到未初始化对象是未定义行为。

### 4. 析构顺序问题

析构顺序与构造相反，但跨编译单元仍未定义。一个全局对象的析构函数访问另一个已析构的全局对象，会崩溃。

### 5. 大 `.bss` 常驻

```c
char big_buffer[512 * 1024 * 1024];   // .bss，不占文件
```

- 不占可执行文件，但占虚拟地址空间；
- 首次写入才分配物理页，写入后会常驻；
- 嵌入式加载器需要启动代码手动清零 `.bss`，漏掉会导致全局变量是垃圾值。

### 6. 共享库里的全局变量

- 每个加载的共享库各有一份全局变量；
- 同一库被静态链接进多个 `.so`，会出现多份副本；
- 动态链接的符号介入可能让不同模块看到不同的全局对象；
- 插件里的全局状态在 `dlclose` 前一直存在。

### 7. 线程安全

全局可变状态需要锁保护；锁本身也可能成为瓶颈。函数内 `static` 的初始化在 C++11 起线程安全，但之后的读写仍需同步。

### 8. 测试与复用

全局状态导致单测之间互相污染，无法并行运行，难以模拟不同环境。

## 四、典型场景

- 配置对象全局化，运行中修改导致其他线程读到半更新状态；
- 日志器/连接池全局单例，析构顺序导致退出时崩溃；
- 注册表全局 map，只注册不注销，插件反复加载后越来越大；
- 大数组放 `.bss` 以为"不占内存"，实际写入后 RSS 暴涨；
- 多线程共享全局计数器未加锁，数据竞争。

## 五、优化与替代

### 1. 函数内 static（Meyers Singleton）

```cpp
Logger& logger() {
    static Logger instance;   // C++11 起线程安全初始化
    return instance;
}
```

避免跨编译单元初始化顺序问题；析构仍在 exit 时，注意依赖。

### 2. 显式初始化/销毁

```cpp
void app_init();
void app_shutdown();
```

把全局对象的生命周期收进明确的流程，避免依赖静态构造/析构顺序。

### 3. 依赖注入

把对象作为参数传递，而不是全局访问。可测试、可替换、生命周期清晰。

### 4. 有界缓存

```cpp
class LruCache {
    size_t capacity;
    // 超过容量淘汰
};
```

给缓存设置上限、TTL、淘汰策略，并暴露统计指标。

### 5. 线程局部存储

每个线程独立的数据用 `thread_local`，避免锁竞争；注意线程退出时的析构和数量上限。

### 6. 用 const / constexpr

只读全局数据放 `.rodata`，无并发风险；能编译期计算的用 `constexpr`。

### 7. 避免大 `.bss`

大数据用堆分配，按需申请；或放 mmap 文件映射，按需加载。

## 六、面试标准简答

### 1. 全局变量和静态变量的生命周期？

静态存储期：程序启动时分配，进程退出时释放。C++ 全局对象在 `main` 前构造、`exit` 时析构；函数内 static 在首次执行到声明处初始化（C++11 线程安全）。

### 2. 什么是静态初始化顺序灾难？

不同编译单元的全局对象动态初始化顺序未定义。一个对象的构造函数访问另一个编译单元的全局对象时，后者可能尚未构造，导致未定义行为。用函数内 static 或显式初始化规避。

### 3. 全局内存有什么风险？

无界增长等同泄漏、隐式共享导致耦合和竞争、初始化/析构顺序问题、共享库多副本、测试污染、大 `.bss` 常驻占用虚拟/物理内存。

### 4. 函数内 static 是线程安全的吗？

C++11 起，函数内 static 的**初始化**是线程安全的（编译器生成 guard）；初始化完成后的读写仍需要同步保护。

## 七、极简口诀

**全局静态活到老，data/bss 常驻跑；**

**只增不减即泄漏，缓存必须有上限；**

**跨单元初始化乱，函数 static 最稳；**

**大 bss 占虚拟，共享库各一份。**
