# 栈溢出缓冲区溢出原理与防护

## 一、前言

"栈溢出"和"缓冲区溢出"经常被混用，其实是两个问题：

- **栈溢出（stack overflow）**：栈空间耗尽，越过了保护页，访问未映射内存 → `SIGSEGV`；
- **缓冲区溢出（buffer overflow）**：向数组写入超过其容量的数据，覆盖相邻内存（可能发生在栈、堆或全局区）。

核心总纲：**栈溢出是"空间不够"，缓冲区溢出是"写超边界"。** 前者通常立刻崩溃，后者可能静默破坏数据，甚至被利用劫持控制流。

## 二、栈溢出

### 1. 常见原因

- 巨大的局部数组：`char buf[10 * 1024 * 1024];`
- 深递归，每个栈帧累积；
- `alloca` / VLA 分配过大；
- 线程栈设置过小。

### 2. 现象

- 访问栈保护页 → `SIGSEGV`；
- 栈顶端溢出可能覆盖其他映射，表现更诡异；
- gdb 里 `bt` 可能显示大量重复帧或直接失败。

### 3. 修复

- 大对象改堆分配（`malloc` / `std::vector`）；
- 递归改迭代；
- 增大栈：`ulimit -s`、`pthread_attr_setstacksize`；
- 编译加 `-fstack-clash-protection` 防止跳页攻击。

## 三、缓冲区溢出

### 1. 栈上缓冲区溢出

```c
void copy(const char* src) {
    char buf[8];
    strcpy(buf, src);   // src 超过 7 字节就溢出
}
```

溢出方向：低地址 → 高地址，依次覆盖相邻局部变量、保存的 `rbp`、返回地址。

后果：

- 局部变量被改；
- 返回地址被改，函数返回时跳到攻击者指定的地址（经典栈溢出攻击）；
- 触发 canary 检测：`*** stack smashing detected ***`。

### 2. 堆缓冲区溢出

```c
char* p = malloc(8);
strcpy(p, long_string);   // 覆盖堆块元数据
```

后果可能延迟到 `free` 时才崩：

```text
free(): invalid next size (normal)
malloc(): corrupted top size
```

### 3. 全局/静态缓冲区溢出

覆盖相邻全局变量、函数指针，可能导致难以定位的逻辑错误。

### 4. 常见触发点

| 函数 | 风险 |
|---|---|
| `strcpy` / `strcat` / `sprintf` | 不检查目标大小 |
| `gets` | 已废弃，绝对不能用 |
| `memcpy` / `memmove` | 长度算错 |
| 数组下标越界 | `a[i]` 未校验 `i` |
| 循环边界 `<=` | off-by-one |
| 字符串未留 `\0` | 后续读取越界 |

## 四、防护机制

### 1. 编译期

```bash
gcc -fstack-protector-strong \
    -D_FORTIFY_SOURCE=2 -O2 \
    -fstack-clash-protection \
    -Wl,-z,noexecstack \
    app.c -o app
```

- **Stack Canary**：返回地址前放随机值，函数返回前校验；
- **FORTIFY_SOURCE**：对 `strcpy` 等做边界检查；
- **NX**：栈不可执行，阻止 shellcode；
- **ASLR/PIE**：地址随机化，增加利用难度；
- **CET/CFI**：限制控制流劫持。

### 2. 代码层

- 用 `snprintf` 代替 `sprintf`；
- 用 `strncpy`/`strlcpy`（注意 `strncpy` 不保证结尾 `\0`）；
- 用 `std::array`、`std::vector`、`std::string`；
- 所有数组访问校验下标；
- 边界计算统一用 `size_t`，防止负数转无符号；
- 对外部输入限制长度。

### 3. 运行时检测

- ASAN：`-fsanitize=address`，精确报越界；
- Valgrind：`--tool=memcheck`；
- `_GLIBCXX_DEBUG`：STL 越界检查；
- fuzzing：AFL++、libFuzzer。

## 五、排查流程

1. **定位崩溃点**：core/gdb 看信号和故障地址；
2. **判断类型**：
   - 访问栈保护页/栈底 → 栈溢出；
   - canary 报错 → 栈缓冲区溢出；
   - `free` 时元数据损坏 → 堆溢出；
3. **找写入点**：ASAN 直接给分配/访问栈；否则看最近的内存操作；
4. **修边界**：改长度、改 API、加校验；
5. **回归**：ASAN + fuzz 验证。

```bash
gcc -fsanitize=address -g app.c -o app
./app
```

## 六、面试标准简答

### 1. 栈溢出和缓冲区溢出的区别？

栈溢出是栈空间耗尽后访问未映射内存；缓冲区溢出是写入超过数组边界，覆盖相邻内存。前者通常是容量问题，后者是边界检查问题。

### 2. 栈缓冲区溢出为什么危险？

栈上保存返回地址，溢出可以覆盖它，函数返回时跳转到攻击者控制的地址。现代防护用 canary、NX、ASLR、CFI 提高利用难度，但不能替代正确的边界检查。

### 3. Stack Canary 的原理？

编译器在局部变量和返回地址之间放一个随机值，函数返回前检查它是否被修改。被修改说明发生了栈溢出，调用 `__stack_chk_fail` 终止程序。

### 4. 如何防止缓冲区溢出？

使用安全函数和容器（`snprintf`、`std::vector`、`std::string`），严格校验长度和下标，开启 `-fstack-protector-strong`、`FORTIFY_SOURCE`、ASAN，对外部输入做长度限制。
