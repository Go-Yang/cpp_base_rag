# 智能指针生命周期与资源管理

## 一、前言

C++ 智能指针用 RAII 把"资源释放"绑定到对象生命周期：

- `std::unique_ptr`：独占所有权；
- `std::shared_ptr`：共享所有权，引用计数；
- `std::weak_ptr`：不拥有对象的观察者。

核心总纲：**所有权决定用哪种指针。** 默认 `unique_ptr`，确实需要共享才用 `shared_ptr`，需要观察/打破循环才用 `weak_ptr`。不要用智能指针表达"借用"。

## 二、unique_ptr

### 1. 基本特性

- 独占所有权，不可拷贝，只能移动；
- 大小通常与裸指针相同（默认 deleter 无状态）；
- 离开作用域自动 `delete`；
- 支持自定义 deleter：`unique_ptr<FILE, decltype(&fclose)>`。

```cpp
auto p = std::make_unique<Foo>(42);
auto q = std::move(p);      // p 变为空
// p->bar();                // 空指针
```

### 2. 数组

```cpp
auto arr = std::make_unique<int[]>(10);   // C++14
arr[0] = 1;                                // 自动 delete[]
```

### 3. 自定义 deleter

```cpp
struct FileCloser {
    void operator()(FILE* f) const { if (f) fclose(f); }
};
std::unique_ptr<FILE, FileCloser> fp(fopen("a.txt", "r"));
```

也可以直接用函数指针/lambda（有状态 deleter 会增加对象大小）。

### 4. 适用场景

- 工厂函数返回值；
- 类成员表示独占资源；
- 容器存 `unique_ptr<T>` 实现多态；
- 替换裸 `new/delete`。

## 三、shared_ptr

### 1. 控制块

`shared_ptr` 由两部分组成：

- 对象指针；
- 控制块指针（强引用计数、弱引用计数、deleter、allocator）。

因此 `sizeof(shared_ptr) == 2 * sizeof(void*)`（通常 16 字节）。

### 2. 引用计数

- 拷贝/赋值增加强引用计数（原子操作）；
- 析构减少强引用计数；
- 强引用归零 → 调用 deleter 销毁对象；
- 弱引用归零 → 释放控制块。

```cpp
auto a = std::make_shared<Foo>();
auto b = a;             // 强引用 2
b.reset();              // 强引用 1
```

### 3. make_shared

```cpp
auto p = std::make_shared<Foo>(42);
```

优点：

- 一次分配同时放对象和控制块，减少分配次数、提升局部性；
- 异常安全（不会出现 `new` 成功但控制块分配失败的泄漏）。

注意：`make_shared` 的对象内存要等**所有 weak_ptr 也销毁**才释放（控制块和对象在同一块内存）。

### 4. 自定义 deleter

```cpp
std::shared_ptr<Foo> p(new Foo, [](Foo* x) { release_foo(x); });
```

### 5. 线程安全

- 控制块的引用计数是原子的，多个线程拷贝/销毁不同 `shared_ptr` 实例安全；
- 同一个 `shared_ptr` 实例被多个线程同时读写不安全；
- 对象本身的线程安全与智能指针无关。

## 四、weak_ptr

### 1. 作用

- 观察 `shared_ptr` 管理的对象，但不增加强引用计数；
- 用来打破 `shared_ptr` 循环引用；
- 缓存中避免延长对象生命周期；
- 实现观察者模式。

### 2. 使用

```cpp
std::weak_ptr<Foo> w = sp;

if (auto p = w.lock()) {     // 尝试提升为 shared_ptr
    p->bar();
}                             // 离开作用域，引用计数恢复

bool alive = !w.expired();
long n = w.use_count();      // 当前强引用数
```

`lock()` 是线程安全的原子操作：成功表示调用期间对象至少存活。

### 3. 循环引用示例

```cpp
struct Node {
    std::shared_ptr<Node> next;
    std::weak_ptr<Node> prev;   // 打破循环
};
```

如果两边都是 `shared_ptr`，计数永远不会归零，对象泄漏。

## 五、所有权设计

| 语义 | 表达方式 |
|---|---|
| 独占拥有 | `std::unique_ptr<T>` |
| 共享拥有 | `std::shared_ptr<T>` |
| 观察/弱引用 | `std::weak_ptr<T>` |
| 借用（不拥有） | `T*` 或 `T&`（生命周期由调用者保证） |
| 可选借用 | `T*`（可为空）或 `std::optional<std::reference_wrapper<T>>` |
| 只读视图 | `std::string_view` / `std::span` |

函数参数建议：

- 不接管所有权：`T&` 或 `const T&`；可为空用 `T*`；
- 接管所有权：`std::unique_ptr<T>` 按值传递；
- 共享所有权：`std::shared_ptr<T>` 按值或 const 引用（按值可延长生命周期）；
- 返回值：`std::unique_ptr<T>` / `std::shared_ptr<T>`。

## 六、常见坑

### 1. 两个 shared_ptr 从同一裸指针构造

```cpp
Foo* raw = new Foo;
std::shared_ptr<Foo> a(raw);
std::shared_ptr<Foo> b(raw);   // 两个控制块，double free
```

必须 `make_shared` 或从已有 `shared_ptr` 拷贝。

### 2. shared_ptr(this)

```cpp
void Foo::register() {
    manager.add(std::shared_ptr<Foo>(this));   // 危险：另一个控制块
}
```

用 `std::enable_shared_from_this<Foo>` 和 `shared_from_this()`。

### 3. 循环引用

两个对象互相 `shared_ptr`，永远不释放。用 `weak_ptr`。

### 4. 用 shared_ptr 表达非拥有关系

函数只是使用对象，不需要延长生命周期，传 `T&`/`T*` 即可。滥用 `shared_ptr` 会增加原子操作开销和生命周期混乱。

### 5. 自定义 deleter 与数组

`shared_ptr<T>` 默认 `delete`；管理数组要用 `shared_ptr<T[]>`（C++17）或自定义 deleter。

### 6. unique_ptr 的空 deleter 与大小

无状态 deleter 不增加大小；函数指针/lambda 捕获会增加大小。

### 7. 移动后使用

`unique_ptr` 被 move 后为空；继续解引用是未定义行为。

## 七、性能与选择

- `unique_ptr`：零开销抽象，优先使用；
- `shared_ptr`：控制块原子操作、额外内存，适合真正的共享所有权；
- `weak_ptr`：lock 有原子操作开销；
- 高频路径避免临时 `shared_ptr` 拷贝；
- 多态容器用 `vector<unique_ptr<Base>>`，不要 `vector<shared_ptr<Base>>`，除非确实共享。

## 八、面试标准简答

### 1. unique_ptr 和 shared_ptr 的区别？

`unique_ptr` 独占所有权，不可拷贝、可移动，几乎零开销；`shared_ptr` 共享所有权，通过控制块引用计数，归零才释放，有原子操作和额外内存开销。

### 2. shared_ptr 的引用计数是线程安全的吗？

控制块的引用计数是原子的，不同 `shared_ptr` 实例在多个线程拷贝/销毁安全；同一个 `shared_ptr` 实例被并发读写不安全；被管理对象的线程安全需要另外同步。

### 3. 如何打破 shared_ptr 循环引用？

把循环中的一边改为 `weak_ptr`。`weak_ptr` 不增加强引用计数，使用时 `lock()` 提升为 `shared_ptr`，对象已释放则返回空。

### 4. make_shared 有什么好处？

一次分配同时容纳对象和控制块，减少分配次数、提升缓存局部性，并且异常安全。缺点是对象内存要等所有 weak_ptr 释放后才归还。

## 九、极简口诀

**默认 unique 独占，共享才 shared；**

**观察用 weak，循环靠它断；**

**make_shared 一次分配，裸针别造两控制块；**

**借用传引用，所有权用智能针。**
