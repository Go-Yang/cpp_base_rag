# 文件句柄泄漏成因与检测

## 一、前言

Linux 把文件、socket、管道、设备、epoll 等都抽象成**文件描述符（fd）**。每个进程的 fd 数量有上限，泄漏完就无法再打开任何文件或建立连接：

```text
Too many open files
accept: Too many open files
```

核心总纲：**fd 是进程级有限资源，`open` 和 `close` 必须成对出现；错误路径是泄漏重灾区。** `FILE*` 和 fd 是两层资源，关闭方式不同。

## 二、fd 的基本机制

### 1. fd 表

- 每个进程有一张 fd 表，fd 是小整数（0、1、2 分别是 stdin/stdout/stderr）；
- `open`/`socket`/`pipe` 返回最小的可用 fd；
- `close(fd)` 释放表项；
- `fork` 后子进程继承父进程的 fd（引用计数 +1）。

### 2. 限制

```bash
ulimit -n                    # 当前 shell 的软限制
ulimit -Hn                   # 硬限制
cat /proc/<pid>/limits | grep 'open files'
cat /proc/sys/fs/file-max    # 系统级上限
```

软限制可以调高到硬限制；硬限制需要特权或 systemd 配置。

### 3. fd 与 FILE*

- `open` 返回 fd，用 `close` 关闭；
- `fopen` 返回 `FILE*`，内部持有一个 fd，用 `fclose` 关闭；
- `fileno(fp)` 取 fd，但不要对同一个 fd 既 `fclose` 又 `close`（double close）；
- `fdopen` 把已有 fd 包装成 `FILE*`，关闭时用 `fclose`。

## 三、常见泄漏场景

### 1. 错误路径漏 close

```c
int fd = open(path, O_RDONLY);
if (fd < 0) return -1;
if (parse(fd) < 0) {
    return -1;      // 漏了 close(fd)
}
close(fd);
```

### 2. 循环/重试中打开不关

```c
for (;;) {
    int fd = open(path, O_RDONLY);
    if (fd < 0) continue;   // 打开失败无 fd，但成功分支若异常退出就漏
    ...
}
```

### 3. socket/accept 泄漏

服务端 `accept` 返回新 fd，处理失败时没 close，长期运行后 fd 耗尽。

### 4. 子进程继承

`fork`/`exec` 后子进程继承 fd；如果子进程长期运行又不关闭，父进程的 fd 也被占用（引用计数未归零）。

### 5. 包装对象析构不关闭

自己封装的 `File`/`Socket` 类，析构函数忘记 `close`，或拷贝时双关闭。

### 6. 特殊 fd

`epoll_create`、`inotify_init`、`eventfd`、`timerfd_create`、`signalfd`、`memfd_create` 都返回 fd，都需要 close。

### 7. 目录流

`opendir` 返回 `DIR*`，需要 `closedir`。

### 8. dlopen 与库句柄

`dlopen` 返回的句柄不是 fd，但同样需要 `dlclose`；库内部可能持有 fd。

## 四、检测手段

### 1. 数量统计

```bash
ls /proc/<pid>/fd | wc -l
lsof -p <pid> | wc -l
ls -l /proc/<pid>/fd | head
```

fd 数量持续上涨是泄漏信号。

### 2. 查看具体 fd

```bash
lsof -p <pid>
ls -l /proc/<pid>/fd
```

能看到每个 fd 指向的文件、socket、管道。

### 3. 跟踪系统调用

```bash
strace -f -e trace=openat,open,close,socket,accept4 -p <pid>
```

观察 open 和 close 是否成对。

### 4. Valgrind

```bash
valgrind --track-fds=yes ./app
```

程序退出时列出未关闭的 fd。

### 5. 资源限制观察

```bash
cat /proc/<pid>/limits | grep 'open files'
cat /proc/<pid>/fdinfo/<fd>   # 单个 fd 的状态
```

## 五、修复与预防

### 1. RAII 封装（C++）

```cpp
struct Fd {
    int fd = -1;
    explicit Fd(int f) : fd(f) {}
    ~Fd() { if (fd >= 0) ::close(fd); }
    Fd(const Fd&) = delete;
    Fd& operator=(const Fd&) = delete;
    int release() { int f = fd; fd = -1; return f; }
};
```

`std::unique_ptr<int, decltype(&close)>` 也可以，但注意 `close` 返回 int、签名匹配。

### 2. C 的 goto cleanup

```c
int fd = -1;
int ret = -1;
fd = open(...);
if (fd < 0) goto out;
if (work(fd) < 0) goto out;
ret = 0;
out:
    if (fd >= 0) close(fd);
    return ret;
```

### 3. 设置 CLOEXEC

```c
int fd = open(path, O_RDONLY | O_CLOEXEC);
```

避免 `exec` 后 fd 泄漏到子进程。`accept4(..., SOCK_CLOEXEC)`、`socket(..., SOCK_CLOEXEC)` 同理。

### 4. 统一关闭路径

- 所有错误分支走同一个 cleanup；
- 不要在多个分支重复 close；
- close 后把 fd 置 -1，防止 double close（close 一个已被复用的 fd 会关掉别人的文件）。

### 5. 限制与监控

- 合理设置 `ulimit -n`；
- 监控 `/proc/<pid>/fd` 数量；
- systemd 配 `LimitNOFILE`；
- 定期压测观察。

## 六、常见问题

### 1. close 返回错误

`close` 失败时 fd 是否已释放取决于实现；不要在失败后再次 close 同一个 fd。EINTR 时也不应盲目重试。

### 2. double close

一个 fd 被 close 两次，第二次可能关掉刚被复用的新 fd，导致其他连接异常。close 后置 -1 可缓解。

### 3. 多线程关闭同一个 fd

需要所有权明确，避免一个线程 close 时另一个线程仍在读写。

### 4. 子进程继承导致父进程 fd 无法释放

`O_CLOEXEC` 或子进程主动关闭不需要的 fd。

### 5. 文件句柄泄漏但 ls 看不到

可能是内核对象（epoll、timerfd）或已被继承到子进程，用 lsof 全局查。

## 七、面试标准简答

### 1. 文件描述符泄漏有什么后果？

进程 fd 表被占满后，无法再打开文件、建立 socket、accept 连接，出现 `Too many open files`。长期服务会逐渐失去服务能力。

### 2. fd 和 FILE* 有什么区别？

fd 是内核文件描述符，整数；`FILE*` 是 C 标准库的缓冲流，内部持有 fd。fd 用 `close`，`FILE*` 用 `fclose`；不能混用，否则可能 double close。

### 3. 如何避免 fd 泄漏？

RAII 封装、goto cleanup 统一释放、错误路径检查、`O_CLOEXEC`、close 后置 -1、监控 fd 数量、压测验证。

### 4. O_CLOEXEC 的作用？

执行 `exec` 时自动关闭该 fd，防止 fd 泄漏到子进程。对 socket、管道、临时文件尤其重要。

## 八、极简口诀

**fd 有限要成对，open 之后必 close；**

**错误分支走 cleanup，fork 继承加 CLOEXEC；**

**FILE* 用 fclose，别和 close 混着来；**

**lsof 看指向，strace 看配对。**
